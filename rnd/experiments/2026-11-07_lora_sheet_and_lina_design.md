# 파츠 시트 LoRA 학습과 리나 SD 디자인 시안 실험 (2026-11-07)

참고 자료의 이미지·파일은 저장하지 않고 수치만 기록합니다.

## 1. 파츠 시트 LoRA (SDXL Illustrious-XL-v1.0, ComfyUI 기본 학습 노드)
- 학습 데이터: 게임 아틀라스 159개를 조립한 시트 159장. 1024×512, 왼쪽 조립 캐릭터 + 오른쪽 25슬롯 파츠 패널(슬롯 위치 고정), 캡션 1개 반복.
- 설정: rank 32, AdamW, lr 1e-4, bf16, batch 1, 그래디언트 체크포인트, 환경 RX 9070 XT 16GB(학습 중 VRAM 여유 약 14.8/17.1GB).
- 구간별 스텝: 1,600(4시간 26분, 스텝당 약 10.0초) → +800(2시간 3분) → +800(약 1시간 50분) → +800 → +800 = 총 4,000스텝. 이어 학습은 `existing_lora` 파일명에 `_{누적스텝}_steps_` 표기 필요.
- 생성 점검(시드 101~104, 28스텝 euler cfg 6, 눈으로 센 값, 수치는 어림값):
  - 1,600스텝: 구조(왼쪽 캐릭터+오른쪽 파츠)는 학습됨, 슬롯 개수·배치는 장마다 다름, 얼굴 슬롯 불명.
  - 2,400스텝: 파츠 형태가 알아볼 만해지고 줄 구조가 4장 중 3장에서 나타남.
  - 3,200스텝: 4줄 구조가 4장 모두에서 일정. 패널 시작 위치가 템플릿(410px)과 맞는 것은 4장 중 2장.
  - 4,000스텝: 줄 구조 4/4, 머리 슬롯 3/4, 작은 캐릭터 조각이 파츠 영역에 생기는 현상 소멸. 얼굴 슬롯은 여전히 불명, 개선 폭은 구간마다 줄어드는 중.
- 결론: 슬롯 배치는 스텝 증가로 개선되지만 정확도와 얼굴 슬롯에는 해상도(1536×704)와 캡션 보강이 필요해 보임. 데이터 확대는 하지 않기로 함(게임 캐릭터 추가 조립 중단).

## 2. 리나 입력 시험
- 인페인팅(왼쪽에 리나 원본, 오른쪽 패널만 생성): 슬롯 구조는 리나에게도 적용됨. 파츠 내용은 리나 디자인과 무관하게 새로 그려져 치마 색 일치 1/4.
- img2img(LoRA로 왼쪽 재생성): 강도 0.5~0.65에서 화풍은 이동하나 파우치·브로치·책 소실, 0.65에서 불필요한 무늬. 강도 0.3~0.4는 소품 8/8 유지, 화풍 변화는 약함, 볼터치·웃음이 사라져 귀여움 감소.

## 3. 리나 SD 디자인 시안 (Qwen Image Edit 2509, 라이트닝 4스텝, cfg 1)
- 입력 `lina_front_smooth`(머리 약 52%, 2등신으로 변환된 이미지)에서 20장: 머리 비율 45~55%, 기준(33%) 통과 0/20. 프롬프트 변형(3/4 지시, 마네킹을 1번 이미지로 입력)도 모두 실패.
- 원인: 입력 이미지의 비율이 그대로 따라옴. 확정 원본 일러스트는 머리 약 16%(약 6등신)이므로 원본을 입력으로 바꿈.
- 원본(1번) + 마네킹(2번) 입력 4장: 머리 약 33%(눈으로), 가로세로비 0.38~0.40, 원본 의상 유지. 마네킹을 1번에 두면 머리 약 40%, 비율 0.44~0.51.
- 귀엽게 편집(위 시안을 입력): 눈·볼터치·둥근 얼굴로 귀여움 상승, 가로세로비 0.50~0.56. 책 없는 시안 9b_9502 채택.
- 마네킹 걷기 4번 프레임 윤곽에 채택 시안을 높이 745px로 맞춰 겹침: 머리(머리카락 포함) 높이가 키의 약 43%(마네킹 33%), 머리 폭은 마네킹 머리 타원의 약 1.9배. 앞서 말한 37~40%는 어림 오류였고 이 측정값이 정확함. 턱이 마네킹 몸통 영역(y≥415)까지 내려와 현재 절단(cut_lina.py)을 그대로 쓰면 턱 픽셀이 몸통으로 배정될 것으로 예상.

## 4. 머리 축소 합성 + 걷기 적용 시험 (rnd/mannequin/lina_v7)
- 방법: 채택 시안(9502)을 키 745px로 맞추고, 머리 영역(턱까지 335px)을 0.603배로 줄여 몸에 붙인 뒤 전체를 745px로 되돌려 머리 33%를 맞춤(턱 선 위치에서 목 중심 정렬). 줄어든 머리 옆으로 떨어진 머리카락 끝은 몸 영역의 떨어진 조각(969px)을 찾아 머리 레이어에 합침. 이후 기존 절단 방식(cut_lina.py, 걷기 4번 프레임 마스크)으로 11개 파츠(머리·몸통·엉덩이·앞뒤 위팔·앞뒤 아래팔+손·앞뒤 허벅지·앞뒤 종아리)를 자르고 걷기 24프레임에 적용(CPU, 약 1분).
- 결과(24프레임 중 12프레임 컨택트 시트로 확인): 머리·얼굴·몸통·앞다리는 전 프레임에서 형태 유지. 파츠 픽셀 수: 머리 55,987 / 엉덩이 22,524 / 몸통 22,313 / 앞 종아리 18,276 / 앞 아래팔 17,694 / 앞 허벅지 12,030 / 앞 위팔 8,863 / 뒤 허벅지 7,944 / 뒤 종아리 4,926 / 뒤 위팔 3,527 / 뒤 아래팔 3,349.
- 문제: ① 무릎 길이 치마가 허벅지·엉덩이 파츠에 나뉘어 걸음마다 치마 조각이 다리와 함께 휘둘리고 틈이 생김(프레임 3~9, 0·1·11에는 왼쪽에 치마 조각이 팔처럼 매달림). ② 뒤 종아리·뒤 팔은 가려진 부분이 없어 일부 프레임에서 가늘게 끊김. ③ 목 부분 흰 칼라 조각과 이음선이 작게 보임.
- 판단: 치마는 별도 레이어(템플릿의 skirtF 슬롯 성격)로 분리해야 함.

## 5. 1536×704 이어 학습 시도와 채점 스크립트 (2026-11-07~08)
참고 자료의 이미지·파일은 저장하지 않고 수치만 기록합니다.
- 데이터: 원본 시트 2560×1152 → 1536×704로 축소 159장, 시트마다 슬롯 캡션(비어 있는 칸 제외). 이미지별 캡션은 `LoadImageTextDataSetFromFolder`로 읽음.
- 시간 모형: 학습 1회 = 준비 약 34분(이미지→잠재 변환, GPU 거의 미사용) + 스텝당 약 12.3초(100스텝 54분 22초, 800스텝 3시간 18분에서 연립). 5장 시험의 9.2초는 준비 시간이 섞인 값이라 실제와 달랐음.
- 4,000스텝 LoRA에서 이어 학습, 학습률 1e-4, +800스텝(누적 4,800): 가중치 3,268개 중 2,756개가 비정상(NaN), 생성 4장 모두 완전 검정(평균 0). 8스텝 시험 파일은 정상.
- 같은 조건에서 학습률 5e-5, +100스텝(누적 4,100): 비정상 0개, 생성 4장 정상. 800스텝 발산 원인이 학습률인지는 미확정.
- 4,100스텝 생성 4장(시드 101~104, 1536×704, 28스텝 euler cfg 6)을 `rnd/lora_eval/score_sheet.py`로 채점(어림값):
  - 필수 파츠 12칸 존재: 9/12, 9/12, 11/12, 8/12 (정답 학습 시트 4장은 12/12, 슬롯 안 비율 1.0)
  - 파츠가 슬롯 안에 든 비율: 0.869, 0.967, 0.848, 0.870
  - 파츠 색이 왼쪽 캐릭터 팔레트에 있는 비율: 0.989, 0.993, 0.897, 0.918 (정답 학습 시트 0.95~0.999) → 파츠 색은 대체로 일치
  - 파츠 면적 / 왼쪽 캐릭터 면적: 0.507, 0.511, 0.277, 0.583 (정답 학습 시트 0.357~0.459)
- 학습 자료의 조립 가능성 확인(원본 아틀라스 5개 기준): 슬롯의 파츠는 회전 없이 원본의 정확히 2.0배(17개 파츠 모두 비율 1.96~2.10). 왼쪽 조립 그림은 캐릭터마다 원본의 4.0~4.56배(높이 약 944~951px에 맞춤). 따라서 파츠는 "배율 약 2.0~2.3배 + 평행이동"만으로 왼쪽에 맞는다(위치 정보는 시트에 없음).
- 조립 채점(`--assemble`): 시트마다 배율을 전체 겹침이 최대가 되는 값으로 정하고 파츠를 평행이동만으로 맞춰 그리기 순서대로 합성. 정답 학습 시트 8장에서 실루엣 겹침(IoU) 0.898~0.967, 추정 배율 1.96~2.30(실제 2.0~2.25)으로 검증됨. 픽셀 색 일치(허용오차 45)는 0.76~0.88로 축소·반올림 영향이 있어 보조 지표로만 사용.
  - 앞서 IoU 0.24~0.33이 나왔던 것은 배율 탐색 범위와 정합 비용 설계 오류였고 자료 문제가 아니었음.
- 4,100스텝 생성 4장 조립 채점(어림값, 시드 101~104): IoU 0.604 / 0.603 / 0.627 / 0.574, 커버리지 0.721 / 0.739 / 0.724 / 0.617, 픽셀 색 일치 0.350 / 0.265 / 0.338 / 0.399, 추정 배율 2.06 / 2.10 / 2.34 / 1.84. 기준 90%에는 크게 못 미침(정답 시트는 IoU 0.90 이상). 한계: 생성 이미지는 왼쪽 캐릭터가 크거나 패널이 왼쪽으로 밀려 왼쪽 영역(x<614)에 패널 조각이 섞이는 경우가 있어 점수가 낮게 나올 수 있음.
- 사용자 기준: "분해 시트를 조립했을 때 왼쪽 캐릭터와 90% 이상 일치". 현재 LoRA는 이 기준에 크게 못 미침(필수 파츠 누락, 위치 어긋남).
