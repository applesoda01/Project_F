의뢰 변주와 정보

같은 의뢰에 붙는 변수 태그, 흐린 승산과 정찰

1. 목적

  • 콘텐츠 반복을 싸게 줄인다. F급 게시판 의뢰 10종을 24주에 다 보고, 그 뒤 E급 승급(40주)까지 새 의뢰가 없다 (보고서 3-4).
  • 06 출발 승인 · 12 육성 방향에 「이 의뢰는 무엇이 다른가」라는 판단 거리를 준다.

2. 지금

  • 첫해 게시판 의뢰 약 67건, 한 종을 5.4~6.6번 · 가장 자주 본 종은 9.2번. 몬스터는 들개 · 멧돼지 · 슬라임 · 도적 4종.
  • 예상 성공률이 숫자로 정확히 보이지만 실제와 어긋남 (예상 96% 이상 → 실제 93.4%).
  • 리퀘스트는 이미 % 대신 「승산 칩」으로 보여 줌 (11-19).

3. 규칙 (안)

3-1. 변주 태그

게시되는 의뢰의 일부(13주 뒤 30% [임시])에 태그 1개가 붙습니다. 태그는 유리한 능력치나 값이 달라, 같은 「들개 퇴치」가 다른 의뢰가 됩니다.

  • 10종 × 태그 6종이라 같은 조합을 두 번 볼 일이 드물어집니다.
  • 태그는 리퀘스트 · 메인 퀘스트에는 붙이지 않음 (이야기가 있는 쪽은 그대로).

3-2. 흐린 승산과 정찰

  • 게시판 의뢰의 예상 성공률을 숫자 대신 승산 칩으로 보여 줍니다 (리퀘스트와 통일). 숫자는 정찰하면 보입니다.
  • 정찰: 의뢰 하나에 정찰비 10G(F) [임시]를 내면 정확한 예상 % + 숨은 사정이 드러남. 설계서의 「정보 구매」 지출과 같은 자리이고, C급 정보실 효과의 앞단계.
  • 결정을 늘리지 않으려고 정찰은 출발 승인 카드 안에서만 고를 수 있게 하는 안도 있음 (3-3 미결).

4. 화면

  • 의뢰 카드 오른쪽 위에 태그 띠 (색 1개 + 두 글자). 마우스를 올리면 효과 한 줄.
  • 도감(의뢰 쪽)에 「본 태그 조합」 칸 — 모으는 재미 (선택).
  • 귀환 보고에 태그가 결과에 준 영향 한 줄: 「밤이라 마커스의 눈이 빛났어요」.

5. 연동

  • 12 육성 방향: 태그가 판정 능력치를 바꾸므로 「누가 이 의뢰에 맞나」가 성장 방향과 이어짐.
  • 13 이야기: 실패 이유 문구(failWhy)에 태그를 섞어 「궂은 날씨에 발이 미끄러졌어요」.
  • 의뢰 데이터는 prototype/data CSV에 태그 표를 더함 (외부 작업자가 늘릴 수 있게).

6. 검증

  • 첫해 「같은 의뢰 + 같은 태그」를 다시 본 횟수 (반복 지표): 한 종 평균 6회 → 조합당 2회 이하.
  • 태그가 성공률 · 수입을 흔드는 크기: 첫해 월 ±20G 안 (콘텐츠 장치이지 경제 장치가 아님).
  • 정찰을 넣는다면: 「늘 정찰」 대 「안 함」 차이가 정찰비를 넘을 것.

7. 미결 사항

  • 태그 수와 목록, 붙는 비율, 붙기 시작하는 주
  • 승산을 칩으로 바꿀지 (게시판 의뢰도 리퀘스트처럼)
  • 정찰을 따로 둘지 / 출발 승인 카드 안에만 둘지 / 넣지 않을지
  • 「숨은 사정」이 불공평하게 느껴지지 않는지 (보호 구간에는 안 붙임)
