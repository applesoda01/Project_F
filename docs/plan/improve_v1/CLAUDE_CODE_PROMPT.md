## 작업 규칙

### 0. 미결 사항은 서로 검토하고 제안해서 결정한다
- 각 기획서 끝의 「미결 사항」은 확정된 것이 아니야. 임의로 정해서 구현하지 마.
- 순서: ① 미결 사항을 코드 현황과 함께 정리 ② 항목마다 선택지 2~3개, 추천안, 근거(구현 비용 · 플레이 영향 · 측정값) ③ 내 결정을 기다림 ④ `DECISIONS.md`에 기록하고 기획서 HTML 본문에도 반영 ⑤ 구현.

### 1. 경제 수치는 선임 검토 전까지 고정
- 수치가 바뀌는 안(02 · 03 · 04 · 05 · 10)은 측정 도구(`prototype/tools/qa/analysis/`) 안에서만 흉내 내어 크기를 재고, 게임 코드에는 넣지 않아.
- 수치가 바뀌지 않는 안(08 · 09 · 11 A · 12 표시 · 13 대사)은 시안 → 내 확인 → 반영 순서로 진행해.

### 2. 측정
- 어림셈 → 30판 훑어보기 → 100판 확인. **시뮬레이션은 돌리기 전에 먼저 물어봐.**
- 합격선은 `01_principles_v1.html` 4장. 직접 돌려 보지 않은 것은 확인했다고 하지 마.

### 3. 구현
- 규칙을 바꾸면 `game_core.js`와 `sim_engine.js`를 함께 고치고 관문 1(`node prototype/tools/gate1_check.js`)을 통과시켜.
- 화면 시안은 1280×720과 1920×1080 두 크기로 캡처해서 보여 줘.
- 기획서 한 건(또는 한 단계)씩 커밋하고, 커밋 메시지는 한국어로.
- 끝나면 `index.html`의 진행 현황과 수정 기록을 갱신해.
