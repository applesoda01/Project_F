<p>예를 들어 <strong>“E급 성직자 / 자유 / 토박이 / 마을 거주”</strong>, <strong>“F급 궁수 / 정식 / 새내기 / 길드 숙소”</strong>가 모두 가능해야 한다. “핵심 모험가”는 주목할 인재 표식이지 제3의 고용 제도가 아니다.</p>
<h3>3.2 애착·거주 불일치 처리</h3>
<p>기존 설계의 애착 구간은 <code>0~29 / 30~69 / 70~99 / 100</code>, 실제 지명 수락 구간은 <code>0~29 / 30~59 / 60~89 / 90 이상</code>이다. 설계상 마을 거주는 애착 100, 이사는 60 미만이고, 인구 계산은 애착 65 이상을 정착 기여자로 센다. v2가 이 차이를 미결로 남겼다. [S02, S03, S06]</p>
<p><strong>추천 처리 순서</strong>는 다음과 같다.</p>
<ol>
<li>계약 기능을 추가할 때 기존 애착·인구 수치를 함께 바꾸지 않는다. 내부 구분을 명확하게 하고, 화면에는 애착 숫자·소속·거주 여부를 따로 표시한다.</li>
<li>수락 계산은 현재 코드 구간을 공통 함수로 사용한다. “토박이”는 관계 판정과 주거 판정을 혼용하지 않도록 별도 검토한다.</li>
<li>애착 65 이상 인구 기여는 첫 버전에서 유지하되, 설명을 <strong>‘지역 활동 기여’</strong>로 명확히 한다. 이것을 실제 주택 입주 여부로 오해하게 하지 않는다.</li>
<li>실제 거주 100/60 규칙과 관계 단계 이름을 통일하는 작업은 별도 승인·회귀 검증 대상으로 둔다. 계약 체결만으로 인구 증가 인원을 추가하지 않는다.</li>
</ol>
<p>새로운 ‘충성도’와 ‘계약 만족도’ 막대를 처음부터 더 만들지 않는다. 애착은 장기 관계에 사용하고, <code>급여 미지급·지원 부족·업무 초과</code>처럼 <strong>설명 가능한 불만 사유</strong>를 계약 상태에 남긴다.</p>
<h3>3.3 창립 멤버</h3>
<p><strong>기존 창립 2명은 ‘상주하는 자유 모험가’로 시작</strong>하는 것을 추천한다. 이름·능력치·기존 상주 혜택·이력은 유지하고, E급 이후 다른 모험가와 마찬가지로 정식 계약을 제안할 수 있게 한다.</p>
<p>창립 멤버라는 이유로 무료 전속 의무를 주지 않는다. 정식으로 계약한 뒤에는 동일한 급여·지원·정식 정원을 적용한다. 창립 표식은 남되 정원은 두 번 세지 않는다.</p>
