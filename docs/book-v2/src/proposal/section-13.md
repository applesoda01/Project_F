> **첨부 개선안 원문 · 신규 제안 / 게임 미반영.** 기준 커밋 `bd7e207`, 2026-11-16 검토 초안. 기존 구현에 관한 서술도 이 기준의 정적 검토이며 이번 작업의 실행 검증 결과가 아닙니다. 숫자는 별도 명시가 없으면 검증용입니다. [자료 안내](README.md)

<p>계약원 개인 지갑은 기존 <code>wallet</code>을 유지한다. 급여를 길드에서 차감하면 같은 금액을 개인에게 지급하거나 유족·외부 지급 대상에 기록한다. 출처 없는 개인 소지금 증가와 수취인 없는 지출은 의도적인 외부 비용일 때만 허용하고 그 의미를 적는다.</p>
<h3>13.2 주간·월간 처리의 일관성</h3>
<p>주가 넘어갈 때 처리 순서에 관한 제안은 다음과 같다.</p>
<ol>
<li>귀환·결과 확정, 기존 거래 중복 여부 확인.</li>
<li>확정된 의뢰 보수·전리품·지원비를 정산하고 사용한 예약 해제.</li>
<li>계약 종료·연장·부상·사망과 기존 업무 예약 정리.</li>
<li>월말이면 해당 기간 보수·사업 계약·보조금 적격 실적 결산.</li>
<li>침공·이미 수락한 계약 임무·지명 임무의 출발 가능 상태 확인.</li>
<li>남은 가용 인원이 게시판에서 자율적으로 의뢰를 선택.</li>
<li>새로운 기록·보고·화면 연출에 필요한 결과 저장.</li>
</ol>
<p>실제 기존 <code>stepWeek</code>의 호출 순서를 무작정 이 목록으로 교체하지 않는다. 특히 ‘이번 주 귀환자 지명 가능’과 침공 차례 간 회복 같은 기존 예외를 보존하며, 예약 판정과 정산의 선후관계를 명시하는 것이 목적이다.</p>

<h3>13.4 저장 호환</h3>
<p>기존 저장을 불러오면 모든 기존 인물은 원칙적으로 <strong>자유 모험가</strong>로 유지한다. 과거 월급·미납금·계약금을 새로 만들지 않는다. 기존 <code>home</code> 상주 동작은 보존하고, 이것만 보고 정식 계약원이나 창립 멤버라고 추정하지 않는다. 창립 여부가 확실한 기록이 없는 저장은 <code>기존 상주 혜택</code>으로 유지한 뒤 표시를 보수적으로 처리한다.</p>
<p>진행 중 의뢰는 기존 정산 규칙으로 끝낸다. 신규 규칙은 전환 이후 게시·출발한 의뢰부터 적용하는 방식을 권장한다. 기존 <code>s.mats</code>는 기존 길드 재고로 한 번만 이관하고, 새 소유권 체계로 이관한 뒤 다시 불러와도 같은 재고를 추가하지 않는다.</p>
<p>기존 원가 미상 재고, 미수령 보수, 외부 체류 인물, 사망·이탈 이력을 명확하게 구분한다. 현재 확인 코드에는 이탈 때 <code>alive = false</code>를 쓰는 처리도 있으므로, 계약 해지·외부 이적을 추가하며 이를 실제 사망과 혼동하지 않도록 별도 상태나 원인 필드가 필요하다. [S10]</p>
