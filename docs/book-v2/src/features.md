## 갱신 규칙

1. 기능 ID는 유지하고, 변경 이유는 [비교표](changes.md)에 함께 기록합니다.
2. 채택 시 기획 상태·결정 날짜·근거를 갱신합니다. 코드 상태는 자동으로 바꾸지 않습니다.
3. 구현 시 코드 커밋·검증 범위·검증 날짜를 추가합니다. 부분 구현은 미반영 부분을 남깁니다.
4. 수치 검증 전에는 검증용 표기를 유지합니다. 기존 측정 결과를 신규 규칙에 재사용하지 않습니다.
5. 문서 기능 DOC-01/02는 게임 구현과 별개로 [변경 비교표](changes.md)에서 관리합니다.
