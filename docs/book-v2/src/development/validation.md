# 4. 보조금·통합 검증

**반기 보조금은 다른 경제 변화와 분리해 측정한 뒤 결합합니다.**

## 7단계 — 반기 실적 보조금

| 작업 | 확인 |
| --- | --- |
| 지급 주기·적격 | 6·12월 말, 의뢰별·기간별1회, 실제 성공 |
| 제외 | 길드 자가 발주, 중복 실적, 별도 지원 없는 장기 계약 |
| 기준 금액 | **반기 성공 의뢰 기본 보상 합 × 50% [임시]** [결정 2026-11-17]. 기존 80%는 결정 이력으로 보존, 늦장 실패(결정 15)도 이 단계에서 함께 켬 |
| 초기 유동성 | 시작500G·시설비 유지 상태에서 첫24주 저점 확인 |

- [ ] 경계 주·재로드·중복 의뢰 ID·자가 발주의 실패 사례를 작성한다.
- [ ] 월 고정/반기 정책을 시험 설정으로 구분해 규칙·시뮬레이터에 적용한다.
- [ ] 기존 / 보조금 단독 / 계약 단독 / 결합 결과를 같은 조건에서 비교한다.

## 8단계 — 통합 완료 판정

| 검증 | 범위 | 기록할 결과 |
| --- | --- | --- |
| 규칙 회귀 | [장부의 정산 검증표](../ch09/ledger.md) 전체 | 총액·재고·예약·지급 횟수 |
| 첫해 | 같은 조건100판×48주 | 현금 저점·운영 손익·성공률·승급·장비 구매력 |
| E급 이후 | 동일 E진입 상태+96주 | 계약 모험가 0명/핵심1~2명/최대 계약의 비용·유휴·가용성 |
| 정책 비교 | 고요율·저지원 / 저요율·고지원 | 개인 성장·수주·길드 재정 |
| UI | 계약·의뢰 관리·리퀘스트 발주·매입·위탁·장부 | 선택·취소·불가 이유·키보드·표시 금액 |
| 저장 | 기존 저장·신규 저장·중간 재개 | 강제 고용·소급 급여·재고 재이관 없음 |

- [ ] 규칙·시뮬레이터의 차이를 기록하고 원인을 설명한다.
- [ ] 기존 관문 기준300~600G를 새 손익 정의에 그대로 대입하지 않고 비교 기준을 합의한다.
- [ ] 검증 결과를 `docs/balance/`에 커밋·시드·정책과 함께 저장한다.
- [ ] `features.md`의 구현 상태는 검증 커밋과 결과가 있는 항목만 갱신한다.
- [ ] 문서 테스트와 HTML 링크를 검사하고 `docs/book/v2` 열람 파일을 갱신한다. 임시 생성 폴더는 정리한다.

기존 명령: `node prototype/tools/gate1_check.js`, `node --test docs/tools/*.test.mjs`. 신규 경제 회귀 명령은 1단계에서 작성할 `node prototype/tools/economy_contract_check.js`이며 현재 실행 가능한 도구로 간주하지 않습니다.

**완료 조건:** 설명할 수 없는 자금·재고 변동이 없고, 계약 모험가 0명 진행과 기존 첫해 경험을 보존합니다. 시안 작성·문서 병합만으로 이 단계를 완료 처리하지 않습니다.
