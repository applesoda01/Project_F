# 1. 기준 확정·저장·정산 기반

**정산·소유권·저장 기반을 먼저 검증합니다. UI만 먼저 연결하지 않습니다.**

## 0단계 — 기준과 미결 확정

| 할 일 | 확인·산출물 |
| --- | --- |
| 현재 main 대조 | 이번 검토 시 원격 main `78721ec`. 명성 방문 간격 등은 V1 기록과 이미 다름. 개발 시작 시 최신 커밋으로 다시 확인 |
| 기존 플레이 측정 | `node prototype/tools/gate1_check.js`, 기준 커밋·시드·설정·결과 저장 |
| 계약 정책 결정 | 기간·정원·후보·보수·지원·업무 상한과 사용자 선택 범위 |
| 정산 정책 결정 | 정수 잔액 배분 순서, 계약 종료 주, 반복 정산·저장 시 처리 |
| 경제 정책 결정 | 요율 해금, 매입·위탁 조건, 보조금 적격·실패 책임 |
| 동시 제안 분리 | main의 대장간 제안 등은 기존 제안 상태를 확인. 이번 경제 최소판에 자동 포함하지 않음 |

- [ ] 현재 코드와 V1/V2 차이를 결정표에 기록한다.
- [ ] 미결 수치에는 시험값·선택 범위·검증 목표를 지정한다.
- [ ] 기존 저장 파일과 기준 측정 결과를 회귀 검증 자료로 확보한다.

## 1단계 — 저장·정산 공통 기반

| 작업 단위 | 만들 것 | 먼저 확인할 실패 사례 |
| --- | --- | --- |
| 상태 분리 | 자유/계약, 애착, 실제 거주, 창립 이력, 활동·예약 | 상주 인물을 자동 고용하거나 인구 중복 가산 |
| 저장 호환 | 버전별 이관, 기존 재고의 길드 소유·원가 미상 표식 | 재로드 때 재고·급여 재생성, 소급 급여 |
| 개인 정산 | 출발 시 조건 저장, 개인 기준액·길드 몫·실수령 | 101G/3명 반올림 손실, 귀환 전 정책 변경 |
| 자금·예약 | 소유 현금·확정 지급 예약·외부 예치 분리 | 예약과 지급의 이중 차감, 예치금 사용 |
| 거래 기록 | 고유 거래/의뢰 식별자, 지급·인도·정산 이력 | 중복 클릭·저장 재개로 2회 지급 |

| 대상 파일 | 책임 |
| --- | --- |
| `prototype/js/game_core.js` | 상태·정산·예약 규칙 |
| `prototype/js/main.js` 및 기존 저장 경로 | 저장·불러오기 연결. 구현 전 실제 직렬화 경로 확인 |
| `prototype/js/sim_engine.js` | 동일 정책의 계산·측정 |
| `prototype/data/balance.csv`, `prototype/tools/data_build.py` | 확정된 시험값과 생성 데이터 |
| `prototype/tools/economy_contract_check.js` **신규 예정** | 저장·정산·거래 식별자 회귀 사례. 아직 존재하지 않음 |

- [ ] 실패 사례를 작성하고 실패 이유를 확인한다.
- [ ] 기존 저장 이관과 개인별 정산을 구현한다.
- [ ] 규칙과 시뮬레이터에 같은 설정을 적용한다.
- [ ] 일반·혼성 파티의 총액 보존과 재로드 안전성을 검증한다.

**완료 조건:** 새 기능을 꺼도 기존 자동 의뢰·F→E 진행이 가능하고, 같은 거래를 반복해도 잔액·재고가 증가하지 않습니다. 다음: [계약·지원·배치](contracts.md).
