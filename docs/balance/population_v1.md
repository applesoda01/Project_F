# 마을 인구 증가 개선안 v1 (가안)

> 작성: Claude, 2026-11-13 밤사이 작업 · 상태: **제안 (결정 전, 코드 반영 안 함)**
> 측정: 게임 규칙(`game_core.js`) 30판 × 36개월, 원정·식사·테이블은 관문 1과 같은 자동 플레이 가정. 모형 비교는 측정한 월별 성공 수·애착 분포를 그대로 넣어 계산.

## 요약
- **문제:** 지금 인구는 3년 동안 150 → 290으로, **첫 단계(마을 300)에도 못 닿습니다.** 늘어나는 원인이 "매달 1.2% 자동 증가" 거의 하나뿐이라 플레이어가 할 수 있는 일이 없습니다.
- **원인 3가지:** ① 증가율이 길드 등급에 묶였는데 게임에는 승급이 아직 없음(등급 F 고정) ② 거주 모험가 조건이 애착 100이라 18개월 차에야 1명 ③ 퀘스트·시설·서브 퀘스트 등 플레이어 행동이 인구와 연결되지 않음.
- **제안 (C안):** %를 없애고 **정수 가산형**으로 바꿉니다. 매달 +2 + 의뢰 성공 1건당 +1 + 거주 모험가(애착 65 이상) 1명당 +2 + 서브 퀘스트 보상(+10~20). 이렇게 하면 **12개월 차에 마을(300), 약 3년 차에 읍(1,000) 근처**에 도달합니다.

---

## 1. 지금 규칙

```
매달: pop += pop × (0.012 + 0.002 × 길드등급) + (애착 100인 모험가 수) × 1
습격 패배 −5%, 침공 패배 −10% (시뮬레이터만)
단계: 개척촌 ~300 / 마을 300 / 읍 1,000 / 도시 3,000 / 성채 도시 8,000 → 의뢰 유입 ×1.0 / 1.3 / 1.6 / 2.0 / 2.5
→ 2026-11-13 결정: 문턱 300 / 1,000 / 2,000 / 3,500 (데이터 반영 전)
```

## 2. 측정 (게임 규칙, 30판 평균)

| 개월 | 인구 | 길드 등급 | 애착 100 (거주) | 애착 65 이상 | 월 의뢰 성공 |
| ---: | ---: | --- | ---: | ---: | ---: |
| 3 | 155 | F | 0 | 0 | 3.7 |
| 6 | 161 | F | 0 | 0 | 5.5 |
| 12 | 173 | F | 0 | 1.1 | 7.0 |
| 18 | 188 | F | 0.7~1.0 | 4.4 | 7.8 |
| 24 | 215 | F | 2.7~2.8 | 4.9 | 7.7 |
| 36 | 290 | F | 3.6~3.7 | 5.3 | 7.8 |

- 첫 1년 증가량 **+23명**(월 약 2명). 화면의 인구 숫자가 거의 움직이지 않음.
- 등급이 F로 고정이라 `growthPerGrade`(+0.2%/등급)는 효과 0. 메인 퀘스트·승급 구현 전까지는 계속 0.
- 같은 1.2%라도 인구가 커질수록 빨라지는 구조(복리) → 초반은 너무 느리고 후반(8,000)은 월 +100 이상으로 너무 빠름.

## 3. 개선안 비교

| 안 | 매달 증가 | 6개월 | 12개월 | 18개월 | 24개월 | 36개월 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| A 지금 | 인구 × 1.2% + 애착100 × 1 | 161 | 173 | 187 | 214 | 292 |
| B 정수 가산 | **+2 + 성공 1건당 +1 + 애착65 이상 1명당 +2** | 186 | 241 | 338 | 453 | 694 |
| **C 추천** | B + **서브 퀘스트 보상** (4개월에 1번 +20 가정) | 206 | **301** | 418 | 573 | 874 |
| D 빠름 | +3 + 성공 ×2 + 애착65 ×3 + 서브 +20 | 236 | 378 | 566 | 802 | 1,270 |

- **C안 추천 이유:** ① 1년 차 끝(첫 승급 예상 시점)에 "마을" 단계에 들어가 의뢰 유입 ×1.3이 체감됨 ② 의뢰를 잘 깨고 모험가를 붙잡아 두는 것, 서브 퀘스트(기부·수색)를 하는 것이 **모두 인구로 보임** ③ 모든 수치가 정수라 툴팁에 "의뢰 성공 시 인구 +1"처럼 그대로 적을 수 있음.
- **D안**은 2년 안에 읍(1,000)에 가까워져 프로토타입 범위(F·E)에서는 단계가 너무 빨리 열림.

## 4. C안 세부 (정수)

| 요인 | 효과 | 화면 문구 예 |
| --- | --- | --- |
| 기본 | 매달 +2 | "마을이 조금씩 커지고 있습니다 (+2)" |
| 의뢰 성공 | F급 성공 1건당 +1, E급 +2 (실패 0) | 의뢰 결과 줄에 "인구 +1" |
| 거주 모험가 | **애착 65 이상** 모험가 1명당 매달 +2 (지금 100 → 65로 낮춤. 애착 단계 65 = "신뢰" 단계와 맞춤) | 마을 화면 "거주 모험가 3명 (+6/월)" |
| 서브 퀘스트 | 기부 +20, 수색 +10, 기부형 "인구 증가 +1/월" (영구) | 퀘스트 보상 카드 |
| 마을 건물 (D급 이후) | 건물 1개당 매달 +3 (설계서 "특별 건물 → 증가율 상승"의 정수판) | |
| 습격·침공 패배 | −5% · −10% → **−15 · −30** (정수, 프로토타입 범위) | |
| 단계 상한 | 단계별 "주거지 한도" (설계서 10.2): 다음 단계로 넘어가려면 서브 퀘스트 1개 필요 (예: 300 → 마을은 "무너진 광장 우물" 기부) — **선택 사항** | |

- 단계 상한을 넣으면 인구가 저절로 단계를 넘지 않고 **서브 퀘스트(기부)가 단계 진입의 열쇠**가 됨 → 사용자가 원한 "돈을 달라는 퀘스트 → 인구 증가"와 직접 연결. 단, 상한에 막혀 있는 동안은 월 증가가 멈추므로 화면에 "주거지가 부족합니다 (기부 퀘스트로 해결)" 안내 필요.
