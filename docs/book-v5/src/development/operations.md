# 3. 거래·의뢰 관리·발주

**기존 소재 판매·자동 의뢰·리퀘스트를 유지하고, 기능별로 순서대로 연결합니다.**

| 단계 | 규칙 작업 | UI 작업 | 완료 기준 |
| --- | --- | --- | --- |
| 4 매입·위탁 | 소유자·원가·지분·수수료·대금 정산 | 경영 우측 매입·위탁, 기존 소재 판매 유지 | 개인·위탁품의 요리/납품 사용 차단 |
| 5 자동 의뢰 관리 | 일반 수수료 선택·해금, 출발 조건 고정 | 의뢰 우측 의뢰 관리. 경영은 조회·바로가기 | 기존 자동 유입·배분·수주 유지 |
| 6 길드 발주·외부 의뢰 | 예산 예약·지급·인도·취소·실적 제외 | 리퀘스트 우측 길드 발주·외부 의뢰 | 기존 부탁·28개 리퀘스트·승급 보존 |

## 4단계 — 실제 거래

- [ ] 매입70G→판매100G, 위탁100G→소유자90G/길드10G 사례를 작성한다.
- [ ] 매입 때 현금과 소유권을 이전하고, 판매 때 원가·매출 중복 계산을 막는다.
- [ ] 위탁 취소·미판매·공동 소유·저장 재개를 검증한다.
- [ ] 의뢰 성공 시 소재는 귀환 때 길드가 판매가의 **70% [임시]**(버림)로 자동 매입(돈은 모험가 지갑), 길드 판매 시 100%, 길드 돈이 모자라면 위탁(수수료 **10% [임시]**). 소재 자동 차익 8%는 없애고 장부·시뮬레이터를 맞춘다 [결정 2026-11-17].

## 5단계 — 자동 의뢰 수수료

- [ ] 의뢰별(또는 등급 칸별) 수수료 10 · 15 · 20% [임시] 지정과 모험가 주당 실수령 선택을 구현한다 [결정 2026-11-17]. 칸별 / 의뢰별은 화면 시안 때 정한다.
- [ ] 일반 의뢰 출발 시 수수료를 저장한다. 기존 계약 수수료는 갱신 전까지 보존한다.
- [ ] 정보실 자동 인상과 중복되지 않도록 서비스·해금 역할을 연결한다.
- [ ] 진행 중 의뢰, 계약 모험가, 혼성 파티에서 정책 변경 회귀를 검사한다.

## 6단계 — 리퀘스트 발주

- [x] 길드 발주를 선지급 모으기로 정함(결정 25): 발주 때 금고에서 바로 내고, 1개씩 지급, 거두면 남은 돈 반환. 맡는 사람이 따로 없어 수주 후 취소 · 불이행 처리가 필요 없음. (2026-11-18)
- [x] 게시판 쏠림 50% [임시] · 발주 소재 의뢰 우선(결정 26), 몬스터 · 탐색 포인트마다 소재 뽑기(결정 27). 관문 1 479G · 96.0%.
- [x] 화면: 리퀘스트 장 길드 발주 책갈피 · 게시판 발주 띠와 표시 (시안 확인 후 연결).
- [ ] 외부 의뢰의 지급자·보수·기간·실패 책임을 표시한다. 자동 게시판 의뢰와 구분한다. **(보류)**
- [x] 자가 발주에 수수료·보조금·명성 · 신뢰 실적이 붙지 않음 (발주 지급은 의뢰 보상과 별도, 결정 25).

**대상:** `prototype/js/game_core.js`, `sim_engine.js`, `ui.js`, 기존 책 UI 스타일·설정 데이터, 신규 예정 `prototype/tools/economy_contract_check.js`.

**완료 조건:** 거래별 현금·원가·소유권·실적이 한 번만 반영됩니다. 후속 장기 호위·선수금 사업은 [5장 후속 개발](later.md)에서 분리합니다. 근거: [거래](../ch06/potion.md) · [의뢰 관리](../ch04/board.md) · [리퀘스트](../ch04/requests.md).
