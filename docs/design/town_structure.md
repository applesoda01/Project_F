# 마을 구조 설계 — 화면 흐름·상호작용·규칙 (초안)

> 요약: 마을은 **로비와 별개의 화면**이며, 하단 HUD의 "마을" 버튼으로 진입합니다. 건물 클릭 → 건물 팝업, 잠긴 슬롯 클릭 → 해금 조건 안내 구조입니다. 마을 화면에서는 시간이 정지합니다(침공 제외). 시각 사양은 [../art/town_spec.md](../art/town_spec.md) 참조.

## 1. 결론
- 화면은 **로비 / 마을 2개**이고, 전환은 페이드(0.4초) 한 번으로 처리합니다.
- 마을의 모든 조작은 **슬롯 클릭 → 팝업** 한 종류로 통일합니다.
- 근거 1: 시간 정지 규칙(설계서 10장)과 맞아 주간 진행·저장 로직을 건드리지 않습니다.
- 근거 2: 건물 17종이 모두 같은 팝업 틀을 쓰면 M3-5~M3-10(장비·대장간·식당·하우징·훈련)을 팝업 내용만 바꿔 붙일 수 있습니다.
- 근거 3: 슬롯 표가 이미 데이터이므로, 해금·등장 판정은 표 한 장(`town_slots.csv`)으로 관리됩니다.

## 2. 화면 흐름
| 단계 | 동작 | 결과 |
| --- | --- | --- |
| 1 | 하단 HUD "마을" 클릭 | 페이드 후 마을 화면, 시간 정지 |
| 2 | 건물 마우스 오버 | 외곽선 강조 + 이름표 |
| 3 | 건물 클릭 | 건물 팝업(이름·단계·효과·업그레이드·이용) |
| 4 | 잠긴 슬롯 클릭 | 윤곽 표시 + "해금 조건" 한 줄 (예: 특별 퀘스트 C) |
| 5 | 소문 말풍선 클릭 | 해당 모험가 상세창 열기 |
| 6 | ESC / 닫기 | 로비 복귀, 시간 재개 |

- 침공 발생 시에만 마을 화면에서 시간이 흐르고, 하단에 경고 띠와 "방어 현황"이 표시됩니다.
- 한 번에 열리는 팝업은 1개입니다.

## 3. 슬롯 상태 (4종)
| 상태 | 표시 | 조건 |
| --- | --- | --- |
| 빈터 | 표지 말뚝만 | 인구 단계 미달 |
| 잠김 | 윤곽(반투명) | 단계 충족, 특별 퀘스트 미완료 |
| 해금 | 건물 스프라이트 | 퀘스트 완료 |
| 업그레이드 | 교체 스프라이트 | 성당→대성당, 마법 학원→마탑 (도시 단계 + 2번째 특별 퀘스트 A) |

## 4. 건물 팝업 공통 구성
1. 머리: 건물 이름, 단계(Lv), 닫기
2. 본문: 현재 효과 1~2줄(수치 포함), 이용 버튼(건물별 기능)
3. 하단: 업그레이드 비용·조건, 미충족 항목은 붉게 표시
4. 건물별 기능은 팝업 본문 영역만 교체합니다(공통 틀 유지).

## 5. 데이터 구조
- `data/town_slots.csv`: id, 이름, gx, gy, w, d, 등장 단계, 해금 조건, 교체 대상. (사양서 5장 슬롯 표와 1:1)
- `data/town_state`(저장): 인구 단계, 해금 건물 목록, 업그레이드 여부, 건물 Lv.
- 인구 단계 판정은 기존 인구 값에서 계산합니다(저장하지 않음).

## 6. 프로토타입 구현 순서 (제안)
1. 마을 화면 껍데기: 배경 + 격자 + 슬롯 임시 박스 (목업 포팅, 약 1일)
2. 단계 전환·해금 데이터 연결 (슬롯 상태 4종 표시)
3. 팝업 공통 틀 + 건물 3종(여관·대장간·성당)으로 시험
4. 소문 말풍선·모험가 동선 연결
5. 침공 연출

## 7. 미확정 (결정 필요)
- 마을 건물 효과 수치(예: 여관 회복 속도, 대장간 장비 제작 수): 건물별 설계 필요
- 마을 화면 중 모험가 거주 표시 방식(애착 100)
- 시간 정지 중 팝업에서 쓰는 재화 소모 규칙
