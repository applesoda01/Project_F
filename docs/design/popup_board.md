# 의뢰 게시판 팝업 개편 설계

> 2026-11-05 사용자와 논의해 확정. 팝업 안쪽 내용 퀄업의 첫 번째 대상. 공통 부품은 `prototype/css/ui_kit.css`.

## 0. 요약

| 영역 | 지금 | 바뀜 |
| --- | --- | --- |
| 칸 배분 → **의뢰 배분** | 등급별 슬라이더 0~10 (박스 안) | 제목 + 아랫줄에 등급별 버튼 4개 **없음·적게·보통·우선** |
| 의뢰 카드 | 이름·유형·골드·필요 능력치·게시 주수·떼기 | 작은 카드: 등급·이름·**해골 위험도**·**▲▼ 개체**·골드·떼기 + **바랜 종이** |
| 상세 정보 | 없음 | **마우스 오버 창** (카드 옆) |
| 나가 있는 파티 표 | 있음 | **삭제** (원정 패널과 겹침, 결과가 미리 보이던 문제) |

화면 구성: 위 = **의뢰 배분** 제목 + 등급별 버튼(한 줄 3등급) / 아래 = **게시된 의뢰** 제목 + 카드 격자(한 줄 5장). 두 구역 모두 "제목 + 장식선" 같은 형식. 등급이 늘면 배분 줄이 늘고 게시된 의뢰가 아래로 밀림, 넘치면 팝업 안 스크롤.

## 1. 의뢰 배분 (예전 이름: 칸 배분)

| 항목 | 규칙 |
| --- | --- |
| 버튼 | 없음 · 적게 · 보통 · 우선 |
| 비중 | 0 · 1 · 2 · 4 (우선 = 보통의 2배) |
| 의미 | 게시판 최대 칸 수 안에서 등급별 비율. 예: 8칸, F 보통·E 우선 → F 3칸 · E 5칸 |
| 칸 수 계산 | 최대 나머지 방식으로 반올림해 **합이 최대 칸 수와 정확히 같게** |
| 표시 | 결과 칸 수는 표시하지 않음 (2026-11-05 결정). 전체 칸 수는 "게시된 의뢰 7 / 8칸" 제목에 |
| 배치 | 한 줄에 3등급씩 격자. S급까지 열리면 3줄 |
| 모두 없음 | **불가.** 마지막 하나를 없음으로 바꾸려 하면 안내만 띄움 |
| 새 등급이 열릴 때 | **그 등급만 "우선"**, 기존 등급 값은 그대로 |
| 기존 저장 값 변환 | 슬라이더 0 → 없음, 1~2 → 적게, 3~6 → 보통, 7~10 → 우선 |

## 2. 의뢰 카드 (약 210×72px, 한 줄 5장)

| 항목 | 내용 |
| --- | --- |
| 등급 배지 | HUD와 같은 배지 그림 |
| 의뢰 이름 | 편집기 이름. 이름 뒤에 유형을 한 번 더 붙이던 것 삭제 |
| 해골 1~3 | 위험도 (2장). 비전투 의뢰는 없음 |
| ▲ / ▼ / ? | 이번 의뢰의 개체 차이 (3장). 해골 옆 작은 기호 |
| 골드 | 보상 골드 |
| 떼기 | 작은 위험 버튼. 등록비·위약금(보상의 10%), 신뢰도 −2 |
| 바랜 종이 | 게시 0~1주 새 종이 / 2~3주 살짝 누렇게 / 4주 이상 더 바래고 모서리 접힘 |

## 3. 위험도 (해골)

- 기준: **그 의뢰 등급의 표준 모험가**(장비 없음)가 예측 전투(combat.js `predict`, 게시 정보 기준·무작위 없음)에서 **승률 70% 이상**이 되는 최소 인원.
- 1명 → 해골 1, 2명 → 해골 2, 3명 이상 → 해골 3 (상한 3). 오버 창에 "○급 모험가 N명 권장" 문장.
- 표준 모험가: F급 Lv 2, E급 Lv 6 (주력 능력치 17 + 레벨 성장, 나머지 7.5 + 성장). 직업 5종 조합(연속 n개 직업)의 평균 예측 승률로 판단.
- 몬스터 수치를 바꾸면 게임이 다시 계산하므로 자동으로 따라 바뀜.
- E급으로 올라가는 것 자체가 어렵다는 점이 해골로 직관적으로 보이는 것은 의도(사용자 확인).

## 4. 개체 표시 (▲▼)

- 의뢰마다 붙는 적 개체 차이(`combat,enemyVar` ±15%)를 3구간으로.

| 개체 차이 | 표시 |
| --- | --- |
| 0.85 ~ 0.95배 | ▼ 약한 무리 (초록) |
| 0.95 ~ 1.05배 | 표시 없음 |
| 1.05 ~ 1.15배 | ▲ 강한 무리 (빨강) |

- **정보실이 있을 때만** 실제 구간을 보여 줌(1단계 이상이면 동일). 없으면 "?" 표시.
- 정보실 단계는 지금처럼 모험가의 예측 정확도에만 영향(1단계마다 오차 25% 감소).
- 비전투 의뢰는 표시 없음.

## 5. 마우스 오버 창

- PC 전용(모바일 고려 안 함) → 클릭 고정 없음.
- 카드에 0.2초 머물면 **카드 오른쪽**에 뜸(공간이 없으면 왼쪽). 마우스를 떼면 사라짐.
- 내용:
  - 전투: 몬스터 도트 + 마리 수, 몬스터별 체력·공격력(게시 정보) / 비전투: 요구 능력치
  - 보상: 골드, 소재(주·부, 확률). 소재 획득은 아직 게임에 없음 → "준비 중" 표시
  - 기간, 의뢰인·공지 문구(편집기에 있으면), 명성·신뢰도 변화
  - "○급 모험가 N명 권장", 개체 표시 설명, 게시 주수, 떼기 비용

## 6. 나가 있는 파티

- 표 **삭제**. 진행 중인 의뢰는 오른쪽 원정 패널에서 봄.

## 10. 의뢰 기한 · 게시판 칸 수 (2026-11-12 확정·구현, 프로토타입)

| 항목 | 규칙 |
| --- | --- |
| 기한 | 의뢰가 **게시판에 붙은 순간부터 1달(4주)** |
| 기한 막대 | 의뢰 카드에 남은 시간 막대. 모험가가 **수락하면 막대가 멈춤** (수행 중에는 기한 없음) |
| 만료 | 아무도 받지 않고 기한이 지나면 의뢰가 사라지고 **신뢰도 −1** (직접 떼기 −2·위약금보다 가벼움 → "둘지, 비용을 내고 뗄지" 고민) |
| 게시판 업그레이드 (1단계, 500G) | 의뢰 기한 **+1주** (4주 → 5주). 여러 단계 설계는 프로토타입 이후 |
| 칸 수 | **처음부터 18칸** (게임 전체 최대치). 등급별 칸 수 증가(`quest.boardCap`)는 프로토타입에서 쓰지 않음 |

- 2장의 "바랜 종이"(게시 주수에 따라 종이가 누레짐)는 기한 막대와 함께 유지할지 구현 때 화면으로 확인.
- 반영 때 확인: 18장이 팝업(한 줄 5장)과 로비 코르크판에 다 들어가는지, F·E 두 등급에 18칸이 나뉠 때 의뢰 배분이 의도대로인지, 관문 1 재검증.

### 10-1. 구현 메모 (2026-11-12)

| 파일 | 내용 |
| --- | --- |
| `prototype/data/balance.csv` | `quest.boardCap` 모두 18, `quest.expireWeeks` 4, `quest.trustExpire` 1 추가, **`quest.perMonth` 10 → 5**, `econ.effectOpen` 0 추가 |
| `prototype/js/game_core.js` | `expireQuests` (매주, 4주 지난 의뢰 제거·신뢰도 −1·길드 기록 `expire`), **의뢰를 매주 게시**(예전에는 `week % 4 === 0`일 때만 = 월 유입의 1/4), 예전 저장은 불러올 때 기한을 새로 시작(`expireV`) |
| `prototype/js/sim_engine.js` | 같은 기한·매주 게시 규칙. 게임과 맞추려고 **모험가 상한(등급별 8·12…) 적용**, **시설 효과 개방 끔**(`econ.effectOpen` 0, 게임에 없는 기능) |
| `prototype/js/ui.js` · `prototype/css/ui_kit.css` | 카드 아래 기한 막대(`.qdl`, 주 게이지와 같은 진행률로 매 프레임 줄어듦, 1/4 이하 빨강), 마우스 오버 "기한 ○주 남음", 기록 아이콘 ⌛ |

**유입량을 5로 줄인 이유:** 매주 게시로 바꾸자 의뢰가 월 약 10건(예전 실제 2~3건)이 되어 모험가 8명이 소화하지 못하고 1년에 42건이 만료, 신뢰도가 50 → 27로 떨어짐. 5로 줄이면 만료 연 약 10건, 연말 신뢰도 약 54. 유입량은 나중에 아이템·시설 등으로 올리는 구조로 감 (2026-11-12 결정).

**관문 1 (100판):** 바꾸기 전 게임 443G · 93.4% / 시뮬레이터 456G · 91.8% → 바꾼 뒤 게임 **492G · 95.0%** / 시뮬레이터 **510G · 94.0%** (통과). 성공률이 상한 95%에 붙어 있어 밸런스 때 확인.

- 1년 성공 의뢰: 33건 → 약 56건. 화면(18장 배치, 기한 막대)은 배포본에서 확인 예정.
