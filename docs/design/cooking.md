# 요리 조합 (식당)

> 2026-11-05 사용자와 논의해 확정. 팝업 퀄업 4번(음식 설정 → **식당**)에서 시작한 새 시스템. 설계서 12-2.6절(요리와 출발 전 식사)을 대체·보완.

## 0. 요약

| 영역 | 예전 | 바뀜 |
| --- | --- | --- |
| 요리 해금 | 토벌·사냥 성공 시 50% 확률로 그 등급 요리가 순서대로 열림 | **식당에서 소재를 조합해 발견**해야 열림 |
| 소재 | 게임에 획득 없음 | 의뢰 성공 시 **편집기 보상표 확률대로** 얻어 길드에 쌓임 |
| 팝업 | "음식 설정" (메뉴 글자 목록) | **"식당"**: 소재 보관함 · 조리대 3칸 · 리나 힌트 · 메뉴판 |
| 효과 | 등급별 공통 보너스 (F +3% … 1개만 열리면 60%) | **발견한 요리 하나당 +2%** (등급 무관, 쌓임). 식사한 모험가에게 비전투는 성공 확률, 전투는 공격력에 적용 |

## 1. 발견 규칙

| 항목 | 규칙 |
| --- | --- |
| 조합 | 소재 **각 1개씩, 1~3개** (같은 소재 2개 불가) |
| 성공 | 넣은 소재가 레시피와 **정확히 같으면** 발견. 소재 소모, 메뉴에 영구히 오름 |
| 판매 | 발견한 요리는 팔 때 소재를 쓰지 않음 (재고·품절 없음) |
| 실패 | 레시피에 없는 조합이면 **넣은 소재가 사라짐** + 리나 힌트 |
| 이미 아는 요리 | 소재를 쓰지 않고 막음 |

## 2. 힌트 (리나, 말풍선 없이 글만)

- 비교 대상: 넣은 재료와 **가장 많이 겹치는 미발견 요리**. 같으면 낮은 등급 → 무작위. 길드 등급 이하 요리가 남아 있으면 그 안에서만.
- 위에서부터 먼저 맞는 문구 하나만:

| 순서 | 경우 | 문구 |
| --- | --- | --- |
| 1 | 이미 발견한 조합 | 이미 아는 요리예요. 재료는 그대로 두었어요. |
| 2 | 하나도 안 겹침 | 이건… 아무도 먹지 않을 거예요. |
| 3 | 재료가 하나 더 들어감 | ○○는 빼 보면 어떨까요? |
| 4 | 재료가 모자람 | 뭔가 하나 더 넣으면 좋겠는데요… |
| 5 | 틀린 재료가 있음 (여러 개면 하나만) | ○○ 대신에 다른 걸 넣어 보면 어떨까요? |

## 5. 식당 화면

| 영역 | 내용 |
| --- | --- |
| 소재 보관함 | 음식 소재만. 아이콘 + 개수. 0개는 흐리게, 모르는 소재는 실루엣 + ???(이름·개수 숨김). 누르면 조리대로 |
| 조리대 | 칸 3개 + "만들어 보기". 올린 소재를 누르면 빠짐 |
| 리나 토스트 | 결과·힌트를 팝업 가운데 토스트로 (성공 금색, 실패 붉은색). 3.2초 뒤 또는 화면을 누르면 닫힘 |
| 큰 솥 | 조리대 아래 GPT 그림(`assets/ui/kitchen/`). 만들어 보기 → 재료 퐁당 → 국자 젓기(약 1.6초) → 실패: 검은 연기·흔들림 / 성공: 요리가 솥 위로 떠오름. 연출 중 누르면 바로 결과 |
| 스크롤 | 소재 보관함·조리대는 고정, **메뉴판만** 휠 스크롤 (다시 그려도 위치 유지) |
| 메뉴판 | 등급별 발견 수 + 보너스 태그. 발견한 요리 = 아이콘·이름·재료 아이콘, 못 찾은 요리 = 실루엣 + ???(재료 개수 숨김) |

## 5-1. 식사 효과 (2026-11-05 확정: C안 = 요리별 능력치 + 발견 수 보너스)

| 효과 | 규칙 |
| --- | --- |
| ① 발견 수 보너스 | `econ.mealPerDish`(0.02) × 발견한 요리 수(등급 무관) × 식사한 파티원 비율. 비전투는 성공 확률, 전투는 공격력에 곱함 |
| ② 요리별 능력치 | 먹은 요리의 능력치(`meals.csv` 효과 칸, 예: 힘·기교 +3%)가 **먹은 사람만** 그만큼 오름. 비전투 판정·전투 능력치 모두 |
| 요리 고르기 | 출발 전, 발견한 요리 중 **의뢰 등급 이하**에서 요구 능력치와 가장 많이 겹치는 요리 → 같으면 높은 등급 → 높은 수치. 발견한 요리가 없으면 식사 없음 |
| 가격·구매 | 고른 요리 등급의 의뢰 보상 × 25%. 소비 성향 확률(절약 30·보통 60·낭비 90%)로 사 먹음 |

- 효과 문구 해석: `+n%` 앞의 능력치 이름(힘·민첩·지력·정신·기교, '모든 능력치' = 다섯 개 모두). 능력치가 없는 효과(사망 확률 −20% 등)는 ①만 적용.
- 메뉴판: 등급 줄 "n / 3 발견" 옆 **"식사 효과 +n%"**(그 등급 발견 수 × 2%), 카드 둘째 줄 오른쪽 끝에 요리 능력치 효과 "(민첩 +3%)".
- 예전 `econ.mealBonus`(등급별)와 "1개만 열리면 60%" 규칙은 쓰지 않음.
- 16개 모두 발견하면 ①만 +32% → 상한은 후반 설계 때 결정.

## 5-2. 발견 연출 (성공)

| 순서 | 내용 |
| --- | --- |
| 1 | 큰 솥: 재료 퐁당 → 국자 젓기 (약 1.6초). 국자는 솥 앞에 두고 수프 표면 아래는 잘라 수프에 잠긴 것처럼 보임 |
| 2 | 금빛 + 요리가 솥 위로 떠오름 (0.7초) |
| 3 | 메뉴판 카드가 실루엣 면 → 요리 면으로 **위아래** 플립(0.6초), 금빛 점·별 파티클 26개, 등급 줄 태그 반짝임. 카드가 화면 밖이면 스크롤 |
| 4 | 리나 토스트 (팝업 가운데, 3.2초 또는 누르면 닫힘) |

- 연출 중 식당을 누르면 바로 마지막 상태 + 토스트.
- 파티클은 카드 중심에서 나옴 (화면 배율·팝업 테두리 보정).

## 6. 수치 확인 (관문 1, 100판)

- 시험·시뮬레이터는 "재료가 다 모이면 바로 만드는 플레이어"로 가정 (`autoCook`, 실패 없음).
- 관문 1 (C안 적용 후): 게임 458G·93.7%, 시뮬레이터 452G·92.0% → 통과 (예전 456G·93.1%).
- 1년 한 판 예시(시드 7001): 출발 36건 중 식사 24건 (들버섯 수프 10 · 민물고기 구이 8 · 멧돼지 스테이크 6).
- F급 요리 발견 시점(중앙값): 민물고기 구이 12주 · 멧돼지 스테이크 14주 · 들버섯 수프 15주. 1년 안에 99~100% 발견.
- 요리를 전혀 만들지 않으면 첫해 월 순이익 422G (기준 300~600G 안).
