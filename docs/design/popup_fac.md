# 시설 팝업 개편 설계

> 2026-11-05 사용자와 논의해 확정. 팝업 안쪽 내용 퀄업의 세 번째 대상. 공통 부품은 `prototype/css/ui_kit.css`.

## 0. 요약

| 영역 | 지금 | 바뀜 |
| --- | --- | --- |
| 등급 표시 | 동그라미 글자 배지 | **HUD 등급 배지 그림** (공통 `badge()` → 음식 설정·전직 제안 팝업도 같이 바뀜) |
| 한 줄 | 등급 · 이름 · 상태 | **[등급] \| [이름] \| [효과] \| [운영 또는 금액]** |
| 구역 | 한 목록 | **운영 중 → 지을 수 있음 → 잠김 · 준비 중** |
| 지을 수 있음 | 짓기 버튼 | 금고에 건설비가 있으면 **금빛 회전 테두리** (모험가 전직 제안과 같은 효과) |
| 유지비 | 월 건설비의 1.5% | **없음** |
| 효과 없는 시설 | 지을 수 있음(돈만 나감) | 예정 효과를 흐리게 + **"준비 중"** (짓기 막음) |

## 1. 줄 규칙

| 상태 | 4번째 칸 | 줄 모양 |
| --- | --- | --- |
| 지음 | ● 운영 중 | 연한 초록 |
| 지을 수 있음 | 짓기 ○○G (돈이 모자라면 비활성) | 돈이 있으면 금빛 회전 테두리 + 연한 금색 |
| 효과 있음 + 등급 부족 | ○급부터 | 흐림, 효과 문장은 진하게 |
| 효과 준비 중 | 준비 중 | 흐림, 효과 문장도 흐리게 |

## 2. 시설별 효과 문장

| 시설 | 등급 | 상태 | 효과 문장 |
| --- | --- | --- | --- |
| 의뢰 게시판 | F | 효과 있음 | 의뢰가 붙는 곳. 길드 등급이 오를수록 칸이 늘어납니다. |
| 접수대 | F | 효과 있음 | 모험가가 의뢰를 받아 가고 결과를 보고합니다. |
| 주점·식당 | F | 효과 있음 | 출발 전 식사로 능력치가 오르고, 식사 수입이 들어옵니다. |
| 소재 판매 창구 | F | 효과 있음 | 의뢰에서 얻은 소재를 되팔아 수입을 얻습니다. |
| 모험가 관리소 | E | 효과 있음 | 2차 전직을 할 수 있게 됩니다. |
| 길드 마스터 집무실 | E | 준비 중 | 스토리·귀빈 의뢰를 받고 길드 운영을 설정합니다. |
| 훈련장 | D | 준비 중 | 힘·민첩·기교를 훈련합니다. D → C 승급 조건. |
| 창고 | D | 준비 중 | 소재를 보관합니다. |
| 추모실 | D | 준비 중 | 떠난 모험가와 가문의 기록을 남깁니다. |
| 정보실 | C | 준비 중 | 중계료가 오르고, 예상 성공률이 정확해집니다. |
| 의무실 | C | 효과 있음 | 부상 회복이 빨라지고, 사망 확률이 줄어듭니다. |
| 도서관 | C | 준비 중 | 지력·정신을 훈련합니다. |
| 해체장 | B | 준비 중 | 원재료를 가공해 상위 레시피를 엽니다. B → A 승급 조건. |
| 휴게실 | A | 준비 중 | 모험가의 애착이 더 빨리 오릅니다. |
| 명예의 전당 | A | 준비 중 | 명성이 오르고 3차 직업 모험가를 기록합니다. A → S 승급 조건. |

- "효과 있음" = 지금 코드에 실제 효과가 있는 시설(`FAC_READY`). 효과가 생기면 목록에 추가.
- 정보실: 지어도 효과 수치(`s.eff`)가 0이라 중계료·예측 정확도가 오르지 않음 → 준비 중. 의뢰 게시판 ▲▼ 개체 표시는 "정보실이 있는가"만 봄.

## 6. F·E 시설 개편 (2026-11-12 확정, 프로토타입 · 업그레이드·집무실·문 구현됨)

> 프로토타입 범위(F·E)의 시설은 이 장이 기준입니다. 2장 표와 다르면 이 장을 따릅니다. 수치는 모두 프로토타입용 임시값이며 밸런스는 프로토타입 이후(todo 10절).
> 원칙: 효과는 %가 아닌 바로 읽히는 정수로 적는다 (`working_rules.md` 4장).

| 시설 | 등급 | 건설 | 지금 하는 일 (1단계) | 업그레이드 (2단계) | 업그레이드 비용 |
| --- | --- | --- | --- | --- | --- |
| 의뢰 게시판 | F | 처음부터 | 의뢰 게시, **처음부터 18칸**, 의뢰 기한 4주 (`popup_board.md` 10장) | 의뢰 기한 **+1주** | 500G |
| 접수대 | F | 처음부터 | 리나 응대. 출발·귀환·식사·술 주문 응대 시간을 **1.5초로 통일** | 응대 시간 **−0.5초** (1.0초) | 500G |
| 주점·식당 | F | 처음부터 | 출발 전 식사 + **술 1잔 단위 판매** (마진 F 2G / E 3G, 마을에 있는 모험가 1명당 주 1잔, 씀씀이 성향별 확률). 음식은 **앉은 모험가만** 주문 (`guild_interior.md` 10장) | 음식·술 1개당 마진 **+5G** | 500G |
| 소재 판매 창구 | F | 처음부터 | 소재 직접 판매 (F 6G / E 9G) | 소재 1개당 **+3G** | 500G |
| 모험가 관리소 | E | 2,000G | 짓지 않으면 전직 막힘 / 지으면 **2차 전직 제안 가능** | 전직 수락 확률 **+10%p** | 1,000G |
| 길드 마스터 집무실 | **F** (E에서 변경) | **1,000G** (2,000G에서 변경) | 짓지 않으면 기능 없음 / 지으면 **메인·서브 퀘스트에 모험가 지명** | 2단계(의뢰인 방문 등)는 프로토타입 이후 | — |

- **문 열림:** 로비 안쪽 문 2개는 길드 등급이 아니라 **해당 시설을 지으면 열림** (왼쪽 = 집무실, 오른쪽 = 관리소). 지금 열린 문 배경은 두 문이 함께 열린 한 장이라 문별로 나눠 덧그려야 함.
- **술 판매는 규칙(`game_core.js`)과 시뮬레이터에서 판정**하고, 로비의 술 주문 장면은 그 결과를 보여 준다 (화면 배속·로비 표시 여부와 무관하게 수입이 같도록).
- **접수대 응대 속도는 로비 연출 값**이라 게임 수치(수입·성공률)에는 영향이 없다. 응대 시간(1.5초)은 화면에 숫자로 보이지 않으므로 정수 원칙의 예외.
- **관리소 수락 확률:** 지금 식(애착 단계 40·65·90·100% × 2차 1.2배, 상한 100%)을 그대로 쓰고 +10%p만 더함. 애착 60 이상은 이미 100%라 효과가 없음 → 계산식 재설계는 프로토타입 이후.
- **소재 자동 차익**(의뢰 성공 시 보상의 8%, `econ.resaleRate`)은 프로토타입에서 그대로 둠. `economy_v1.md`의 "없앰"과 다름 → 밸런스 때 정리.
- **메인·서브 퀘스트**(F급)는 프로토타입 범위. 아직 코드에 없어 새로 구현해야 하며, 집무실이 지명 기능의 선행 조건.
- 화면: 하단 "시설" 버튼이 건설 메뉴가 됨 (시설 / 장식 / 테이블 탭, `guild_interior.md` 10장). 시설 탭에서 짓기·업그레이드.
- 반영 때 관문 1 재검증 (칸 18개, 술 판매, 테이블 0세트 시작, 앉은 모험가만 주문으로 수입·성공률이 바뀜).
