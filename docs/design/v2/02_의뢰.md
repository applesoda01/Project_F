## 요약

- 퀘스트는 목적에 따라 **메인 · 서브 · 리소스 3종**입니다(2026-11-09, 승급 퀘스트 분류 폐지). 길드 승급은 메인 퀘스트를 클리어하면 됩니다.
- 리소스 퀘스트(일상 의뢰)는 신뢰도와 마을 인구에 따라 유입되고, **한 달 5건을 4주로 나눠 매주 게시**합니다(2026-11-12, 10 → 5). 플레이어는 등급별 **의뢰 배분**(없음 · 적게 · 보통 · 우선)으로 육성 전략을 정합니다.
- 게시판은 프로토타입에서 **처음부터 18칸**, 의뢰 기한은 **게시 순간부터 4주**입니다. 만료되면 신뢰도 −1, 직접 취소(떼기)하면 위약금(보상의 10%) + 신뢰도 −2입니다.
- 의뢰 유형은 5종(토벌 · 사냥·채집 · 조사 · 호위·구호 · 탐사)이고, 전투 의뢰는 전투 계산으로, 비전투 의뢰는 능력치 프로필 충족률로 성패를 정합니다. 카드에는 해골 위험도(1~3)와 개체 표시(▲▼?)가 붙습니다.
- **지명 퀘스트**는 집무실에서 마스터가 모험가를 직접 골라 보내는 퀘스트로, 메인 · 서브가 모두 이 틀을 씁니다. 2026-11-16 결정: 퀘스트마다 최소 능력치 조건을 두되 **파티 중 1명만** 채우면 되고, 수락 확률은 전직과 같은 규칙(정수 %), 모험가에게도 보수 몫을 주며, 대열은 항상 자동(직업 순)입니다. **같은 날 오후 구현(13절):** 조건값 기준 15, 서브 퀘스트 전체 마감 없음, 섭외비(F 20G ~ S 600G, 거절당해도 지불).
- **F급 메인 퀘스트 = 침공 「다리를 지켜라」 (2026-11-16):** 리퀘스트 8번 들어주면 등장, 막아 내면 E급 (12.2절 → [08_길드승급.md](08_길드승급.md) · [03_전투.md](03_전투.md) 14장).
- 서브 퀘스트는 8종 유형을 바탕으로 **F급 28개 목록**이 제안되어 있습니다(카이로소프트식 게임 수치 등장 조건, 계절 퀘스트 9개, 의뢰인 NPC 8명). 잠긴 설비 10개(테이블 3 · 4번째 + 장식 8종)와 마을 건물 2개(대장간 · 물약 상점)가 서브 퀘스트 보상으로 열립니다.
- 메인 퀘스트는 F1 · E1 · D2 · C2 · B3 · A3 · S4 = 16개 [가안]이며, F급 메인은 모험가 관리소 해금 + E급 승급과 연결됩니다.

## 1. 퀘스트 카테고리

퀘스트는 목적에 따라 메인 · 서브 · 리소스 3종으로 나뉩니다(2026-11-09, 승급 퀘스트 분류는 폐지). 승급은 메인 퀘스트를 클리어하면 다음 등급이 되는 구조입니다. 지금까지 정한 일상 의뢰 규칙(유입, 필터, 성공 판정)은 리소스 퀘스트의 규칙입니다.

| 구분 | 메인 | 서브 | 리소스 |
| --- | --- | --- | --- |
| 목적 | 마스터의 서사, 마왕, 길드 승급 | 마을 사람·모험가 이야기, 히든 | 금전·소재 |
| 등장 경로 | 의뢰인이 집무실 방문 | 집무실 방문 또는 마을 말풍선 | 게시판 자동 등록 |
| 거절 | 불가(보류만) | 가능(일정 기간 뒤 재등장) | 게시판 철회 규칙 |
| 반복 | 1회 | 1회 | 반복 |
| 실패 시 | 재도전 가능 | 재도전 가능 | 소멸 |
| 보상 | 서사, 명성, 등급 상승 | 서사, 건물·전직 개방 | 금전, 소재 |

> ⚠️ 출처 차이: design_v0.1.md §6.0은 메인 · 서브 · **승급** · 리소스 4종(승급 = 등급 조건 충족 시 접수원 보고, 보상 = 등급 상승)이고 "메인을 하지 않아도 승급할 수 있다"고 적었으나, game_overview.md §4 · progression_v1.md(2026-11-09) · decisions.md는 승급 분류를 없애고 3종으로, "길드 승급 = 메인 퀘스트 클리어"로 바꿈 → 최신인 3종 분류를 따름. game_overview.md §11 "불일치" 목록에도 "설계서 본문은 그대로(4종 분류)"로 올라 있음.

- **메인과 승급의 관계:** 길드 등급에 도달하면 그 등급의 메인 퀘스트가 열립니다. 열린 메인은 사라지지 않고, 접수원이 월간 보고에서 상기시킵니다. (원안의 "메인을 하지 않아도 승급할 수 있다"는 위 출처 차이에 따라 "메인 클리어 = 승급"으로 바뀜. 승급 규칙 자체는 → [08_길드승급.md](08_길드승급.md))
- **서브의 세 갈래:** 마을 사람(핵심 건물 11종 등), 모험가(애착·친밀도, 성향 변화 계기), 히든(조건이 있어야 열림).
- **히든 서브:** 전직 탐색과 같이 소문 → 근접(조건 일부 공개) → 발견 순서로 드러납니다.

**기존 의뢰의 배치** (design_v0.1.md 원안)

| 기존 항목 | 카테고리 |
| --- | --- |
| 일상 의뢰 (토벌·사냥·채집·조사·호위·탐사), 복원 재료 특별 의뢰 | 리소스 |
| 보스급 의뢰, 승급 침공 | 승급 |
| 간부 퀘스트, 마왕성 | 메인 |
| 핵심 건물 11종 의뢰 | 서브 (마을 사람) |
| 3차 확장 의뢰, 용사의 검, 현자의 지팡이, 마인, 대도서관, 선택 간부 | 서브 (히든) |
| 소규모 습격 | 퀘스트가 아닌 방어 이벤트 |

> ⚠️ 출처 차이: 위 표의 "승급" 줄(보스급 의뢰, 승급 침공)은 승급 퀘스트 분류가 폐지되어 새 3종 안에서 어디로 갈지 다시 정하지 않음. 승급 흐름 원안(보스급 의뢰 N건 → 침공)은 → [08_길드승급.md](08_길드승급.md).

- 핵심 건물 11종 서브 스토리(D~A급, 총 20개)의 사연 · 의뢰인은 → [09_스토리_세계관.md](09_스토리_세계관.md), 건물 자체는 → [06_마을.md](06_마을.md).

## 2. 의뢰 유입

### 2.1 유입 경로

| 구분 | 유입 방식 | 플레이어의 판단 |
| --- | --- | --- |
| 리소스 퀘스트 (일상 의뢰) | 신뢰도와 마을 인구에 따라 유입되고, 필터(의뢰 배분)를 통과한 것만 자동 게시 | 필터 설정 |
| 메인·서브 퀘스트 | 의뢰인이 길드 마스터 집무실에 직접 방문 (서브는 마을 말풍선도) | 메인은 보류만, 서브는 수락·거절 |
| ~~승급 퀘스트~~ | ~~등급 조건 충족 시 접수원이 보고~~ | ~~보류 또는 진행~~ |

- 승급 퀘스트 줄은 1절의 분류 폐지로 지움(원안 표에는 있음).
- 핵심 수치와의 관계(design_v0.1.md §4): **신뢰도** = 의뢰인의 신뢰, 의뢰 유입량에 영향 / **마을 인구** = 의뢰 유입량에 영향 / **길드 등급** = 게시판 용량, 의뢰 난이도 상한에 영향.

> 출처: design_v0.1.md §6.1 · §4 · game_overview.md §4

### 2.2 월간 유입량과 매주 게시

**월간 의뢰 유입량** = 기본량 × 신뢰도 보정 × 인구 단계 보정 [가안]

| 항목 | 값 |
| --- | --- |
| 기본량 | **한 달 5건** (`quest.perMonth`, 2026-11-12 10 → 5) |
| 게시 | **매주 게시** — 한 달 5건을 4주로 나눠 매주 게시 (× 신뢰도 퀄리티) |
| 만료 | 게시 후 4주가 지나면 만료 (4절) |
| 신뢰도 보정 | 신뢰도 5단계에 따라 의뢰 수 · 보상 · 경험치 변동 (2.3) |
| 인구 단계 보정 | 마을 인구 단계 개척촌(~299) → 마을(300) → 읍(1,000) → 도시(2,000) → 성채 도시(3,500)에 따라 ×1.0 → ×2.5 (→ [06_마을.md](06_마을.md)) |

> ⚠️ 출처 차이: balance/progression_v1.md(2026-11-09)는 기본량을 "한 달 10건"(단위 실수 바로잡음)으로, 매주 나눠 게시하도록 정했고, popup_board.md §10-1(2026-11-12)은 매주 게시로 바꾸자 월 약 10건이 되어 모험가 8명이 소화하지 못한다는 이유로 `quest.perMonth`를 **10 → 5**로 줄임 → 최신인 5건을 따름(game_overview.md 갱신 기록 2026-11-12와 같음).

- **예전 코드:** 의뢰를 `week % 4 === 0`일 때만 게시(= 월 유입의 1/4)했으나, 2026-11-12부터 매주 게시합니다.
- **유입량을 5로 줄인 이유:** 매주 게시로 바꾸자 의뢰가 월 약 10건(예전 실제 2~3건)이 되어 모험가 8명이 소화하지 못하고 1년에 42건이 만료, 신뢰도가 50 → 27로 떨어짐. 5로 줄이면 만료 연 약 10건, 연말 신뢰도 약 54. 유입량은 나중에 아이템·시설 등으로 올리는 구조로 감 (2026-11-12 결정).
- **관문 1 (100판):** 바꾸기 전 게임 443G · 93.4% / 시뮬레이터 456G · 91.8% → 바꾼 뒤 게임 **492G · 95.0%** / 시뮬레이터 **510G · 94.0%** (통과). 성공률이 상한 95%에 붙어 있어 밸런스 때 확인. 1년 성공 의뢰: 33건 → 약 56건.

> 출처: design_v0.1.md §6.1 · game_overview.md §2 · 갱신 기록 · popup_board.md §10 · §10-1 · balance/progression_v1.md §2-1

### 2.3 신뢰도와 의뢰

- 신뢰도(0~100, 시작 50)는 5단계로 의뢰 수·보상·경험치에 영향을 줍니다. 1단계 유지 시 수입·성장이 보통의 약 60%, 5단계면 약 2.25배입니다. 단계별 범위표는 [../../balance/progression_v1.md](../../balance/progression_v1.md) §2-1에 있습니다.
- 신뢰도 자체의 정의 · 변동 규칙 전체는 → [05_길드.md](05_길드.md). 의뢰 결과에 따른 신뢰도 변화는 6.3, 만료 · 취소에 따른 변화는 4절에 둡니다.

## 3. 필터 (의뢰 배분)

- 게시판 칸을 **절대 등급(F~S)별로 배분**합니다. (예전 이름: 칸 배분 → **의뢰 배분**, 2026-11-05)
- 필터 설정이 곧 길드의 **육성 전략**입니다. 예를 들어 고등급 위주로 배분하면 정예 집중, 저등급 칸을 남기면 신인과 2세 육성이 됩니다.

| 항목 | 규칙 |
| --- | --- |
| 버튼 | 없음 · 적게 · 보통 · 우선 |
| 비중 | 0 · 1 · 2 · 4 (우선 = 보통의 2배) |
| 의미 | 게시판 최대 칸 수 안에서 등급별 비율. 예: 8칸, F 보통·E 우선 → F 3칸 · E 5칸 |
| 칸 수 계산 | 최대 나머지 방식으로 반올림해 **합이 최대 칸 수와 정확히 같게** |
| 표시 | 결과 칸 수는 표시하지 않음 (2026-11-05 결정). 전체 칸 수는 "게시된 의뢰 7 / 8칸" 제목에 |
| 모두 없음 | **불가.** 마지막 하나를 없음으로 바꾸려 하면 안내만 띄움 ("적어도 한 등급" 규칙) |
| 새 등급이 열릴 때 | **그 등급만 "우선"**, 기존 등급 값은 그대로 |
| 기존 저장 값 변환 | 슬라이더 0 → 없음, 1~2 → 적게, 3~6 → 보통, 7~10 → 우선 |

- 책 UI(2026-11-13)에서는 등급마다 **막대 3개**(없음 0 · 적게 1 · 보통 2 · 우선 3)를 눌러 정하고, 칠해진 맨 위 막대를 다시 누르면 없음이 됩니다. 버튼 배치 · 막대 모양은 → [10_UI.md](10_UI.md)

> ⚠️ 출처 차이: popup_board.md §1(2026-11-05)의 비중은 0 · 1 · 2 · 4이고, §7 책 펼침판(2026-11-13)의 "0 · 1 · 2 · 3"은 칠한 막대 수입니다. 비중 값이 바뀌었다는 기록은 없으므로 비중은 0 · 1 · 2 · 4로 둠. 구현 때 확인 필요.

- 의뢰 유형을 필터 조건에 넣을지는 미결입니다(미결 참고).

## 4. 게시판 규칙

### 4.1 기본 규칙

| 항목 | 내용 |
| --- | --- |
| 용량 | 프로토타입은 **처음부터 18칸** (게임 전체 최대치). 등급별 칸 수 증가(`quest.boardCap`)는 프로토타입에서 쓰지 않음 |
| 의뢰 기한 | 게시된 순간부터 **1달(4주)** (4.2) |
| 수주 | 모험가가 취향에 맞는 의뢰서를 스스로 골라 수주 |

### 6.2 능력치 프로필 (비전투 의뢰)

의뢰마다 요구 능력치를 비율로 가지고, 파티 능력치 합이 이를 얼마나 채우는지로 성공을 판정합니다.

| 의뢰 등급 | 요구 능력치 수 |
| --- | --- |
| F~E | 1개 (솔로로 충분) |
| D~C | 2개 |
| B~A | 3개 |
| S | 4개 |

- 의뢰 유형의 대표 능력치가 가장 큰 비중을 차지합니다.
- 능력치별 충족률을 비중대로 평균 내고, 능력치별 충족률은 최대 150%까지 인정합니다. [가안]
- 성공률 = 0.55 + 1.1 × (종합 충족률 − 1), 최소 5% ~ 최대 97% [가안]
- 병목: 요구 능력치 중 하나라도 충족률이 50% 미만이면 성공률 절반 [가안]
- 식당 요리 효과(비전투는 성공 확률 +)는 → [05_길드.md](05_길드.md)

> 출처: design_v0.1.md §6.6 · game_overview.md §4

## 7. 위험도와 개체 표시

### 7.1 위험도 (해골)

- 기준: **그 의뢰 등급의 표준 모험가**(장비 없음)가 예측 전투(combat.js `predict`, 게시 정보 기준·무작위 없음)에서 **승률 70% 이상**이 되는 최소 인원.
- 1명 → 해골 1, 2명 → 해골 2, 3명 이상 → 해골 3 (상한 3). 상세 창에 "○급 모험가 N명 권장" 문장.
- 표준 모험가: F급 Lv 2, E급 Lv 6 (주력 능력치 17 + 레벨 성장, 나머지 7.5 + 성장). 직업 5종 조합(연속 n개 직업)의 평균 예측 승률로 판단.
- 몬스터 수치를 바꾸면 게임이 다시 계산하므로 자동으로 따라 바뀜.
- E급으로 올라가는 것 자체가 어렵다는 점이 해골로 직관적으로 보이는 것은 의도(사용자 확인).
- 비전투 의뢰는 해골이 없습니다.
- **위험도 결과(F·E 전투 의뢰 11종, 2026-11-05):** 해골 1 = F 탐사·F 호위 2 / 해골 2 = F 토벌·F 호위·F 토벌 2·F 사냥 2·E 사냥·E 호위 / 해골 3 = E 토벌·E 탐사·E 토벌 2.

> 출처: popup_board.md §2 · §3 · §9

### 7.2 개체 표시 (▲▼)

의뢰마다 붙는 적 개체 차이(`combat,enemyVar` ±15%)를 3구간으로 보여 줍니다.

| 개체 차이 | 표시 |
| --- | --- |
| 0.85 ~ 0.95배 | ▼ 약한 무리 (초록) |
| 0.95 ~ 1.05배 | 표시 없음 |
| 1.05 ~ 1.15배 | ▲ 강한 무리 (빨강) |

- **정보실이 있을 때만** 실제 구간을 보여 줌(1단계 이상이면 동일). 없으면 "?" 표시.
- 정보실 단계는 지금처럼 모험가의 예측 정확도에만 영향(1단계마다 오차 25% 감소).
- 비전투 의뢰는 표시 없음.
- 개체 차이 ±15% 자체의 전투 규칙은 → [03_전투.md](03_전투.md)

## 11. 서브 퀘스트 보상: 설비 해금 (2026-11-13 사용자 결정)

서브 퀘스트를 구현할 때 이 연결을 같이 넣습니다. 설비 쪽 규칙 · 화면은 먼저 준비함(반영 전 작업용 사본, 시설 장 시안).

- **규칙:** 게임 처음엔 설비 중 **테이블 2세트만** 지을 수 있음. **테이블 3 · 4세트와 장식 8종**(화분 · 게시판 장식 · 사물함 · 현수막 · 대기 벤치 · 낡은 지도 · 벽난로 · 트로피 장식장)은 **서브 퀘스트(리퀘스트) 보상**으로 하나씩 열림.
- **연결 자리 (코드):** `game_core.js` `unlockReward(s, id)` — `'table'`이면 테이블 1세트 더(최대 4), 장식 id면 그 장식 열기. 상태는 `s.unlock = { table: 2, deco: {} }`, 놓을 수 있는 수는 `capOf(s, id)`.
- **데이터 표 연결:** `rw_table_cap`(테이블 +1) · `rw_deco_cap`(장식) 열 → 보상 지급 때 `unlockReward` 호출. 장식은 "설치 수 +1"이 아니라 **어떤 장식을 여는지(장식 id)**로 적어야 함 → `rw_unlock`에 장식 id를 넣는 방식 추천(sub_quest_F_v1.md §4에서 `rw_unlock` 값 목록 확정).
- **화면:** 시설 장 왼쪽 설비 카드 — 잠긴 장식 = 흐린 그림 + 자물쇠 + "리퀘스트 보상", 테이블 = `0/2` · "3~4세트는 리퀘스트 보상". 보상을 받으면 기록에 "새 장식을 얻었습니다" 한 줄. (→ [10_UI.md](10_UI.md))
- **시험:** 개발 메뉴 "설비 보상 열기" = 테이블 4세트 · 장식 8종 모두 열기.
- **예전 저장:** 해금 도입 전 저장은 이미 놓은 테이블 수 · 장식을 열린 것으로 둠 (`migrate`).
- **밸런스 측정 (관문 1, 첫해 100판):** 테이블 상한 4 → 2로 바꿔도 게임 483G · 94.5% → 482G · 94.6%, 시뮬레이터 472G → 469G (첫해엔 3 · 4번째 테이블을 거의 사지 않음). 관문 1은 장식 없음 가정이라 장식 잠금 영향 없음.
