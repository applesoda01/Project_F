## 요약

- 화면은 **타이틀 → 저장 칸 → 검정 페이드 → (새 게임이면) 프롤로그 영상 → 길드(로비) ↔ 마을**로 이어지고, 플레이어는 하단 HUD와 팝업으로 운영합니다.
- 타이틀은 도트 모험가 무리가 달리는 배경 위에 COLLEGIUM 로고, PRESS ANY KEY, 가로 한 줄 메인 메뉴(새 게임 · 이어하기 · 옵션 · 종료)를 둡니다. 저장 칸은 세로 카드 3장입니다.
- 팝업 7종(의뢰 게시판 · 모험가 · 시설 · 장부 · 길드 기록 · 도감 · 전직 제안)과 식당은 2026-11-05~09에 안쪽 내용을 모두 개편했고, 2026-11-13부터 **"길드 업무 일지" 책 펼침판**(왼쪽 큰 책갈피 7장: 의뢰 · 리퀘스트 · 모험가 · 시설 · 음식 · 경영 · 설정)으로 다시 담았습니다. 기존 팝업 화면과 기능은 그대로 남아 있습니다.
- 팝업 공통 부품은 `prototype/css/ui_kit.css`(등급 배지 · 10칸 막대 · 아이콘 칸 · 오버 창), 책 화면은 `prototype/css/book.css`와 조절 도구 `prototype/tools/book_layout_editor.html`입니다.
- 길드 화면 오른쪽에는 **원정 현황 패널**(평소 반투명 50%, 마우스를 올리면 100%)이 항상 있고, 줄을 누르면 **원정 미니 뷰**(480×203, 배경 투명, 횡스크롤)가 열려 출발 때 계산된 전투 기록을 재생합니다.
- 리퀘스트 장의 **지명 창**, 모험가 칭호 · 몸 상태 · 대화의 화면 자리는 설계 또는 견본 단계입니다(각 절의 상태 표기 참고).
- 규칙과 수치는 컨텐츠 문서가 기준이며, 이 문서는 화면에 필요한 만큼만 적고 링크합니다.

## 1. 화면 흐름과 화면 목록

화면은 타이틀 → 길드(단면 로비) ↔ 마을로 이어지고, 플레이어는 하단 HUD와 팝업으로 운영합니다. 팝업은 공통 부품(`ui_kit.css`)으로 만들어 등급 배지 · 막대 · 아이콘 칸을 일관되게 쓰도록 정리 중입니다.

**화면 흐름 (2026-11-11 합침 반영)**

1. 타이틀: 도트 전사들이 달리는 배경 + COLLEGIUM 로고 + PRESS ANY KEY → 메뉴(새 게임 · 이어하기 · 옵션 · 종료)
2. 저장 칸 선택: 새 게임은 빈 칸 · 덮어쓰기(두 번 눌러야 시작), 이어하기는 저장된 칸만. 칸마다 날짜 · 등급 · 골드 · 모험가 수 · 플레이 시간 · 저장 시각 표시, Esc로 타이틀 복귀
3. 암전 → 프롤로그 영상(약 101.6초, 건너뛰기 가능, 새 게임에서만) → 길드
4. 게임 안 옵션 메뉴에서는 '새 게임'을 삭제했고 불러오기는 유지합니다.

타이틀 구성(시작 연출 카메라 상승 연출은 미구현)과 프롤로그 영상 파일 위치(`prototype/assets/prologue/`)는 추후 확인이 필요합니다.

**길드 · 마을 화면**

| 화면 | 핵심 구성 | 현재 상태 |
| --- | --- | --- |
| 길드 1층 | 14×14칸 쿼터뷰 내부, 게시판(클릭 시 팝업), 테이블 · 장식, 구름 · 바깥 풍경 | 로비 코드 보류(리나 그림 · 캐릭터 애니메이션 완료 대기), 시간 · 계절 연출 설계 완료 |
| 마을 | 탑뷰, 건물 클릭 팝업, 거주 모험가 · 비둘기 · 말풍선, 낮밤 · 계절 | 말풍선이 캐릭터를 따라다니고, 비둘기 그림자는 물 위에서만 보이도록 수정 |
| 원정 현황 패널 | 길드 우측, 원정 중 모험가 목록(평소 반투명), 클릭 시 미니 뷰 | 구현 |

## 2. 타이틀 화면

> 2026-11-02 사용자와 함께 정리. 미리보기: `prototype/tools/title_preview.html`, 도트 규격: [`docs/art/pixel_spec.md`](../../art/pixel_spec.md)

### 2-1. 화면 순서

1. 하늘색 배경 아래로 도트 땅이 흐르고, 전사가 왼쪽 밖에서 달려 들어옴. 화면 가운데에 오면 카메라가 따라감.
2. 타이틀(마법진 + 문양 + COLLEGIUM)이 등장하고, PRESS ANY KEY가 반짝임(땅과 겹치는 위치).
3. 아무 키나 누르면 PRESS ANY KEY가 사라지고 메인 메뉴가 나타남.
4. 메인 메뉴: **새 게임 · 이어하기 · 옵션 · 종료**

| 메뉴 | 동작 |
|---|---|
| 새 게임 | **저장 칸 3개 층이 열림** (2-5절) |
| 이어하기 | 저장 칸 3개 층이 열림. 저장된 칸을 고르면 시작 연출 후 저장 시점으로 |
| 옵션 | 빈 팝업(내용은 나중에) |
| 종료 | 보이기만 하고 지금은 반응 없음 |

> 출처: title_screen.md §1

### 2-2. 달리는 무리 (2026-11-02)

- 배경에 동시에 보이는 캐릭터는 **최대 5명**. 모험가 10종(직업 5 × 남녀) 중 겹치지 않게 고름. 동작은 **달리기만** 사용(쓰러짐 없음).
- 처음엔 전사 남 혼자 왼쪽에서 달려 들어옴. **카메라는 맨 앞 캐릭터**를 화면 가운데에 둠.
- **합류:** 1~4명이 함께 뒤(화면 왼쪽 밖)에서 빠르게 달려와(땅보다 최대 +150도트/초) 줄 끝에 붙음.
- **줄:** 합류하면 **한 줄로** 서서 앞 캐릭터를 따라감. 줄 간격 기본 62도트(조절 막대 "줄 간격").
- **이탈:** 가끔 한 명이 오른쪽으로 빠르게(+220) 달려 나가 사라짐 → 남은 캐릭터가 다시 한 줄로 정렬. **맨 앞이 빠지면 카메라는 다음 캐릭터로 부드럽게 넘어감.**
- 무리 사건은 7~15초마다 1번(5명 미만이면 합류 65%, 2명 이상이면 이탈 가능).
- 다리 동작은 각자 달린 거리로 넘어가므로, 빨리 달리는 캐릭터는 다리도 빠름.

> 출처: title_screen.md §1-1

### 2-3. PRESS ANY KEY → 메인 메뉴 (구현됨)

- 타이틀 등장(5.2초) 뒤 아무 키 · 클릭 → PRESS ANY KEY가 잠깐 빛나고 사라짐 → 같은 자리에 메뉴가 서서히 나타남.
- **메뉴는 가로 한 줄** (2026-11-02 변경, 세로 → 가로): PRESS ANY KEY 자리(y=818, 땅과 겹침), 화면 가운데 기준, 항목 간격 230, 글자 32. 타이틀 크기는 그대로(0.8).
- 고른 항목: 밝아지고 양옆 마름모 + 아래 밑줄. 좌우 화살표 · 마우스로 고르고 Enter · 클릭으로 정함.
- 새 게임 → 저장 칸 층(새 게임), 이어하기 → 저장 칸 층(이어하기), 옵션 → "준비 중" 팝업, 종료 → 반응 없음.
- 층이 닫히면 메뉴로 돌아옴. 메인 메뉴에서 Esc · 오른쪽은 반응 없음.

> 출처: title_screen.md §1-2

### 2-4. 타이틀 공통 규칙

- 메뉴 표현: 은빛 글자만, 가로 한 줄. 고른 항목은 양옆 마름모 · 밑줄 + 밝게.
- 저장 기록이 하나도 없으면 **이어하기는 흐리게**, 고를 수 없음.
- **Esc · 마우스 오른쪽 = 바로 전 화면.** 메인 메뉴에서는 반응 없음(PRESS ANY KEY로 돌아가지 않음).
- 층(저장 칸 · 옵션)이 열려도 뒤 화면(타이틀 · 배경 · 달리기)은 그대로. 층이 열려 있는 동안 PRESS ANY KEY 자리에 **"뒤로가기"** 글자.

> 출처: title_screen.md §2

### 2-5. 저장 칸 층

- 칸 3개. 칸마다 보여줄 것: **저장 날짜 · 시간, 길드 단계, 플레이 시간, 모험가 수, 소지금**(구현본은 저장 시각도 표시). 칸마다 반투명 어두운 바탕.
- **모양: B 세로 카드 3장 (확정)**. 카드 330×570(화면 px), **카드 간격 140**(가운데 카드 기준 좌우 대칭), 위 125. 모서리 깎은 은빛 테두리 2겹 + 위쪽 눈금 + 아래쪽 가는 선 · 마름모, 바탕 짙은 남색 88%.
  - 위에서부터: 칸 번호 문양(눈금 있는 작은 마법진 안에 Cinzel Ⅰ·Ⅱ·Ⅲ, 고른 칸은 천천히 회전) → 길드 단계 → 저장 날짜 · 시간 → 구분선 → 플레이 · 모험가 · 소지금(금색)
  - 고른 칸: 테두리 발광 + 양옆 장식선 · 마름모. 한글은 고운바탕체.
  - 카드가 길어 가운데 카드가 달리는 캐릭터 머리를 가림(층이 열려 있는 동안만).
- 빈 칸은 **"비어 있음"** + 음영.

| 들어온 곳 | 빈 칸을 고르면 | 저장된 칸을 고르면 |
|---|---|---|
| 새 게임 | 그 칸에 새로 시작 → 시작 연출 → 프롤로그 | 덮어쓰기 (구현: **두 번 눌러야** 덮어씀 · 설계: 경고 "덮어쓰겠습니까?") |
| 이어하기 | 고를 수 없음(음영) | 시작 연출 → 저장 시점으로 |

> ⚠️ 출처 차이: title_screen.md §3(2026-11-02)은 저장된 칸을 고르면 경고 창 "덮어쓰겠습니까?"(예 / 아니오)를 띄운다고 하고, title_screen.md §5 제작 목록과 game_overview.md §9(2026-11-12)는 "덮어쓰기 · 삭제 2번 클릭"으로 구현됐다고 함 → 최신인 "두 번 눌러 덮어쓰기"를 본문에 따르고, 경고 창 설계는 아래에 남겨 둠.

## 3. 팝업 공통 규칙

### 3-1. 개편 방식과 공통 부품

### 6-7. 아래 탭 (기존 팝업, 2026-11-05 확정)

- 스킬 · 전직 · 성향 · 경력. 항상 하나가 펼쳐져 있고 기본은 **스킬**.

**스킬**

| 항목 | 규칙 |
| --- | --- |
| 장착 칸 | **5칸** (설계서 7.4-1). 가진 스킬은 아이콘 + 이름, 나머지는 "빈 칸"(오버 안내 없음) |
| 아이콘 | 1차 5 + 2차 25 = 30종 (`skill_<str·agi·int·spi·dex>_<0~5>.png`, 계열 안 순서 = 스킬 표 순서). 3차는 아직 없어 그 계열 1차 아이콘을 씀 |
| 칸 테두리 | 계열 색: 힘 빨강 · 민첩 초록 · 지력 파랑 · 정신 금색 · 기교 보라 |
| 오버 창 | 이름 · 계열 · 직업 · 효과 · 계열 능력치 / **진화**: 발견한 직업만 "직업 → 진화 스킬", 모르는 직업은 "? 아직 모르는 직업" 한 줄 (초반엔 이것만) |

**전직**

- 발견한 직업만 표시("아직 모르는 직업 N개" 줄 없음).
- 조건은 능력치와 같은 10칸 칸 막대 + **빨간 세로선 = 필요치**. 채우면 숫자 초록 + "조건 충족".

**성향**

| 순서 | 표시 |
| --- | --- |
| 애착 (맨 위) | 애착 [단계] + 진행 바 + 수치 + 다음 단계, 아래 한 줄 설명 |
| 모험심 · 소비 · 사교 | 항목 이름 + [값 박스] + 행동 문장. **수치는 화면에 보이지 않음** (내부 규칙만) |

- "위험" 축의 화면 이름 = **모험심** (내부 이름 risk는 그대로).
- 말투 줄 삭제 (모험심 · 사교에서 자동으로 정해지고 말풍선 분위기만 바꿈).
- 애착 단계 이름: 방랑자 · **새내기** · 동반자 · **토박이** (아래 출처 차이 참고).

| 값 | 문장 |
| --- | --- |

> **요약:** 길드 화면 오른쪽 가장자리에 **원정 중인 모험가 목록**을 항상 띄웁니다. 평소에는 **반투명(불투명도 50%)** 으로 두어 길드 장면을 가리지 않고, **마우스를 올리면 100%** 로 선명해집니다. 한 줄에는 이름 · 등급 · 의뢰명 · 진행 바 · 위험도를 보여 주고, 귀환하면 목록에서 사라집니다. **줄을 탭하면 오른쪽 아래(하단 HUD 위)에 그 모험가의 원정 장면(미니 뷰)이 열려** 진행 상황에 따라 이동 · 조우 · 전투 · 결과 장면이 바뀝니다(15절). 코드 이름은 패널 `hudExp`, 미니 뷰 `expView`.

### 14-1. 확정 · 가정

| 구분 | 내용 | 근거 |
| --- | --- | --- |
| 확정 | 패널은 우측에 **항상 표시**, 평소 반투명, 마우스를 올리면 선명 | 사용자 지시 |
| 가정 | 한 줄 정보 = 이름 · 등급 · 의뢰 · **진행 바 · 위험도** | 질문 답변 "2번"을 모든 항목에 적용해 해석 |
| 가정 | 목록 = **현재 원정 중인 모험가만**(귀환하면 삭제), 이벤트 로그 없음 | 같은 해석 |
| 가정 | 이번 산출물 = **기획서만**(목업 · 구현 없음) | 같은 해석 (이후 구현됨, 14-8절) |
| 확정 | 줄을 탭하면 **오른쪽 아래(하단 HUD 위)에 원정 장면** 표시 | 사용자 지시 |
| 확정 | 장면 방식 = **장소 배경 + 파티 동작 반복**에 더해 **진행 상황에 따라 장면 전환**(둘 다) | 사용자 답변 |
| 확정 | 닫기 = **같은 줄 재탭 또는 X 버튼**에 더해 **귀환 시 자동으로 닫힘**(둘 다). 이후 X 버튼은 없애고 미니 뷰 클릭으로 바뀜(15-6절) | 사용자 답변 |
| 확정 | 미니 뷰에는 **파티원을 전원 그림**(대표만 그리지 않음) | 사용자 지시 |
| 확정 | 장면은 **횡스크롤(측면 뷰)** 로 진행 | 사용자 지시 |
| 주의 | 기획서의 파티 최대 인원은 **5인**이라 "4명"이 아니라 **최대 5명 전원**을 기준으로 설계 | 기획서 파티 규칙 |

> 출처: expedition_panel.md 머리 요약 · §0

### 14-2. 목적과 위치

1. 길드 화면은 시간이 흐르고, 모험가는 스스로 의뢰를 골라 길드 밖으로 나갑니다. 지금은 "누가 어디서 무엇을 하는지"를 볼 곳이 없습니다.
2. 기획서 6.4의 "마을에서 활동 중인 모험가 패널"과 **같은 계열**이지만, 이 패널은 **원정 중**인 모험가에 한정합니다. 6.4는 전체 모험가 필터형 목록이므로 역할이 겹치지 않게 별도 화면으로 둡니다.
3. 마스터가 확인할 질문은 세 가지입니다. 누가 나가 있는가, 언제 돌아오는가, 위험한가.

> 출처: expedition_panel.md §1

### 14-3. 화면 배치 (1920×1080 기준)

| 항목 | 값 [가안] |
| --- | --- |
| 위치 | 오른쪽 가장자리, 우측 여백 16px |
| 크기 | 폭 360px, 높이는 줄 수에 따라 늘어나며 최대 약 700px |
| 세로 범위 | 상단 y=96 ~ 하단 y=800 (상단 HUD 아래, 하단 HUD(`hudBR`) 위) |
| 겹침 | 오른쪽 위는 배속 바 이동 이후 비어 있고, 오른쪽 아래는 `hudBR`이 쓰므로 그 사이를 사용 |
| 레이어 | 길드 장면 위, 대사창(`dlg`) · 팝업(`pop`) 아래. 팝업을 열면 패널 · 미니 뷰는 팝업 뒤로 |

- 미니 뷰가 열리면 패널의 세로 범위가 줄어듭니다(패널 y=96~581, 미니 뷰 y=597~800). 미니 뷰를 패널과 겹치지 않는 곳으로 옮겨 두면 패널이 짧아지지 않습니다(15-6절).
- 실제 프로토타입의 `hudTL` · `hudBR` 크기와 맞는지는 구현 전에 확인합니다.
- 반투명이어도 패널은 클릭을 받습니다. 뒤에 있는 길드 장면의 클릭 대상(모험가 · 시설)이 패널 영역과 겹치지 않도록 길드 화면 우측 여백을 확보해야 합니다.

> 출처: expedition_panel.md §2 · §13 · popup_board.md §7(함께 고칠 것)

### 14-4. 패널 구조와 한 줄 정보

```
┌ 원정 중 (5)                        ┐   ← 머리줄: 제목 + 인원수
│ [D] 리나  고블린 소굴 토벌          │
│     ▓▓▓▓▓░░░░░  3주 남음   ▲ 위험  │
│ [E] 카일  약초 채집 (2인)           │
│     ▓▓▓░░░░░░░  1주 남음   ● 안전  │
│ ...                                │
└─────────────────────────────────────┘
```

- 머리줄은 `원정 중 (N)` 입니다. 인원이 0이면 패널 전체를 숨깁니다.
- 목록은 한 줄 높이 약 64px(2행 구성)이고, 화면에는 최대 8줄을 보여 준 뒤 스크롤합니다. 모험가 최대 99명 기준이지만 한 번에 원정 중인 수는 대부분 이보다 훨씬 적습니다.

| 칸 | 내용 | 표시 규칙 |
| --- | --- | --- |
| 파티 색 띠 | 그 의뢰의 파티 색 (2026-11-12) | 줄 왼쪽 세로 띠(5px) + 등급 배지 테두리. 로비 발밑 원 · 모험가 목록과 같은 색(6-8절) |
| 등급 배지 | 모험가 등급 F~S | 기존 등급 배지 에셋을 축소 사용 |
| 이름 | 모험가 이름 | 파티면 대표(파티장) 이름 + "외 N" |
| 의뢰명 | 수주한 의뢰 이름 | 긴 이름은 말줄임 |
| 진행 바 | 경과 기간 ÷ 전체 소요 기간 | 주 단위로 마디를 표시 |
| 남은 기간 | "N주 남음", 마지막 주는 "곧 귀환" | 월 = 4주 기준 |
| 위험도 | 안전 / 주의 / 위험 3단계 | 아이콘 + 글자 + 색을 함께 사용(색만으로 구분하지 않음) |
| 지명 표시 [제안] | 지명 의뢰면 📜 배지 | 5절 |

**위험도 산정 [가안]:** 성공률 70% 이상 = 안전, 40~69% = 주의, 40% 미만 = 위험. 시뮬레이터에서 분포를 보고 구간을 조정합니다. 게임에서는 출발 때 예상 성공률(`rate`)을 씁니다.

**파티 처리:** 같은 의뢰의 파티는 **한 줄로 묶고**, 구성원 수를 이름 옆에 표시합니다. 선택(클릭) 시 구성원이 펼쳐집니다.

> 출처: expedition_panel.md §3 · §4 · §16 · popup_advs.md §8 · nomination_v1.md §3

### 14-5. 반투명과 호버 동작

| 상태 | 불투명도 | 전환 |
| --- | --- | --- |
| 평소 | 50% [조절기로 확정] | - |
| 마우스 진입 | 100% | 0.15초 |
| 마우스 이탈 | 50% | 0.3초 지연 후 0.3초 |
| 새 항목 발생 · 귀환 임박 | 해당 줄만 1초 강조 후 원래 투명도 | 호버 없이도 알림 |

- 반투명일 때도 글자는 읽혀야 하므로, **줄 배경은 어두운 나무 질감으로 채우고 전체를 반투명 처리**합니다(글자만 투명하게 하지 않습니다).
- 50%라는 값은 `dialog_tuner`와 같은 방식의 조절기로 정합니다. 대사창 시안(55/70/85/100)이 참고가 됩니다.

### 15-2. 장면 구성

장면은 **장소 배경 + 파티 스프라이트 + 적 스프라이트 + 한 줄 문구**로 조립합니다.

| 요소 | 내용 |
| --- | --- |
| 장소 배경 | 의뢰 유형별 1종 [가안: 숲, 던전, 유적, 길(호위), 동굴 5종]. 2026-11-02 프로토타입은 **숲만** 사용, 던전 · 동굴 · 유적 블록은 이번 범위에서 제외 |
| 파티 | 모험가 스프라이트, 파티원 전원. 동작은 걷기 · 달리기 · 공격 · 쓰러짐(도트 시트 `art_source/pixel_chr/`). **대기 동작은 만들지 않음** |
| 피격 | 새로 그리지 않고 **캐릭터 전체를 붉게 깜빡임**(코드) |
| 적 | 의뢰에 나오는 몬스터. 의뢰 데이터의 `enemy_ids`를 읽음. 처음엔 **네모 상자 + 이름**, 이후 몬스터 도트 그림(15-8절) |
| 문구 | 장면 하단 한 줄. 예: "고블린 소굴 입구에 도착", "고블린 무리와 조우!" |

- 이후(2026-11-14~16) 미니 뷰 모험가 · 몬스터는 SD 모션과 의뢰 종류별 배경으로 바뀌었습니다. 그림 · 모션 기록은 옮기지 않고 링크만 둡니다: [../../handoff_2026-11-16.md](../../handoff_2026-11-16.md) · [../../art/sd_motion_workflow.md](../../art/sd_motion_workflow.md) · [../../art/sd_sprite_motion_list.md](../../art/sd_sprite_motion_list.md) · [../../reports/밤사이_작업3_보고_2026-11-16.md](../../reports/밤사이_작업3_보고_2026-11-16.md).

> 출처: expedition_panel.md §11.2 · §12

### 15-3. 진행도에 따른 장면 전환

장면은 원정의 **진행 바(진행도)** 에 따라 단계가 바뀌고, 단계 안에서는 동작을 반복 재생합니다.

| 구간 | 진행률 | 내용 | 문구 예시 |
| --- | --- | --- | --- |
| 이동 | 0~30% | 파티가 장소로 이동(배경이 흐름) | "숲길을 따라 이동 중" |
| 조우 | 30~34% (전투) / 30~50% (비전투) | 적을 발견, 전투는 즉시 교전. 비전투는 "목적지에 도착했다" | "고블린 무리와 조우!" |
| 교전 · 수행 | 34~85% (전투) / 50~85% (비전투) | 전투 로그 재생, 비전투는 수집 게이지 상승 | "고블린과 교전 중" |
| 결과 | 85~100% | 승리 · 후퇴 연출. 성공 · 실패는 **출발 시점에 이미 정해진 결과**를 보여 줌 | "의뢰 성공!" |
| 귀환 | 귀환 | 원정이 끝나면 미니 뷰가 자동으로 닫힘 | "길드로 귀환" |

> ⚠️ 출처 차이: expedition_panel.md §11.3 · §15 · quest_combat.md §6(2026-11-03)은 조우 30~50%, 교전 50~85%라 하고, game_overview.md §9(2026-11-12)는 조우 30~34%(전투) / 30~50%(비전투), 교전 · 수행 34~85% → 최신인 game_overview 쪽을 따름.

- 의뢰 유형별 "수행" 동작: 토벌 = 전투, 사냥 · 채집 = 채집 · 사냥, 조사 = 유물 조사, 호위 · 구호 = 호위 · 치료, 탐사 = 탐색 · 함정 해제.
- 성공 · 실패 판정은 **미니 뷰가 열리는 시점과 무관하게** 출발할 때 정해진 값을 쓰므로, 뷰를 열고 닫는 것이 결과에 영향을 주지 않습니다(보기 전용 원칙).
- 사망은 직접적 묘사 없이 "쓰러짐" 포즈와 문구("○○이(가) 돌아오지 못했다")로 표현합니다. 수위 기준은 기존 사망 연출 규칙(기획서 8장, → [01_모험가.md](01_모험가.md))을 따릅니다.

> 출처: expedition_panel.md §11.3 · §15 · quest_combat.md §6 · game_overview.md §9

### 15-4. 전투 재생 (교전 구간)

미리보기(`prototype/tools/expedition_preview.html`)가 가짜 데이터 대신 **실제 게임 데이터(F·E급 의뢰 · 몬스터 수치)와 전투 계산(combat.js)** 으로 원정을 만들고, 교전 구간에 전투 기록을 그대로 재생합니다.

| 항목 | 내용 |
| --- | --- |
| 재생 구간 | 교전 구간. 라운드를 같은 길이로 나누고 라운드 안의 행동을 고르게 배치 |
| 적 | 실제 체력 기준 게이지(빨강 → 주황 → 노랑). 맞으면 붉은 깜빡임, 치명타는 밝은(큰) 깜빡임, 체력 0이면 사라짐. 같은 이름은 첫 마리에만 이름. 보스는 크기 배율(140%)만큼 큼. 오른쪽 끝을 넘으면 겹쳐서 줄임 |
| 모험가 | 교전 · 결과 때 머리 위 작은 게이지. 맞으면 붉게, 회피는 살짝 뒤로 비킴, 물약 · 성직자 회복은 초록 반짝임, 쓰러지면 그 자리에 쓰러짐. 앞줄(전사 · 도적)이 맨 앞 |
| 모험가 머리 위 막대 (2026-11-12 현황) | 다음 공격까지의 게이지(노랑), 체력(빨강), 마력(파랑) 막대가 같은 높이(4px). 막대 길이는 몬스터와 같음 |
| 결과 | 성공: 쓰러진 사람은 남고 나머지는 오른쪽으로 떠남(승리 동작 없음), 문구 "의뢰 성공! (○○는 부상)". 실패: 다치거나 죽은 사람만 쓰러지고 나머지는 후퇴(왼쪽 = 길드 방향으로 달림) / 전멸 "전원 쓰러졌다…" / 쓰러진 사람 없이 후퇴선에 걸리면 "더 버티기 어렵다… 후퇴!" |
| 비전투 | 조우 단계 "목적지에 도착했다", 수행 단계는 파티가 멈춰 서고 땅에서 노란 반짝임 + "채집 중… / 조사 중… / 탐사 중…"(유형별), 수집 게이지 상승. 실패하면 쓰러지지 않고 걸어서 왼쪽으로 "성과 없이 돌아갑니다…" |
| 피해 숫자 | game_overview.md §9 현황: 전투 로그 재생에 피해 숫자 표시 (아래 출처 차이) |
| 미리보기 조작 | 의뢰(무작위 · 전투 · 비전투), 결과(자연스럽게 · 성공 · 실패 · 성공+부상)를 골라 보내기. 처음에는 전투 성공 · 전투 실패 · 비전투 · 성공+부상 4건 |

- 전투 기록은 게임이 출발할 때 계산해 `s.active[].fight`에 저장해 두므로, 게임 화면의 미니 뷰가 이 재생 코드를 그대로 씁니다 (기록 형식 → [03_전투.md](03_전투.md)).
- 처음 설계(§12) 때의 적 체력 게이지: 적 상자 위 40×5 막대. 빨강(>50%) → 주황(25~50%) → 노랑(≤25%). 교전 동안 줄어듦: 성공 시 12~22%까지 → 결과에서 0 후 사라짐, 실패 시 50~65%에서 멈춤. 이 진행도 연출용 값은 §15에서 실제 체력 기준 게이지로 바뀜.

### 15-5. 시간 · 배속 연동

- 장면의 동작 속도는 **배속**을 따릅니다(1× · 2× · 4×). 일시정지하면 장면도 멈춥니다.
- 단계 전환은 **진행도**가 기준이므로, 4배속에서 단계가 매우 빠르게 지나갈 수 있습니다. 한 단계 최소 표시 시간을 0.5초로 둡니다 [가안].
- 마을 화면은 시간이 정지하므로 미니 뷰는 길드 화면에서만 사용합니다 (마을 화면에서는 패널 · 미니 뷰 숨김).

**저장 데이터 규칙**
- 화면 배치처럼 플레이와 무관한 값은 저장 데이터의 `ui` 묶음에 모읍니다.

- 위치를 옮기면 `s.ui.expView`가 바로 바뀌고, 다음 저장(수동 저장 · 매달 자동 저장) 때 기록됩니다.

### 18-1. 침공 화면 (마을 화면, `js/invasion.js`)

규칙 · 적 구성은 → [03_전투.md](03_전투.md) 14장. 아래는 원본 raid_invasion_v2.md §12-1을 그대로 옮긴 것입니다.

- 차례마다: 모험가가 길드 앞에서 다리 앞으로 뛰어나감 → 늑대가 다리 바깥 끝에서 건너옴 → 전투 기록(라운드마다 0.42초)을 그대로 재생(공격 모션 · 데미지 숫자 · 치명타 노랑 · 회복/물약 초록 · 쓰러짐 · 체력 막대).
- 전멸: "모험가가 모두 쓰러졌습니다!" → 남은 적이 왼쪽 길을 따라 영주의 성으로 → 성 오른쪽에 "영주의 성 N%" 게이지가 깎이는 동안 쓰러진 모험가 머리 위에 "일어나기까지 N초" → 일어나 성의 왼쪽 아래 면 앞에서 싸움. 또 지면 게이지 0 · 연기 → 결과 창.
- 차례 사이 정비 창: 모험가마다 체력 막대(정비로 +30% · 쓰러진 사람은 40%로 일어남), **물약 사기**(1개 20G, 금고에서, 한 사람 3개까지, 체력이 떨어지면 스스로 마심), 다음 적 이름 · 수. 장부 지출 "침공 대비 물약" 줄.
- 결과 창: 승리 = E급 승급 · 1,000G · 명성 +10 · 쓰러진 인원(부상) / 패배 = 인구 −N · 신뢰도 −5 · 사망자 · 4주 뒤 재도전. 확인을 누르면 마을 화면을 닫고 시간을 되돌림(멈춰 둔 그 주의 나머지 진행).

- 등장 · 수주 화면: 리퀘스트 장 맨 위에 붉은 테두리 "메인" 카드(리나가 영주의 전갈을 전함), 카드에 지금 전력 · 예상 승률(20번 모의)과 "받기". 출발 금지 기간에는 게시판 장에 "침공 대비 — 출발 금지" 띠, 상단 정보판에 "침공까지 N주". (raid_invasion_v2.md §5 · §10)
