## 요약

- 모험가는 5개 전투 능력치(힘·민첩·지력·정신·기교)와 운용 능력치(행운), 직업 계통, 성향, 애착도로 정의되는 **자율 행동 주체**입니다. 플레이어는 직접 조작하지 못하고, 의뢰 필터·시설·선물로 성장 방향을 유도합니다.
- 직업은 **총 48개**(1차 5, 1차 종결 특수 3, 2차 15, 3차 심화 12, 3차 확장 10, 전설 3)이며, 전직은 능력치 조합으로 정해져 출신과 관계없이 같은 조합이 같은 직업으로 수렴합니다. 전직은 접수원이 제안하고 길드 마스터가 승인하며, 모험가는 애착도에 따라 수락하거나 거절합니다.
- 레벨은 성장의 엔진이고 직업은 방향입니다. 전직해야 레벨 상한이 풀리고, 가진 스킬이 새 직업의 형태로 진화합니다(스킬 82개).
- 모험가 등급(F~S)은 레벨과 실적으로 오르는 공식 자격이며, 승급하면 능력치 5개에 각각 +3~+10의 보너스를 받습니다. 모험가 등급 상한은 길드 등급 + 1입니다(2026-11-12).
- 성향(위험·소비·사교 3축 × 3단계 + 선호 의뢰)이 의뢰 선택·소비·파티 결성을 정하고, 애착도(0~100)가 방문 빈도·거주·전직 수락을 정합니다.
- 모험가는 의뢰 실패나 전투 후 판정으로 사망할 수 있고, 6개월 뒤 "○○ 2세"가 유품과 스킬 1개를 물려받아 등장합니다.
- [제안] 몸 상태(배고픔·피로도), 칭호, 모험가끼리 대화(관계 수치)는 2026-11-13 설계 문서로 제안된 상태이며, 대화의 로비 잡담·파티·미니 뷰 대사는 반영되었습니다.

## 1. 행동 구조

방문 → 퀘스트 수주 → 정비 → 퀘스트 실행 → 달성/실패 → 방문 후 보상

**설계 원칙** (모험가 관련)

- 육성은 경영의 일부입니다. 플레이어는 모험가를 직접 조작하지 않고, 투자와 방침으로 성장 환경을 만듭니다.
- 모험가는 스스로 판단합니다. 의뢰 선택, 장비 구매, 훈련 종목, 파티 결성은 모험가가 결정합니다.

모험가는 5개 능력치와 직업 계통, 성향, 애착도로 정의되는 자율 행동 주체입니다. 플레이어는 모험가를 직접 조작하지 못하고, 의뢰 필터·시설·선물로 성장 방향을 유도합니다.

> 출처: design_v0.1.md §1 설계 원칙 · §7.1 · game_overview.md §3

## 2. 직업 (총 48개)

전직은 능력치 조합으로 정해지며, 같은 조합은 출신 직업과 관계없이 같은 직업으로 수렴합니다. 레퍼런스는 창세기전3이고, 살릴 재미는 '경로를 짜는 계획'과 '최종직에 도달하는 성취감'입니다.

| 단계 | 수 | 규칙 |
| --- | --- | --- |
| 1차 (기본) | 5 | 전사, 궁수, 마법사, 성직자, 도적. 모두 전직 가능 |
| 1차 종결 (특수) | 3 | 희귀하게 등장. 전직 없음, 전투 외 고유 능력 (짐꾼·상인·정보꾼) |
| 2차 | 15 | 능력치 2개 조합. 물리 특화 3개는 2차 종결, 신비 특화 2개는 3차로 이어짐 |

| 3차 확장 | 10 | 능력치 3개 조합 (수렴) |

## 4. 레벨과 스킬

레벨은 성장의 엔진이고, 직업은 그 방향을 정합니다. 전직해야 레벨 상한이 풀리고, 가진 스킬이 새 직업의 형태로 진화합니다.

### 4.1 레벨

| 항목 | 내용 |
| --- | --- |
| 레벨 상한 | 50 [가안] |
| 단계별 상한 | 1차 30, 2차 40, 2차 종결·3차·특수 직업 50 |

## 6. 모험가 등급과 승급 보너스

모험가 등급(F~S)은 길드가 인정하는 공식 자격이며, 레벨(경험의 양)과 실적(도전의 질)을 모두 채워야 오릅니다. 직업 단계와는 별개입니다.

| 승급 | 최소 레벨 [가안] | 실적 조건 [가안] | 능력치 보너스 (5개 각각) |
| --- | --- | --- | --- |
| F → E | Lv 5 | E등급 의뢰 5회 성공 | +3 |
| E → D | Lv 10 | D등급 의뢰 5회 성공 | +4 |
| D → C | Lv 18 | C등급 의뢰 7회 성공 | +5 |
| C → B | Lv 26 | B등급 의뢰 7회 성공 | +6 |
| B → A | Lv 35 | A등급 의뢰 10회 성공 | +8 |
| A → S | Lv 45 | S등급 의뢰 10회 성공 | +10 |

- 2026-11-12: **승급 보너스** = 능력치 5개에 각각 고정값(`growth.gradeStat`, 정수). **모험가 등급 상한 = 길드 등급 + 1**(F급 길드에서도 E급까지, S급은 길드 S 승급 순간만). 승급하면 축하 카드(초상·능력치 +N·리나 한마디, 같은 주는 한 장에 묶음). 1년 차 첫 승급 중앙 11주차, 1년 평균 7.4회(게임 100판)

| 항목 | 내용 |
| --- | --- |
| 상한 (우리 길드 출신) | **길드 등급 + 1** (2026-11-12). 조건을 채워도 상한에 걸리면 길드가 승급할 때까지 대기 |
| 상한 (외부에서 온 모험가) | 다른 길드가 인정한 등급 유지. 길드 등급 +2단계까지만 방문. 희귀하게 등장하고, 우리 길드에서의 추가 승급은 길드가 따라잡아야 가능 |
| 강등 | 없음 [가안] |
| 승급 처리 | 조건을 채우면 접수원이 알리고 자동 승급 [가안] |
| 2세 | Lv 1, F급부터 다시 시작 (11절 참고) |

> ⚠️ 출처 차이: design_v0.1.md §7.3 상한 표는 "상한 (우리 길드 출신) = 길드 등급까지. 조건을 채워도 길드가 승급할 때까지 대기"이고, 같은 절의 2026-11-12 메모와 game_overview.md 갱신 기록(2026-11-12)은 "모험가 등급 상한 = 길드 등급 + 1"입니다 → 최신인 2026-11-12 결정(길드 등급 + 1)을 따름.

- 승급 축하 카드의 화면 구성은 (→ [10_UI.md](10_UI.md)). 길드 등급과 승급 흐름은 (→ [08_길드승급.md](08_길드승급.md)).

## 9. 성향

성향은 축 3개 × 3단계 + 선호 의뢰 유형으로, 모험가가 스스로 내리는 판단(의뢰 선택, 소비, 파티 결성)을 정합니다. 수치는 모두 [가안]이며 시뮬레이터로 검증합니다.

| 축 | 단계 | 영향 |
| --- | --- | --- |
| 위험 (화면 이름: 모험심) | 신중 / 보통 / 무모 | 고르는 의뢰 등급(자기 등급 −1~0 / −1~+1 / 0~+2), 수주 기준(70% / 55% / 35%), 실패 시 사망 확률(×0.5 / ×1.0 / ×1.5) |
| 소비 | 절약 / 보통 / 낭비 | 예비금(장비 가격의 2배 / 1배 / 0.3배), 식당 이용(30% / 60% / 90%), 물약 구매량, 보상 가중치(×0.8 / ×1.0 / ×1.3) |
| 사교 | 독불장군 / 보통 / 사교적 | 파티 모집 기준(예상 성공률 30% / 50% / 70% 미만), 친밀도 상승(×0.5 / ×1.0 / ×1.5) |
| 선호 의뢰 | 5개 유형 중 1개 | 같은 조건이면 먼저 고름 |

- "위험" 축의 화면 이름은 **모험심**입니다(내부 이름 risk는 그대로).
- **물약 최대 소지 수** = 소비 성향(절약 1 · 보통 2 · 낭비 3). 초과 칸은 잠급니다.
- **장비 구매 기준** = 세트 가격(무기 가격 × 3) × (1 + 소비 성향 여유분 × 0.5). E급 예: 900G × 절약 2 · 보통 1.5 · 낭비 1.15 → 1,800 · 1,350 · 1,035G. 길드 등급 때문에 더 살 장비가 없으면 "길드 등급 상한". 장비 가격은 (→ [04_아이템.md](04_아이템.md)).
- 전투의 후퇴선은 위험 성향에 따라 신중 50% / 보통 30% / 무모 10%이고, 출발 기준은 0.95 / 0.85 / 0.65입니다 (→ [03_전투.md](03_전투.md)).
- 지명 퀘스트 수락 확률의 위험 보정은 (→ [02_의뢰.md](02_의뢰.md)).

> 출처: design_v0.1.md §7.6-1 · popup_advs.md §3 · §6 · game_overview.md §5(링크)

### 9.1 예상 성공률과 의뢰 선택

- 예상 성공률 = 실제 성공률 × 인식 계수(신중 0.9 / 보통 1.0 / 무모 1.2) ± 오차 10%p (정보실 레벨당 2%p 감소)
- 판단 순서: 점수가 가장 높은 의뢰서 → 예상 성공률이 파티 모집 기준 미만이면 주점에서 모집(최대 2주) → 모집 실패 시 수주 기준 이상이면 솔로 수주 → 아니면 다른 의뢰나 휴식
- 실제 성공률의 등급 기준치: F 15, E 25, D 35, C 45, B 60, A 75, S 90 (요구 총량 = 기준치 × 요구 능력치 수 × 0.85~1.15)

> 출처: design_v0.1.md §7.6-1

## 13. 칭호 [제안]

> 상태: **제안 (결정 전, 코드 반영 안 함)** — 화면 자리만 책 조절 도구(`prototype/tools/book_layout_editor.html` 모험가 장)에 견본으로 잡아 둠. 출발점: 사용자 결정 (2026-11-13).

- **조건을 달성한 칭호만 고를 수 있고, 플레이어가 모험가마다 1개를 붙인다.** 같은 칭호를 여러 모험가가 붙일 수 있다.
- **기본 칭호 "신입":** 처음부터 모두 가지고, 다른 칭호를 붙이지 않으면 신입 (2026-11-13 결정).
- **효과는 능력치 보조**(+1 ~ +3). 칭호 이름은 **4글자 이하**.
- 측정: 모든 모험가가 1년 내내 칭호를 붙였다고 쳐도(상한 가정) 관문 1 수입 **+0 ~ +4G**, 성공률 **+0.2 ~ +0.9%p** → 영향 작음. 단, 성공률이 이미 상한(95%) 근처라 주 능력치 +3을 모두에게 주면 95.4%로 기준을 살짝 넘음 → **주 능력치형은 +2까지** 추천.

> 출처: titles_v1.md 머리 · 요약

### 13.1 사용자 결정 (2026-11-13, 받아 적은 그대로)

1. 한 모험가가 붙이는 칭호는 **1개**
2. 칭호는 **플레이어가** 골라 붙임
3. 이름은 **최대 4글자**
4. 효과가 있으면 좋음 → 가능한지 확인 (→ 가능, 13.2)
5. 얻는 방법: "의뢰 N회 성공, 대회 우승, 애착 단계" 같은 방식이 맞음 → 설계 필요 (→ 13.3)

7. 효과는 **능력치 보조**
8. 시스템 설계는 문서로 따로, 화면은 견본 칭호로 자리만
9. **칭호가 없으면 모두 "신입"** (기본 칭호, 효과 없음. 다른 칭호를 떼면 다시 신입)

### 14.2 대화가 생기는 곳 · 때

| # | 상황 (`talk.csv` 상황 이름) | 곳 | 누가 | 언제 | 빈도 (안) |
| --- | --- | --- | --- | --- | --- |
| 1 | `table` 식탁 잡담 | 로비 | 같은 테이블에 앉은 두 사람 | 식사 · 술 중 | 앉아 있는 동안 1번 |
| 2 | `board` 게시판 앞 | 로비 | 게시판 앞에 함께 선 두 사람 | 의뢰 고르는 중 | 25% |

- **손님이 많은 장면 우선순위:** 리나 응대 · 승급 · 레벨업 말풍선이 있으면 대화는 미룸.

### 14.3 대사 표 구조: `prototype/data/talk.csv`

```
상황,역할,말투,관계,대사,메모
table,open,bold,,오늘 사냥감 봤어? 내가 다 잡을 거야!,
table,reply,careful,,…조심해. 저번에 다쳤잖아.,
table,close,any,,(둘 다 웃는다),맺음 (생략 가능)
```

| 열 | 값 | 설명 |
| --- | --- | --- |
| 상황 | table · board · idle · depart · return_ok · return_fail · battle_start · battle_hit · battle_heal · battle_win · battle_lose · town | 14.2 표 |
| 역할 | open(말 걸기) · reply(대답) · close(맺음, 선택) | 대화 = open + reply (+ close) |
| 말투 | bold · careful · friendly · loner · plain · any | 말하는 사람의 말투 |
| 관계 | 비움 · good · bad | ⑤ 관계 수치 단계. 비우면 모든 관계 |
| 대사 | `{a}` 말 건 사람 이름, `{b}` 대답하는 사람 이름, `{q}` 의뢰 이름 | |

- **조합 규칙:** open은 A의 말투에서, reply는 B의 말투에서 고름 → 호탕 A + 무뚝뚝 B면 "같이 가자!" / "…알아서 해." 처럼 말투 차이가 대화에서 드러남.
- **줄 수 (안):** 상황 12 × 말투 5 × open · reply 2 × 2~3줄 ≈ **240~360줄** 중 우선 로비 3상황(②)부터 **90줄**.
- **대사 쓰기:** Claude가 초안 → 사용자가 대사 편집 도구로 고침. 지금 편집기는 `prototype/tools/talk_editor.html`(모험가 대화 편집기)이고, 저장 후 `data_build.py`로 `data_gen.js`를 만듭니다.
- 지명 퀘스트 수락·거절 말풍선(`speech.csv` 상황 `nominate_ok` · `nominate_no`)은 (→ [02_의뢰.md](02_의뢰.md)).

> ⚠️ 출처 차이: character_talk_v1.md §1(요약)은 "상황 6 × 말투 5 × 역할 2~3 × 3줄 ≈ 180~270줄"이고, 같은 문서 §3은 "상황 12 × … ≈ 240~360줄", §6-2(반영)는 실제로 280줄입니다. 상황 수가 7곳(§2)을 이벤트별로 나눠 12가지(§3)가 된 차이이며, 실제 반영은 280줄입니다.
