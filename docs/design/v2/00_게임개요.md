## 요약

- 플레이어는 길드 마스터가 되어 모험가를 직접 조작하지 않고 환경과 방침으로 키우는 **실시간 경영 시뮬레이션 + 육성** 게임입니다. 최종 목표는 마왕을 무찌르는 모험가 파티가 길드에서 나오는 것입니다.
- 게임은 **주 단위**로 흐릅니다. 한 달 = 4주, 1년 = 48주이며, 배속 없이 1주 약 30초, 1달 약 2분, 1년 약 24분입니다.
- 플레이어의 개입은 "의뢰 필터 설정 → 시설·장식 투자 → 승인·지명 결정"에 집중됩니다. 모험가는 스스로 의뢰를 고르고 출발합니다.
- 길드의 핵심 수치는 금전·명성·신뢰도·길드 등급(F~S)이고, 마을의 핵심 수치는 마을 인구입니다.
- 플랫폼은 스팀(PC) 확정이며, 지금은 빌드 도구 없이 브라우저에서 바로 열리는 웹 프로토타입(`prototype/`)으로 만들고 있습니다. 프로토타입 범위는 F급 시작부터 첫 전직까지 약 1년(게임 내)입니다.
- 첫 엔딩 10~15시간, 부가 요소 포함 25~40시간, 게임 내 기간은 첫 엔딩까지 약 15년 [가안]입니다.

## 1. 콘셉트

이 게임은 플레이어가 길드 마스터가 되어 모험가를 직접 조작하지 않고 환경과 방침으로 키우는 실시간 경영 시뮬레이션입니다. 최종 목표는 마왕을 무찌르는 모험가 파티가 길드에서 나오는 것입니다.

| 항목 | 내용 |
| --- | --- |
| 장르 | 실시간 경영 시뮬레이션 + 육성 요소 |
| 플레이어 | 길드 마스터. 직접 싸우지 않고, 환경과 방침을 정해 간접적으로 운영 |
| 길드 | 플레이어가 시뮬레이션을 하는 공간 |
| 최종 목표 | 마왕을 무찌르는 모험가 파티가 등장하는 것 |
| 비주얼 | 일러스트풍 (HD-2D 분위기의 마을·길드 배경 + 도트 SD 캐릭터) (→ [11_비주얼_사운드.md](11_비주얼_사운드.md)) |
| 플레이 타임 | 첫 엔딩 10~15시간, 부가 요소 포함 25~40시간 |
| 게임 내 기간 | 첫 엔딩까지 약 15년 [가안] |
| 세계관 규칙 | 화약이 없는 세계. 무기는 검, 창, 활, 지팡이, 맨손 등 (→ [09_스토리_세계관.md](09_스토리_세계관.md)) |

**설계 원칙**

1. 육성은 경영의 일부입니다. 플레이어는 모험가를 직접 조작하지 않고, 투자와 방침으로 성장 환경을 만듭니다.
2. 모험가는 스스로 판단합니다. 의뢰 선택, 장비 구매, 훈련 종목, 파티 결성은 모험가가 결정합니다.

**프로토타입 범위:** 현재 웹 프로토타입(`prototype/`)은 F급에서 시작해 첫 전직까지 약 1년(게임 내)을 다루고, 마을 건물·효과는 E급까지를 범위로 봅니다. 프롤로그 영상(약 101.6초)은 확정되어 새 게임 시작 때 재생됩니다. (→ [10_UI.md](10_UI.md) 화면 흐름)

> 출처: design_v0.1.md §1 · game_overview.md §1

## 2. 핵심 게임 루프

게임은 주 단위로 흐르며, 플레이어의 개입은 "의뢰 필터 설정 → 시설·장식 투자 → 승인·지명 결정"에 집중됩니다. 모험가는 스스로 의뢰를 고르고 출발하며, 결과는 미니 뷰와 보고로 확인합니다. (수치 출처: [../../balance/progression_v1.md](../../balance/progression_v1.md), [../../balance/economy_v1.md](../../balance/economy_v1.md), 2026-11-09)

| 단계 | 내용 |
| --- | --- |
| 1. 의뢰 유입 | 한 달 5건(2026-11-12, 10 → 5)을 4주로 나눠 매주 게시. 게시 후 4주가 지나면 만료. 신뢰도 5단계에 따라 의뢰 수·보상·경험치 변동 (→ [02_의뢰.md](02_의뢰.md)) |
| 2. 게시·필터 | 게시판 칸을 등급별로 배분해 육성 전략을 정함 |
| 3. 모험가 수주 | 모험가가 성향에 맞춰 직접 고름 (필요 시 주점에서 파티 모집) (→ [01_모험가.md](01_모험가.md)) |
| 4. 수행 | 출발 → 이동 → 조우·전투(또는 수집) → 결과. 미니 뷰에서 진행 관찰 (→ [03_전투.md](03_전투.md)) |
| 5. 정산 | 성공 시 보상·경험치·능력치·명성 상승, 실패 시 명성 하락(사망 확률 판정) |
| 6. 월간 보고 | 접수원이 수입·지출·전직 제안 등을 보고. 보조금은 반기마다 지급 (→ [07_경제.md](07_경제.md)) |

### 2-1. 진행 흐름 (새 게임 기준)

1. 튜토리얼(시간 멈춤, 모험가 2명)
2. F급 운영: 매주 의뢰 게시, 명성 10마다 모험가 1명 합류
3. 리퀘스트(서브 퀘스트) 8번 들어주기 (2026-11-16, 메인 등장 중앙값 32주)
4. F급 메인 퀘스트 「다리를 지켜라」 등장 → 받으면 2주 뒤 침공 (클리어 중앙값 40주)
5. E급 승급, 관리소 해금 후 2,000G로 건설 (→ [08_길드승급.md](08_길드승급.md))

> ⚠️ 출처 차이: game_overview.md §2(2026-11-09)는 "첫 모험가가 2차 전직 조건 충족(약 41주) → F급 메인 퀘스트 등장: 지명 튜토리얼, 1주 전투", 같은 문서 갱신 기록과 raid_invasion_v2.md(2026-11-16)는 "리퀘스트 8회 → 침공" → 최신을 따름. 시작 조건도 2026-11-16부터 시작 금고 500G · 시작 모험가 2명(창립 멤버).
6. 다음 달 초 첫 전직 제안 (약 48주)

### 2-2. 목표 수치 (시험용 게임 30~40판 기준)

| 지표 | 결과 |
| --- | --- |
| 튜토리얼 뒤 첫 2차 전직 제안 | 중앙값 48주 (하위 20% 40주 ~ 상위 20% 60주) |
| 1년 뒤 모험가 수 | 약 8명 |
| 첫 전직 시점 | 의뢰 약 15건 성공, 평균 Lv 14.9, 주 능력치 50.3 |
| 첫해 경제 | 월 순이익 약 545G |

단, progression_v1의 내용은 시험용 게임에서 검증한 가안이며, 정식 코드에는 메인 퀘스트·튜토리얼 구현 때 한꺼번에 반영할 예정입니다.

| 길드 마스터 | 플레이어 |

## 7. 기술·제작 환경

프로토타입은 빌드 도구 없이 브라우저에서 바로 열리는 웹 게임이고, 규칙 수치는 데이터 파일로 분리해 시뮬레이터와 같은 계산을 쓰도록 맞춘다는 원칙입니다. 모든 수치는 설정값으로 분리하고, 시뮬레이션 결과에 따라 조정합니다.

### 7-1. 프로젝트 구조

| 위치 | 역할 |
| --- | --- |
| `prototype/index.html`, `js/`, `css/` | 게임 본체 (HTML UI 층 + 1920×1080 캔버스, 비율 유지 축소) |
| `prototype/js/game_core.js` | 게임 규칙·상태(주 진행, 저장 직렬화) |
| `prototype/js/combat.js` | 전투 엔진 |
| `prototype/js/ui.js`, `main.js`, `expedition.js`, `town.js`, `actors.js` | 팝업·HUD / 부트·저장·타이틀 흐름 / 미니 뷰 / 마을 / 쿼터뷰 캐릭터 |
| `data/collegium_data.json`, `data/balance.csv` | 몬스터·의뢰·소재·장비 데이터 및 설정값(스키마 `tools/balance_schema.json`), `tools/data_build.py`로 `js/data_gen.js` 생성 |

### 7-1-1. 웹 시연 준비 (2026-11-16)

| 목록 | `prototype/js/manifest.js` |

### 7-4. 에셋 제작 방식

1. 아트는 GPT(ChatGPT)·Gemini로 생성합니다. 한 번에 한 시트씩, 단색 마젠타 또는 투명 배경으로 받아 크로마키로 투명 처리하고 크기·정렬을 검증합니다.
2. 요청문은 보내기 전에 사용자에게 보여 주고 허락을 받습니다. 사용자가 생성 결과를 다운로드 폴더에 저장하면 가져와 알파로 자르고 256px 등으로 맞추며, 원본 시트는 `art_source/`에 보관합니다.
3. 최종 에셋은 용량을 최적화(WebP/PNG)해 `prototype/assets/` 아래에 둡니다. 도트 SD 캐릭터·타이틀 규격은 `docs/art/pixel_spec.md`에 있습니다.
4. 인게임 에셋 교체는 논의 시안을 보여 준 뒤 사용자가 "반영해줘"라고 할 때만 프로젝트에 씁니다.

### 7-5. 협업 규칙 (working_rules.md 요약)

- 종결어는 격식체 한국어, 결론 먼저·근거 2~3가지·숫자 포함, 답변이 길면 요약 먼저입니다.
- 작업이 2분을 넘기면 사유를 알리고, 토큰이 많이 드는 작업은 착수 전 규모를 알리고 확인받습니다.
- 커밋·푸시는 사용자가 GitHub Desktop으로 직접 하고, Claude는 한국어 커밋 요약을 제공합니다.
- 새 요청·결정은 그 자리에서 `docs/todo.md`에 먼저 기록합니다(2026-11-11 추가).
