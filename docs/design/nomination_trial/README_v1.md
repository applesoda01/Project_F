# 지명 퀘스트 시험판 (밤사이 작업 3 E, 2026-11-16)

결정(nomination_v1.md 7장)대로 작업 공간 게임 사본에 만듦. 게임 저장소는 그대로.
- 화면: 왼쪽 위 **📜 지명 (시험)** 버튼 → 지명 의뢰 3건 · 모험가 목록(조건 능력치 · 애착 · 수락 % · 상태) → 이름 클릭 = 바로 수락/거절(말풍선 한 줄) → [보내기] = 다음 주 게시판보다 먼저 출발. 화면 `shot_1~4.png`
- 규칙(`game_core.js`): `launchParty`(게시판 출발 처리를 함수로 뺌, 결과 같음) · `nomEnsure / nomList / nominate / nomSend / nomLaunch / nomReturn`. 보상은 게시판과 같은 코드(모험가 몫 · 애착 +2). 대열은 직업 순 자동.
- 측정 `measure.json` (100판 · 1년, 16주부터 6주마다 3건을 열고 수락 확률 높은 순으로 지명)

| 조건 | 1건당 지명 가능(평균) | 보낼 수 있었던 비율 | 지명 의뢰 성공/실패 | 첫해 월 순이익 | 전체 성공률 |
| --- | ---: | ---: | --- | ---: | ---: |
| 지명 없음 | — | — | — | 482G | 94.6% |
| 퀘스트별 능력치 ≥ 15 | 1.1~1.6명 | 26% | 419 / 27 | 500G | 94.1% |
| 퀘스트별 능력치 ≥ 18 | 1.0명 | 21% | 359 / 10 | 499G | 94.5% |
| 퀘스트별 능력치 ≥ 22 | 0.7~1.0명 | 20% | 343 / 9 | 497G | 94.8% |

- **발견:** "힘 18 이상"처럼 능력치 하나를 고르면 그 능력치를 주력으로 쓰는 한 직업만 조건을 채워서(시작 주력 15, 나머지 6) 1건당 **1명 안팎**만 지명할 수 있습니다. 2~3명 퀘스트는 80% 가까이 못 보냅니다.
- 선택지: ① 조건을 "주력 능력치 ≥ N"(직업 무관)으로 ② 조건은 "파티 중 1명만" 채우면 되게 ③ 1인 퀘스트 위주로 설계. 주력 능력치 방식은 인원이 충분하지만, 맞지 않는 직업이 섞여 지명 의뢰 실패가 늘어납니다(성공 53%) → 퀘스트 난이도는 따로 조정 필요.
- 반영 범위: 시험판이라 저장(직렬화) · 시뮬레이터 · 책 UI는 손대지 않음. 실제 구현은 서브 퀘스트 데이터 표와 함께.
