## 요약
- **지명 퀘스트 = 집무실에서 마스터가 직접 모험가를 골라 보내는 퀘스트.** 메인·서브가 모두 이 틀을 쓰고, 게시판 의뢰(리소스)와 전투·판정 엔진은 공유합니다. 새로 만드는 것은 "등장 → 접수 → 지명 → 수행 → 보고" 흐름과 데이터 표 1개뿐입니다.
- **서브 퀘스트 8종**을 제안합니다. 그중 **"기부(돈을 달라)" 퀘스트는 지명 없이 돈만 내는 퀘스트**로, 보상은 장식 설치 수 +1, 마을 인구 +20 등입니다. 1년 차 금고 과다(7,925G, 적자 달 0번) 문제의 지출처도 겸합니다.
- F급 프로토타입용 서브 퀘스트 예시 12개와 등장 빈도(월 1개 안팎)를 넣었습니다. 결정이 필요한 항목은 마지막 절에 모았습니다.

## 1. 지명 퀘스트 구조

### 1-1. 흐름

| 단계 | 내용 | 화면 |
| --- | --- | --- |
| ① 등장 | 의뢰인(주민·영주·상인·모험가)이 길드를 찾아옴 → 집무실 문에 알림 표시, 채팅 로그 "○○가 집무실에 의뢰를 맡겼습니다" | 로비 문 위 느낌표, 책 UI **리퀘스트 장** 목록 |
| ② 접수 | **서브: 수락 / 거절**, 메인: 보류만 가능(거절 없음). 수락하면 기한 시작 | 리퀘스트 장 카드 |
| ③ 지명 | 1~5명 고르기 + **대열 순서 직접 지정** (게시판 의뢰는 자동). 모험가마다 수락 확률 표시, 거절하면 성향 말풍선 | 지명 창 (모험가 명부 장 재사용) |
| ④ 수행 | 게시판 의뢰와 같은 전투·판정(`combat.js`). 기간 1~3주. 미니 뷰에 원정 표시 | 원정 중 패널 (파티 색 원 그대로) |
| ⑤ 보고 | 성공·실패 일지 또는 대사 2~3줄 + 보상 표시 | 집무실 보고 카드 |

- **집무실이 없으면** 지명 퀘스트는 등장만 하고 "집무실을 지어야 받을 수 있음"으로 잠김(이미 `popup_fac.md`에 정한 선행 조건). 단, **기부형(2-1)은 집무실 없이도** 접수대에서 처리 → 초반부터 돈 쓸 곳이 생김.
- 지명 중인 모험가는 그 기간 게시판 의뢰를 받지 않음.

### 2-1. 기부 퀘스트 (사용자 요청) 상세

**방식:** 집무실 없이도 접수대에서 "기부하기" 한 번으로 완료. 돈이 모자라면 카드에 "부족 ○G" 표시, 기한(6주) 안에 언제든 낼 수 있음.

| 보상 종류 | 정수 효과 | 가격대 (F급) | 비고 |
| --- | --- | --- | --- |
| **장식 설치 수 +1** | **장식 총 개수 상한 +1** (2026-11-13 사용자 결정. 총 개수 상한을 새로 둠, 종류마다 1개 규칙은 유지) | 600~800G | 총 개수 상한의 시작값은 결정 필요 (예: F급 4개) |
| **테이블 상한 +1세트** | F급 최대 4 → 5세트 | 500G | 식사 수입 상한이 늘어남 |
| **마을 인구 +20** | 즉시 +20 (수 주에 걸쳐 이사 오는 연출) | 300~500G | 인구 단계 진입을 앞당김 (`balance/population_v1.md` 참고) |
| **마을 인구 증가 +1/월** | 매달 인구 +1 영구 | 800G | 장기 투자형 |
| 신뢰도 +3 | 즉시 | 300G | 기한 넘긴 의뢰로 깎인 신뢰 회복용 |
| 의뢰인 대기 줄 +1명 | 접수대 줄 자리 9 → 10 | 400G | 로비가 붐빌 때 |

- **연출:** 주민 "광장 우물이 무너졌어요. 고칠 돈이 없는데…" → 기부 → 다음 달 마을 화면에 고쳐진 우물 + 인구 +20.
- **빈도:** F급 1년에 4~6개 (2~3달에 1개). 1년 차 금고 7,925G 중 **약 2,500~3,500G를 흡수** → 목표 금고 4,000~5,000G 범위(todo 6절)에 들어감 (어림값, 시뮬 확인 필요).
- 기부는 **선택**이라 안 내도 벌칙 없음(기한 넘김 신뢰도 −1만). 돈을 모으는 플레이와 쓰는 플레이가 갈리게.

## 4. 결정이 필요한 것

1. ~~"장식 설치 수 +1"의 뜻~~ → **장식 총 개수 +1로 결정 (2026-11-13)**. 남은 결정: 총 개수 상한 시작값
2. 기부형을 집무실 없이 접수대에서 처리할지 (제안: 예)
3. 서브 기한 6주 · 재도전 1회
4. 모험가 개인 퀘스트의 보상 크기 (애착 +10, 능력치 +2)
5. 전리품 장식은 "종류마다 1개" 규칙에 포함할지
6. 구현 순서: ① 데이터 표 + 기부형(지명 없음, 가장 쉬움) → ② 지명 창 + 토벌·수색 → ③ 모험가 개인·시설 요청

## 5. 보상 연동 메모: 설비 해금 (2026-11-13 사용자 결정)

> 서브 퀘스트를 구현할 때 이 연결을 같이 넣을 것. 설비 쪽 규칙 · 화면은 먼저 준비함 (반영 전 작업용 사본, 시설 장 시안).

- **규칙:** 게임 처음엔 설비 중 **테이블 2세트만** 지을 수 있음. **테이블 3 · 4세트와 장식 8종**(화분 · 게시판 장식 · 사물함 · 현수막 · 대기 벤치 · 낡은 지도 · 벽난로 · 트로피 장식장)은 **서브 퀘스트(리퀘스트) 보상**으로 하나씩 열림.
- **연결 자리 (코드):** `game_core.js` `unlockReward(s, id)` — `'table'`이면 테이블 1세트 더(최대 4), 장식 id면 그 장식 열기. 상태는 `s.unlock = { table: 2, deco: {} }`, 놓을 수 있는 수는 `capOf(s, id)`.
- **데이터 표 연결:** 1-4의 `rw_table_cap`(테이블 +1) · `rw_deco_cap`(장식) 열 → 보상 지급 때 `unlockReward` 호출. 장식은 "설치 수 +1"이 아니라 **어떤 장식을 여는지(장식 id)**로 적어야 함 → `rw_unlock`에 장식 id를 넣는 방식 추천.
- **화면:** 시설 장 왼쪽 설비 카드 — 잠긴 장식 = 흐린 그림 + 자물쇠 + "리퀘스트 보상", 테이블 = `0/2` · "3~4세트는 리퀘스트 보상". 보상을 받으면 기록에 "새 장식을 얻었습니다" 한 줄.
- **시험:** 개발 메뉴 "설비 보상 열기" = 테이블 4세트 · 장식 8종 모두 열기.
