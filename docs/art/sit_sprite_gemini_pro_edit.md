# 앉기 스프라이트 생성 방식 (Gemini Pro 편집법)

작성일: 2026-11-10 · 대상: 모험가 10종(전사/궁수/마법사/성직자/도적 × 여/남) 앉기 정지 자세

## 요약

**결론:** 서 있는 원본 그림 1장과 앉기 포즈 참고 그림 1장을 Gemini Pro에 넣고 "다리와 팔만 바꿔라"고 편집시키면, 화풍과 머리·상체 비율을 유지한 앉은 모습을 만들 수 있다. 캐릭터당 약 5분.

근거 3가지.
1. **머리 일치:** 8종의 머리 영역 평균 픽셀 차이 3.3~6.4(0~255 기준), 머리 일치 점수 0.981~0.993. 전체를 새로 그리는 방식(LoRA txt2img, LTX 영상, Gemini Flash 각도 프롬프트, GPT 전체 다시 그리기)은 체형과 선 굵기가 바뀌었다.
2. **입력이 결과를 결정한다:** 걷기 영상에서 뽑은 프레임을 입력으로 쓴 archer_f는 다리가 뭉개지고 활이 통나무로 보이는 결과가 나왔다. 원본 시트(시드 402 등)를 입력으로 바꾸자 정상 결과가 나왔다.
3. **모델이 바뀔 수 있다:** Pro 수요가 몰리면 Flash로 자동 대체된다. 8종 중 1종(rogue_f)이 대체되었고 결과는 쓸 만했으나 매번 확인해야 한다.

## 준비물과 입력 이미지 규칙

| 항목 | 규칙 |
| --- | --- |
| 이미지 1 (대상) | 원본 시트(ComfyUI 시드 선택본)에서 캐릭터만 잘라 낸 서 있는 그림. 걷기 영상 프레임은 쓰지 않음 |
| 캔버스 | 420×600 px, 흰 배경, 캐릭터 키 516 px, 아래 여백 30 px, 가운데 정렬 |
| 이미지 2 (포즈 참고) | 여전사 앉기 그림(image2_pose_sit_warrior_f.png). 포즈만 복사하도록 프롬프트에서 명시 |
| 모델 | Gemini 3.1 Pro (모드 선택에서 Pro 표시 확인) |
| 검증 도구 | sprite_norm.py(친구 제공, 안전 확인함) + 픽셀 차이 스크립트 |

원본 시트 크롭은 배경색 차이로 가장 큰 덩어리를 찾아 자르는 스크립트(mkin.py)로 만들었다. 시트 왼쪽 약 560 px 안에 캐릭터가 있고 오른쪽은 부위 조각 이미지라 제외한다.

## 실행 절차 (캐릭터 1종, 약 5분)

역할 분담: Claude는 브라우저 세팅과 전송, 사용자는 이미지 업로드와 다운로드. 이미지 업로드는 우회할 수 없다.

1. **입력 준비 (Claude):** 원본 시트에서 캐릭터를 자르고 420×600 캔버스로 정렬. 다리 분리, 소품, 배경 잡티를 눈으로 확인.
2. **새 채팅 (Claude):** 이전 대화의 오염을 막기 위해 Gemini 새 대화를 열고 프롬프트를 입력. 모드가 Pro인지 확인.
3. **업로드 (사용자):** 이미지 1(캐릭터 원본) → 이미지 2(포즈 참고) 순서. 순서가 바뀌면 결과가 달라진다.
4. **전송 (Claude):** 첨부 순서와 모드를 다시 확인한 뒤 전송. 생성 40~90초.
5. **대체 확인 (Claude):** 결과 아래에 "다른 모델이 사용되었으며"라는 안내가 있으면 Flash 대체. 자세가 정상이고 수치가 좋으면 쓰고, 아니면 재시도.
6. **다운로드 (사용자):** "원본 크기 이미지 다운로드". Downloads에 Gemini_Generated_Image_*.png로 저장(약 1700×2500 px).
7. **가져오기와 검증 (Claude):** 새로 생긴 파일 하나만 가져와 배경 제거·정렬 후 원본과 겹쳐보기, 픽셀 차이로 비교.

브라우저 자동화 메모:
- 새 채팅: `location.href='https://gemini.google.com/app'`
- 프롬프트 입력: `.ql-editor`에 focus 후 `document.execCommand('insertText', false, 텍스트)`
- 전송: `button[aria-label="메시지 보내기"]` click
- 모드 확인: aria-label에 "현재 Pro 모드 사용 중" 포함 여부. 모델 목록에서 "3.1 Pro" 선택
- 대체 감지: 페이지 텍스트에 "다른 모델이 사용되었으며" 포함 여부

## 프롬프트 템플릿

중괄호 항목만 캐릭터별로 채운다. 필수 문구(머리·비율 고정, 새 물건 금지)는 빼지 않는다.

```
Edit image 1. Keep the character EXACTLY the same: same head size and position, same face, same {eyes}, same {hair}, same 3/4 view, same dark brown line thickness, same cel shading and colors, same outfit details ({outfit}).
Only change: the legs and arms to match the pose in image 2 (sitting upright as if on an invisible chair, thighs horizontal, knees bent at 90 degrees, hands resting on the knees). Image 2 is a different character: copy only its pose, not its armor, colors, or body shape.
Do not redraw the head or hood or hair. Do not change body proportions, do not make the character taller, slimmer, or older. Do not add any weapon or new object.
Same canvas size as image 1, full body visible, not cropped, character in the same spot. Plain flat white background, no shadow, no effects, no text.
```

채울 항목은 원본 그림을 눈으로 보고 적는다. 기억에 의존해 적은 의상 설명(예: warrior_m의 머리색, 정강이 보호대)이 원본과 달랐던 사례가 있었다.

예외 처리:
- **손에 든 물건이 있는 캐릭터(cleric_m의 책):** "손을 무릎에"를 "책은 한 손으로 무릎 위에 들고, 다른 손은 무릎에 둔다"로 바꾸고 물건을 의상 목록에 포함.
- **모자가 높은 캐릭터(mage_m):** "head or hood or hair"를 "head or hat or hair"로 수정.
- **새 물건이 생기는 경우(archer_f의 활):** "Do not add any weapon or new object"를 넣었음에도 활이 추가된 사례가 있다. 원본의 활이 통나무 같은 막대 모양일 때 발생했으므로 해당 물건의 형태를 먼저 정리.
- **다리가 잡히지 않는 원본:** 원본이 아니라 걷기 프레임을 써서 생긴 문제였다. 원본 시트로 교체.
- **머리가 바뀐 경우(같은 대화에서):** `The head changed. Use image 1's head and hair exactly as they are, pixel for pixel; only redraw the legs and arms. Keep the same scale.`

## 검증과 합격 기준

```
python3 -I sprite_norm.py STAND.png SIT.png --out OUT --canvas 420x600
```

영역은 캐릭터 키 기준 위에서 0~40%(머리), 40~62%(상체), 62~100%(다리). 차이는 흰 배경에 합성한 이미지의 평균 절대차(0~255).

| 판정 항목 | 합격 기준 | 비고 |
| --- | --- | --- |
| 머리 일치 점수 | 0.93 이상 | 변별력이 낮아(모두 0.97 이상) 보조 지표 |
| 머리 차이 | 5 이하 권장, 7 이하 허용 | 실측 3.3~6.4 |
| 상체 차이 | 15 이하 | 팔 위치 변경분 포함, 실측 5.8~15.0 |
| 다리 차이 | 판정 제외 | 서기에서 앉기로 바뀐 부분이라 항상 30~40 |
| 겹쳐보기 | 눈으로 확인 | 파랑=원본, 빨강=결과, 보라=겹침. 머리가 보라이면 합격 |
| 눈으로 확인 | 필수 | 새 물건, 소품 유실, 다리 형태 등은 수치로 못 잡음 |

정정 사항: 눈 위치 기반 비교는 잡음이 커서 철회했다. 머리 일치 점수만으로 "체형 합격"이라고 판단했다가 다리가 바뀐 사례가 있었다. 수치는 보조이고 겹쳐보기와 육안 확인이 최종 판정이다.

알려진 이슈:
- 정렬용 캔버스(420×600)에서 발이나 끝자락이 잘릴 수 있다(원본 파일은 무손상). 최종 출력 캔버스는 여유를 두고 다시 잡는다.
- 의자 합성(X250, Y257, 71.2%) 시험이 아직 없어 엉덩이 높이와 망토·의자 겹침은 미확인.
- 형태가 바뀐 경우는 결과 페이지에서 눈으로 확인해 비고에 기록한다.

## 실패 사례와 교훈

| 실패 사례 | 원인 | 대응 |
| --- | --- | --- |
| 새 포즈를 생성하면 화풍이 바뀜(LoRA txt2img, LTX 영상, Gemini Flash 각도 프롬프트, GPT 전체 다시 그리기) | 전체를 새로 그리는 방식은 비율과 선 굵기를 보존하지 못함 | 원본 픽셀을 남기고 다리와 팔만 바꾸는 편집 방식, 고정 목록 프롬프트 |
| Gemini Flash는 3/4 시점을 못 유지 | 모델 능력 한계 | Pro 사용 |
| GPT는 체형이 바뀜 | 전체 재해석 | Gemini Pro로 교체, GPT는 무료 한도도 소진 |
| 걷기 프레임을 입력으로 쓴 archer_f의 다리가 늘어짐, 활이 통나무로 보임 | 영상에서 뽑은 프레임 자체가 다리를 뭉개고 활을 두꺼운 막대로 그리는 결함을 가짐 | 입력을 원본 시트로 교체, 걷기는 원본 기준으로 재생성 |
| Pro 수요 폭주로 Flash가 대신 생성 | 자동 대체(안내 문구가 결과 아래에 나옴) | 매번 대체 여부 확인, 화풍이 유지되면 수치로 판정해 쓰고 아니면 재시도 |
| 머리 일치 점수만으로 합격 판단 | 점수는 변별력이 낮고 눈 위치 비교는 잡음이 큼 | 겹쳐보기와 육안 확인을 최종 판정으로 |

핵심 교훈: **품질 문제가 생기면 프롬프트를 고치기 전에 입력 이미지를 먼저 의심한다.** archer_f는 프롬프트를 3번 수정하는 대신 입력을 교체하자 한 번에 해결되었다.
