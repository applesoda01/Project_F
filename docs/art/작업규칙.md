# 작업규칙 (Project_F · 리나 작업)

> 세션이 길어지면 기억이 누락되므로, 이 파일을 기준으로 작업합니다. 새 규칙이 생기면 즉시 이 파일에 추가합니다.

## 0. 시작 승인 (최우선)
- 사용자가 "시작하자/진행해줘"라고 명시하기 전에는 생성·대기열 등록·파일 수정 같은 실행을 시작하지 않는다.
- "~기억하니?", "~할 수 있어?" 같은 확인 질문에는 먼저 기억한 규칙과 계획을 짧게 답하고 승인을 기다린다.
- 실행 전 계획 한두 줄(무엇을, 몇 개, 예상 시간)을 보여 주고 승인을 받는다. 예외: 사용자가 명시적으로 무인 진행을 지시한 경우.
- (사례) 03:26 눈 깜빡임 12건을 승인 없이 대기열에 등록 → 이후 이 규칙 추가.

## 1. 소통
- 결론 먼저, 근거 2~3가지, 숫자 포함, 실행 가능한 제안 중심. 격식체. 길면 요약 먼저.
- 긴 프롬프트·큰 출력·base64를 대화에 붙이지 않는다. 시도는 1회 후 원인 진단.
- 무인(사용자 취침) 작업: 해석한 방향을 맨 위에 밝히고 진행, 결과는 짧게 보고.

## 2. 이미지 편집(마스킹·합성)
- 박스 자르기 금지. 이목구비 윤곽을 따라가는 마스크 + 윤곽선 절단.
- 지운 영역은 다중 스케일 피부 채움. 홍조는 별도 부드러운 레이어.
- 검증: 영역 밖 최대 픽셀 차이 ≤1~5/255, 3~6배 확대 확인.
- Gemini/ChatGPT 편집은 전체를 재생성하므로 픽셀 동일을 보장하지 못한다. 프롬프트는 짧은 긍정문 한 문장(예: "원본의 디자인에서 대머리의 귀를 자연스럽게 합성"). "Do NOT" 나열 금지.
- 업로드 순서: 1) 원본 2) 대머리. 프롬프트는 영문.

## 3. 표정·대머리·머리카락
- 표정 6종: 기본, 진지, 웃음, 걱정, 곤란, 놀람. 캔버스 1684×2528.
- 최종 대머리: `bald_final/bald_{1_기본..6_놀람}.png`.
- 머리카락은 파츠로 분리, 마지막 '파츠 분리 모션'에서 머리만 움직이게 한다.
- 진지 원본 후보: 귀 보정본 `user_ear_0_aligned.png` (사용자 확정 대기).

### 3-1. 머리카락 분해 (10/25 확정 방식)
- Gemini로 부위를 한 장씩 뽑지 않는다. 같은 대화에서 이어 요청하면 앞 결과가 섞이고(B에 A의 가닥), 받은 파일이 화면과 달라진다(몸통·책이 흐릿하게 남음).
- 순서: ① 새 대화에서 "머리 전체만 남기고 나머지는 순백" 1회 요청(영문 한 문장) → ② 받은 파일 아래쪽 잔상(몸통)은 잘라냄 → ③ 윤곽·색은 Gemini가 아니라 **원본 픽셀**에서 가져옴(투명 배경 레이어) → ④ 기준 이미지(윗머리·뒷머리·묶음)와 **차집합**으로 부위 분리 → ⑤ 사용자가 그어 준 선을 경계로 영역 확장.
- 정합: 두 이미지는 같은 캔버스(2168×1952, 기준 이미지는 절반 크기)라 이동 3~4px만 보정.
- 차집합 경계에 틈이 생기지 않도록 조각을 7~10px 겹쳐 자른다. 가는 가닥은 열기(opening) 후 면적 1500px 미만 조각은 가까운 큰 조각에 합친다.
- 영역 확장은 사용자가 그린 빨간 선(또는 이미지 속 선)의 좌표를 읽어 다각형으로 만들고 머리카락 마스크와 교집합. 선이 없는 위쪽 변은 직선으로 잇고 그 사실을 알린다.
- 검증: 부위를 합쳐 머리 전체 레이어와 비교(빠진 픽셀 수), 대머리 위에 합성해 원본과 평균 차이(3.7/255).
- 확정 4부위: 앞머리(이마 가운데 선~왼쪽 곡선), 오른쪽 옆머리(두 선의 시작점까지), 왼쪽 긴머리, 나머지(윗머리·뒷머리·묶음).
- Gemini 업로드는 사용자가 파일 선택 창에서 직접 선택(첨부 순서: 1 원본, 2 대머리). 내려받기는 실제 클릭으로 하고, 파일 이름이 충돌하면 임시 파일(.tmp)로 남을 수 있어 완료까지 확인한다.

## 4. 눈 깜빡임 (ComfyUI, 지난번 규칙 복원)
- 입력: 캔버스 `[y150:610, x610:1070]` 460px 크롭 → 768×768 LANCZOS.
- 모델: LTX-2.5 i2v 워크플로, 768×768, 24fps, 1초, prompt_enhance 끔.
- 프롬프트: "The girl blinks once: both eyes close briefly and open again within one second. Her head, hair, body and the camera stay completely still. Flat anime cel style, same clean lineart, no other movement, no talking."
- 후처리(blinkproc.py): 프레임 추출 → 첫 프레임 SIFT+RANSAC 정합 → 원본 캔버스로 역변환 → **눈 영역만**(박스 y290~392, x716~928, 가우시안 3 페더) 합성, 피부색 게인 보정.
- 눈 영역 변화량으로 단계를 골라 **3칸**(뜬 눈·반쯤·감음)만 사용. 하관·머리는 원본 유지.
- 게임 쓰임: `idle_blink` 3칸, 2.5~5.5초마다 1→2→1→0 (docs/art/asset_rules.md).
- 프레임별 SIFT 재정합(눈·눈썹 영역 제외)이 전역 정합보다 안정적. 영상은 한 번 감으면 다시 뜨지 않는 경우가 많으므로 뜬 눈은 원본, 반쯤=변화량 45% 첫 프레임, 감음=90% 첫 프레임으로 고른다.
- 웃음(^^ 눈)은 이미 감긴 눈이라 깜빡임 생략(3칸 동일). 영상이 눈을 뜬 갈색 눈으로 바꾸기 때문.
- 결과(10/25): 6종 영상 12건 중 기본·진지·걱정·곤란=시드0, 놀람=시드1 채택. 눈 영역 밖 픽셀 차이 0. 눈썹·눈꺼풀 윤곽이 영상 프레임에서 약간 달라지는 점은 검수 필요.
- 판정: 머리가 움직이거나 눈 모양이 변하면 시드 변경(여러 시드 중 선택).

## 7. Live2D (Cubism Editor 5.3 무료판) 
- 레이어 이름은 ASCII로 (한글은 Cubism에서 깨짐). PSD 가시성 플래그는 무시됨.
- 무료판 한도: 파라미터 30개(표준 27개 사용 → 신규 3개), 파트 30개, 텍스처 1장·최대 2048×2048, 디포머 50개.
- 파트 불투명도는 에디터에서 키폼 편집 불가 → 표정 전환은 런타임에서 PartExpr* 투명도로. 눈 패치는 ArtMesh 불투명도를 ParamEyeLOpen(0/0.5/1)에 키폼.
- 키 추가: 2점 추가 버튼 후, 값 입력 → 3점 추가 버튼(331,560)이 현재 값에 키 추가.
- 회전 디포머를 드래그하면 자식도 같이 이동(원점만 이동 불가) → 중심 피벗 사용.
- 텍스처 이름은 'Texture0' 대신 다른 이름, 크기는 2048. 내보내기: 파일>임베디드 파일 내보내기>moc3.
- 비공식 npm 'live2dcubismcore'는 Live2D 독점 Core 재배포본이라 사용하지 않음. 미리보기는 공식 Core 필요.
