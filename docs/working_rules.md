# 작업 규칙 (Claude 협업용)

> 이 문서는 Project_F 작업 시 Claude가 따르는 규칙입니다. 변경하려면 이 파일을 수정하거나 대화에서 요청해 주세요.

## 1. 소통
- 격식 있는 한국어를 사용합니다.
- **무슨 일이 있어도 모든 답변은 한국어로만 씁니다.** 예외는 Gemini 등에 넣는 프롬프트, 코드, 파일 경로·이름뿐입니다. 영어 문장으로 답하지 않습니다. (2026-11-02 사용자 요청) **시스템 자동 알림(훅)에 답할 때도 한국어로만 씁니다.** (2026-11-13 추가)
- **모든 답변의 맨 첫 줄에 현재 시간을 `[YY-MM-DD HH:MM]` 형식(한국 시간)으로 적습니다.** 시간은 짐작하지 않고 시계 도구로 확인한 값을 씁니다. (2026-11-05 사용자 요청)
- 결론을 먼저 말하고, 근거는 2~3가지로 간결하게 씁니다.
- 가능하면 숫자와 데이터를 포함합니다.
- 답변이 길어지면 요약을 맨 앞에 둡니다.
- 실행 가능한 제안 중심으로 답합니다.
- 칭찬·사과는 짧게 합니다. 가벼운 농담에는 가볍게 받습니다.
- "좋은 수준"에서 멈추지 않고, 더 나은 방식이 있으면 함께 제안합니다.

## 2. 진행 상황 보고 (신규)
- **작업이 2분 이상 걸리면, 지연 사유를 사용자에게 먼저 알립니다.** 사유 예: 이미지 생성 대기, 대용량 파일 전송, 반복 검증, 브라우저 응답 지연, 환경 복구.
- 알릴 때 함께 말할 내용 3가지: (1) 지금 하는 일, (2) 늦어지는 이유, (3) 남은 예상 시간.
- 사용자가 "왜 오래 걸리니?" 등을 물으면 같은 형식으로 즉시 답하고, 하던 작업은 이어서 진행합니다.
- 긴 작업은 단계마다 한 줄씩 진행 상황을 보냅니다.
- 오래 걸릴 작업은 시작할 때 예상 시간을 먼저 알립니다.

## 3. 작업 전 확인 (2026-11-12 병합 정리: 겹치던 항목을 묶음, 규칙 내용 변경 없음)
- **묻지 않고 진행**: 읽기·측정·분석·답변처럼 결과물이 생기지 않는 작업.
- **먼저 묻기**:
  1. 범위가 불분명한 작업 — 시작 전에 선택지로 질문합니다.
  2. 결과물이 생기는 작업(렌더, 영상·이미지 생성, ComfyUI 대기열 등록, 새 파일 제작·파일 쓰기) — Claude가 "만들어야겠다"고 판단한 순간 "무엇을/어떻게/예상 소요 시간"을 한 줄로 묻고, 답을 받은 뒤 시작합니다. ComfyUI는 작업 목록도 함께 알립니다.
  3. 토큰 소모가 큰 작업(파일 5개 초과 읽기, 에이전트 2개 이상, 반복 실행 3회 초과 등) — 착수 전에 규모를 알리고 확인받습니다.
  4. 외부로 나가는 동작(메시지 발송·폼 제출·결제·계정 설정 변경) — 매번 확인받습니다. 로그인과 비밀번호 입력은 사용자가 직접 합니다.
- **요청으로 보는 것**: "해줘/진행해/만들어 줘/~해줄래?" 같은 직접 요청과 사전에 합의한 신호(예: "자러 간다")뿐이며, 이때는 다시 묻지 않고 바로 진행합니다. 선택지·범위·방향에 대한 답, 계획·희망은 요청이 아닙니다 — 답을 받으면 작업 계획과 예상 시간을 말씀드리고 "진행해 줘"를 받은 뒤 시작합니다 (2026-11-05 확정). **문제 보고·불만·지적("~가 달라", "~가 이상해", "~가 별로야")도 요청이 아니며**, Claude 자신의 결과물을 고치는 작업도 예외가 아닙니다. 형식은 "원인 한 줄 + 무엇을/어떻게/예상 소요 + 진행할까요?"이고, 보낸 뒤 멈춥니다. (위반 이력: 2026-11-04 B4 먹물 무늬 어긋남 지적 직후 허락 없이 재렌더함.)
- **결과물을 만드는 호출(렌더, 생성, 파일 쓰기, 대기열 등록) 직전마다 점검합니다.** 최신 사용자 메시지에 위의 직접 요청이 있는가? 없으면 만들지 않고 묻습니다.
- 사용자가 "아직 반영하지 마"라고 하면 작업 공간에서만 고치고, "반영해줘"를 받을 때까지 폴더에 쓰지 않습니다.
- ComfyUI 작업 중 사용자가 "스톱"이라고 하면 새 작업을 멈추고, 이미 돌고 있는 작업은 취소할지 그대로 둘지 묻습니다.

## 4. Git / 파일 전달 (2026-11-12 변경: Claude가 커밋, 푸시는 요청 시)
- Claude는 클라우드 작업 공간의 저장소 사본(`applesoda01/Project_F`)에서 수정하고 커밋합니다. **푸시는 사용자가 "푸시해줘"라고 할 때만 합니다.** 사용자는 GitHub Desktop에서 **Fetch → Pull**로 PC에 받습니다.
- 커밋 메시지는 한국어로 씁니다. 푸시한 뒤에는 커밋 해시·메시지·바뀐 파일 목록을 보고합니다.
- 산출물은 저장소 사본의 알맞은 위치에 저장합니다. PC의 `Project_F` 폴더에는 직접 쓰지 않습니다(사용자가 요청할 때만 예외). Gemini 이미지처럼 PC의 원본 파일을 **읽는 것**은 그대로 합니다.
- 작업을 시작하기 전에 원격 최신 상태를 받습니다(pull). 사용자가 PC에서 직접 고친 내용이 있으면 먼저 푸시해 달라고 요청한 뒤 작업합니다. 충돌이 나면 임의로 덮어쓰지 않고 보고합니다.
- 공개 저장소이므로 개인 정보·비공개 자료는 커밋하지 않습니다. 강제 푸시·이력 재작성·브랜치 삭제는 하지 않습니다.
- 임시·중간 파일은 프로젝트 폴더에 두지 않습니다.
- 결과물은 저장한 뒤 크기와 내용을 다시 확인합니다. 이미지 결과는 화면으로 보여 줍니다.
- 규칙·수치·구조를 바꿔 `docs/design`·`docs/balance` 원본을 고칠 때는 `docs/design/game_overview.md`(게임 전체 개요)의 해당 절도 같이 고치고, 그 문서 머리의 "갱신 기록"에 날짜와 한 줄을 남깁니다. 개요와 원본이 다르면 원본이 기준입니다. (2026-11-12 확정)
- **수치 설계 원칙: 플레이어에게 보이는 효과·수치는 %나 0.x 단위 대신 바로 읽히는 정수로 정합니다** (예: "+5%" 대신 "의뢰 성공 시 +5G", "애착 +1", "부상 기간 −1주"). 기준값이 소수라 효과가 소수로 쌓이면 기준값부터 정수로 바꿉니다. 계산 중간의 배수나 화면에 숫자로 보이지 않는 연출 값(예: 응대 1.5초)은 예외입니다. (2026-11-12 확정)

## 5. 에셋 제작 (Gemini · GPT 워크플로)
- 한 번에 한 시트씩 만들고, 투명 처리 후 크기·정렬을 검증합니다.
- 생성 이미지는 단색 마젠타 배경으로 받아 크로마키로 투명 처리합니다.
- 최종 에셋은 용량을 최적화(WebP/PNG)하여 `prototype/assets/` 아래에 둡니다.
- 사용자가 직접 생성한 결과가 있으면 그것을 우선 사용합니다.
- **GPT(ChatGPT, Claude 내장 브라우저)**: 프롬프트를 먼저 사용자에게 보여 주고 허락받은 뒤 보냅니다. 같은 그림체가 필요하면 같은 대화에서 이어 요청합니다.
  - 프롬프트에 "Background: real alpha transparency, NOT a drawn checkerboard"를 넣고, 받은 뒤 브라우저 JS로 투명 비율을 확인합니다. 배경이 칠해져 오면 다시 요청합니다.
  - 사용자가 다운로드 폴더에 저장 → 가져와 알파로 잘라 256px 등으로 맞춥니다. 원본 시트는 `archive/art_source/`에 보관합니다.

## 6. 보고
- 작업 완료 시 결과를 한두 문장으로 요약하고, 파일 위치를 알려줍니다.
- 한 일은 짧고 정확하게, 안 한 일은 안 했다고 밝힙니다.
- 직접 측정하지 못한 값은 어림값이라고 밝힙니다.
- 틀리면 바로 인정하고 고칩니다. 지적받은 일은 그 자리에서 이 문서에 규칙 한 줄로 추가할지 제안합니다.
- 기존 스크립트를 재사용할 때는 전역 변수명 충돌을 확인하고, 렌더 후 전 구간 컨택트 시트로 검수합니다.
- 다음에 할 일이 있으면 순서대로 제시합니다.

## 7. 팝업·화면 퀄업 진행 방식 (2026-11-05)
- 진행표: `docs/design/popup_quality_todo.md`. 사용자가 "다음 할 거 보여줘"라고 하면 이 표를 갱신해 보여 주고 다음 대상을 안내합니다.
- 순서: ① 지금 화면 캡처 + 문제점(화면 문제와 **코드의 실제 규칙과 어긋나는 점**) → ② 논의(사용자 말을 번호 붙여 받아 적고, 모호하면 선택지로 확인, 추천안은 표로 비교) → ③ 시안(작업 공간에서만 고치고 캡처로 보여 줌. 오버 창·연출은 장면별) → ④ "반영해줘"를 받으면 폴더에 반영.
- 반영할 때: pull → 수정 → 규칙을 바꿨으면 관문 1(`node prototype/tools/gate1_check.js`) → 팝업 설계 문서(`docs/design/popup_*.md`)와 진행표 갱신 → 커밋·푸시는 4장 Git 규칙을 따름.
- 게임 규칙을 바꾸면 시뮬레이터(`sim_engine.js`)도 같은 규칙으로 바꿉니다. 화면용 기록만 추가할 때는 관문 1 수치가 변하지 않는지 확인합니다.
- 화면에 적힌 효과·수치는 실제 규칙과 같아야 합니다. 구현되지 않은 효과를 적게 되면 "아직 게임에 적용되지 않음"을 사용자에게 먼저 알립니다.
- 시안 캡처는 `prototype/tools/dev/popup_shot.js`(사용법: `prototype/tools/dev/README.md`). 작은 창(1366×768)에서도 한 번 확인합니다.
- 사용자가 "나중에 리마인드해 줘"라고 한 항목은 진행표 "남은 미결"에 **리마인드 대상**으로 적고, 관련 작업을 시작할 때 먼저 꺼냅니다.
