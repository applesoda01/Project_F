0. 문서 목적과 읽는 기준

기존 v2 기획의 자율 모험가 육성 구조를 유지하면서, 사용자가 제안한 수익·지출 구조와 자유 모험가의 정식 소속 편입을 하나의 경영 시스템으로 연결한다. 새 기능 목록만 늘리는 것이 아니라, 누가 돈을 내고 누가 보상·전리품을 소유하는지, 길드 마스터가 어떤 결정을 내리는지, 기존 구현에서 무엇을 유지하거나 변경해야 하는지까지 정의한다.

검토 대상은 00_게임개요, 01_모험가, 02_의뢰, 04_아이템, 05_길드, 06_마을, 07_경제, 08_길드승급, 10_UI의 관련 절, 현재 game_core.js의 생성·출발·정산·월결산·지명 처리, balance.csv, 첨부 「길드의 수익 구조.md」이다. 관련 절을 대조한 정적 검토이며, 전체 게임 실행·새 밸런스 시뮬레이션·플레이 테스트를 수행한 보고서는 아니다.

표기 뜻

[기존 기획] v2 또는 연결 원본의 규칙이다. 코드 반영 여부는 따로 표시한다.

0.2 결론

자유 모험가가 주축인 개방형 길드를 유지하고, 그중 일부와 정식 계약을 맺어 길드가 책임지는 핵심 전력을 확보한다.

자유 모험가는 의뢰·소재·시설 이용을 통해 길드의 활동 규모를 키운다. 정식 모험가는 정기 보수와 지원을 받는 대신 합의한 임무를 우선 수행한다. 길드가 버는 돈은 이 둘이 더 좋은 의뢰를 수행하고 마왕 토벌에 도전할 수 있는 환경에 재투자된다.

정식 계약의 가치는 더 높은 보상 배분율 하나가 아니라, 인력 가용성·지명 비용 절감·장기 계약 수행·계획적인 지원에 둔다. 모든 모험가를 정식으로 바꾸는 것이 정답이 되어서는 안 된다.

1. 유지할 정체성과 개선 목표

1.1 유지할 것

기존 게임은 직접 싸우지 않는 길드 마스터가 환경과 방침으로 모험가를 키우고, 최종적으로 마왕을 무찌를 파티를 길러 내는 게임이다. 의뢰 선택·장비 구매·훈련·파티 결성은 모험가의 자율 판단이 원칙이다. 주 단위 진행과 한 달 4주 구조도 유지한다. [S01, S02]

다음 항목은 이번 개선의 기본 전제다.

  • 메인·서브·리소스의 기존 퀘스트 3분류와 리퀘스트의 이야기·해금 역할을 유지한다.
  • 자유 모험가에게 고정 급여를 지급하지 않는다. 정식 계약 여부와 무관하게 인격·성향·개인 소지금은 남는다.
  • 마을 상점은 길드와 다른 경제 주체다. 무기·물약 판매액을 자동으로 길드 매출에 합치지 않는다.
  • F→E의 리퀘스트 8회 → 「다리를 지켜라」 침공 → E급 승급 흐름을 정식 계약의 필수 인원 조건으로 막지 않는다.
  • 현재 시작 금고 500G, 창립 모험가 2명, 시설 유지비 0을 출발점으로 삼는다. 제안된 급여·사업 비용을 과거부터 소급하지 않는다. [S03–S08, S10–S12]

1.2 개선 목표

기존 고민 개선 후 플레이어가 판단할 일
시간이 지나면 돈이 쌓이는 경향 지금 현금을 확보할지, 핵심 전력을 계약할지 선택한다.
애착이 높으면 모든 기능이 비슷하게 유리함 관계, 계약상 의무, 실제 체류 상태를 구분한다.
수익원이 있어도 돈의 출처가 불분명함 의뢰·판매·공공 지원별로 지급자와 정산을 확인한다.
모험가 육성과 길드 수익이 별개처럼 보임 지원 → 수행 능력 → 외부 수입 → 재투자가 연결된다.
시설을 많이 추가해야 경영이 늘어남 기존 게시판·판매 창구·관리소·업무 일지에 정책을 추가한다.

1.3 검토한 세 방향

방향 장점 한계 판단
A. 자유 모험가만 유지하고 단골 혜택 추가 기존 규칙 변경이 작다. 중요한 임무를 맡길 인력을 확보하는 선택이 약하다. 보조 관계 시스템으로는 유효하다.
B. 자유 모험가 + 소수 정식 계약원 자율 행동과 인재 투자·책임을 함께 살린다. 계약 비용·가용 시간·정산 구분이 필요하다. 추천안.
C. 전원을 고용하는 용병단 운영 배치와 손익 계산이 직관적이다. 자유 모험가와 간접 육성이라는 정체성이 바뀐다. 이번 범위에서 제외한다.

B안은 작성자의 추천이며 아직 사용자 확정안이 아니다.

3. 모험가 구조 — 소속, 관계, 생활 상태를 분리

3.1 하나의 승급 줄로 만들지 않는다

자유 모험가 → 정식 모험가 → 토박이 → 핵심 모험가처럼 한 줄의 등급으로 만들지 않는다. 각 단어가 서로 다른 사실을 나타내기 때문이다.

축 값 예시 결정하는 것 결정하지 않는 것
소속·계약 자유 / 정식 계약 정기 보수, 임무 우선권, 지원, 계약 기간 전투 등급·애착·주거
관계 애착 0~100, 방랑자·새내기·동반자·토박이 정서적 신뢰, 자유 모험가의 요청 수락, 갱신 의향 자동 고용·자동 급여
생활·체류 방문 / 길드 숙소 이용 / 마을 거주 이동·체류, 주거 표현 계약 의무
현재 활동 길드 대기 / 의뢰 중 / 부상 / 외부 체류 / 배치 예약 지금 새 일을 받을 수 있는가 영구적인 소속
성장 모험가 등급 F~S, 직업, 레벨 수행 능력과 성장 경로 길드 직원 여부
이력·표식 창립 멤버, 마왕 토벌 후보, 단짝 파티 이야기·관찰·선택 편의 별도의 급여 등급

예를 들어 “E급 성직자 / 자유 / 토박이 / 마을 거주”, “F급 궁수 / 정식 / 새내기 / 길드 숙소”가 모두 가능해야 한다. “핵심 모험가”는 주목할 인재 표식이지 제3의 고용 제도가 아니다.

3.2 애착·거주 불일치 처리

기존 설계의 애착 구간은 0~29 / 30~69 / 70~99 / 100, 실제 지명 수락 구간은 0~29 / 30~59 / 60~89 / 90 이상이다. 설계상 마을 거주는 애착 100, 이사는 60 미만이고, 인구 계산은 애착 65 이상을 정착 기여자로 센다. v2가 이 차이를 미결로 남겼다. [S02, S03, S06]

추천 처리 순서는 다음과 같다.

  1. 계약 기능을 추가할 때 기존 애착·인구 수치를 함께 바꾸지 않는다. 내부 구분을 명확하게 하고, 화면에는 애착 숫자·소속·거주 여부를 따로 표시한다.
  2. 수락 계산은 현재 코드 구간을 공통 함수로 사용한다. “토박이”는 관계 판정과 주거 판정을 혼용하지 않도록 별도 검토한다.
  3. 애착 65 이상 인구 기여는 첫 버전에서 유지하되, 설명을 ‘지역 활동 기여’로 명확히 한다. 이것을 실제 주택 입주 여부로 오해하게 하지 않는다.
  4. 실제 거주 100/60 규칙과 관계 단계 이름을 통일하는 작업은 별도 승인·회귀 검증 대상으로 둔다. 계약 체결만으로 인구 증가 인원을 추가하지 않는다.

새로운 ‘충성도’와 ‘계약 만족도’ 막대를 처음부터 더 만들지 않는다. 애착은 장기 관계에 사용하고, 급여 미지급·지원 부족·업무 초과처럼 설명 가능한 불만 사유를 계약 상태에 남긴다.

3.3 창립 멤버

기존 창립 2명은 ‘상주하는 자유 모험가’로 시작하는 것을 추천한다. 이름·능력치·기존 상주 혜택·이력은 유지하고, E급 이후 다른 모험가와 마찬가지로 정식 계약을 제안할 수 있게 한다.

창립 멤버라는 이유로 무료 전속 의무를 주지 않는다. 정식으로 계약한 뒤에는 동일한 급여·지원·정식 정원을 적용한다. 창립 표식은 남되 정원은 두 번 세지 않는다.

4.2 정식 계약의 권한 한계

정식 계약은 전투 직접 조작권이나 무조건 복종권이 아니다. 계약이 보장하는 것은 합의한 종류·위험·시간 범위에서 우선적으로 일을 맡기는 권리다.

부상, 기존 원정, 충족하지 못한 임무 조건, 계약상 위험 상한 초과, 업무 시간 초과, 급여 체납 상태에는 배치할 수 없다. 범위 밖 임무는 별도 동의를 받으며 자유 모험가와 같은 거절 가능성을 남긴다. 기존 전투·후퇴·대열 규칙은 그대로 적용한다.

계약 범위 내 배치는 매번 애착 확률을 굴려 거절시키지 않는 안을 추천한다. 안정적인 인력 확보라는 대가가 분명해야 하기 때문이다. 애착과 성향은 영입·재계약·업무 선호·범위 밖 요청에 계속 작용한다.

4.3 배치 시간과 자율성

첫 시험에서는 계약원 1명당 4주 중 최대 2주를 길드 지정 업무에 예약하고 나머지를 일반 의뢰·회복·개인 활동에 남기는 값을 검토한다. [검증용 수치]

장기 의뢰는 실제 점유 주수만큼 계산하고, 같은 사람을 호위·소재 수집·방어 대기에 중복 예약하지 않는다. 방어 대기도 인력 점유다. 일정상 쉴 시간이 남는다고 피로도가 이미 구현된 것으로 취급하지 않으며, 피로 시스템을 넣기 전에는 예약 시간 제한과 기존 부상 규칙으로 과로를 제한한다.

침공 준비는 기존의 출발 제한을 우선 적용한다. 계약 임무를 수락하기 전에 예상 충돌을 안내하고, 이미 외부에 약속한 호위가 있다면 대체 인원·일정 변경·위약금 중 하나가 필요하다. 같은 모험가가 양쪽에 동시에 나타나서는 안 된다.

5.2 영입 대상과 제안

영입 후보는 기존 자유 모험가에서 고른다. 초안에서는 애착 30 이상 + 이 길드 의뢰 3회 이상 성공 + 계약 가능한 상태를 후보 노출 기준으로 시험한다. 능력이 뛰어나도 자유로운 생활을 선호하면 거절할 수 있다. [검증용 수치]

영입 화면은 현재 수익·역할·지원 욕구와 계약의 장단점을 보여 준다. 능력치 총합으로만 추천하지 않고, 부족한 역할(회복·전위·탐색), 지명 수락 안정성, 최근 활동량도 함께 보여 준다.

제안 방식: 최초 버전은 급여·길드 몫·지원 범위를 묶은 표준 계약 1종으로 시작한다. 자유 슬라이더를 여러 개 열어 수십 조합을 최적화하게 만들지 않는다. 영입 수락 여부는 제안 시 결정해 저장하고, 같은 조건으로 매주 다시 눌러 확률을 뚫는 방식을 막는다. 조건을 실질적으로 개선하거나 다음 재협상 시점에 다시 제안한다.

계약 상담은 기존 지명 섭외비와 다르다. 영입금이 있다면 계약 성립 때만 1회 지급하고, 지명 거절비를 계약 상담에 자동 적용하지 않는다.

5.4 급여·부상·계약 종료

정기 보수는 일한 주수에 비례해 적립한다. 월 중 영입·종료 때 월급 전체가 생기거나 사라지지 않게 한다. 월말에 지급할 때만 지갑을 늘리며, 적립금과 실제 지급을 둘 다 현금 지출로 세지 않는다.

부상 중에도 계약상 기본 보수를 지급한다. 길드가 책임지는 인재라는 의미와 재정 위험을 만들기 위해서다. 치료 지원은 계약 한도 내 실제 비용만 지급하며, 부상이 없는데 지원 예산을 매월 전액 차감하지 않는다.

첫 체납 때는 미지급액을 남기고 신규 지정 업무를 중지한다. 첫 시험에서는 경고 후 4주 유예를 두고 정산·합의 종료하며, 해지 버튼으로 밀린 보수를 지우지 않는다. 사망하면 그 주까지 발생한 보수와 약정 위로금을 유족에게 정산하고, 이후 급여는 발생하지 않는다. 보험·공제 적립 시스템은 이번 범위에 넣지 않는다.

종료 예정일을 넘는 임무는 갱신·연장 동의 없이 새로 배치하지 않는다. 예기치 않은 귀환 지연에는 출발 때 확정한 보상 조건과 추가 근무분을 유지한다. 개인 장비·선물·유품은 모험가 측 소유이며, 명시적인 길드 대여품만 회수 대상이다.

5.5 창립 멤버·고정 파티·계승

창립 멤버에게도 별도 계약 동의가 필요하다. 친한 파티원과 함께 계약하기를 원하는 성향은 후속 협상 조건으로 확장하되, 첫 버전에서는 파티를 자동 분해하거나 다른 파티원까지 강제 계약하지 않는다.

사망 후 계승되는 장비·스킬과 새로 등장하는 2세의 계약은 분리한다. 부모의 고용 의무·개인 채무·길드 대여 계약을 자녀에게 자동 상속하지 않는다. 부모에게 길드가 지급하지 못한 보수는 별도의 유족 정산 대상이다. 유품과 가문 관계는 기존 기획을 유지하고, 2세는 새 인재로 계약을 제안한다.

6.2 외부 일반 의뢰

주민·상인이 보상금을 부담하고, 길드는 의뢰를 연결해 중계료를 받는다. 모험가가 직접 수주하거나 리퀘스트에서 지명할 수 있다. 취소·기한·능력치·대열 등은 기존 규칙을 재사용한다.

금전 보상이 없는 리퀘스트는 수수료도 0이다. 지원 필요 시 길드가 별도 예산을 지출한다. 기존의 인구·시설 해금·명성 보상은 해당 보상으로만 기록하고, 금화 매출로 환산해 금고에 넣지 않는다.

6.3 길드 발주 의뢰

길드가 원하는 소재·아이템을 확보하기 위해 자기 돈으로 보상을 건다. 첨부 메모와 기존 v2의 ‘길드 발주 의뢰’를 구체화한 것이다. [S07, S14]

게시 용량 기존 18칸 안에서 사용, 동시 2건을 시험값으로 시작. 외부 의뢰를 모두 밀어내지 못하게 제한

보유 재료를 즉시 납품하는 거래와 실제 원정을 떠나는 수집 의뢰를 구분한다. 즉시 납품에는 원정 경험치·전투 실적을 주지 않는다. 지정 납품에 쓴 물건을 같은 소유자 명의로 다시 위탁 판매할 수 없다.

6.4 정기 호위·왕국 계약

상단·도시와 길드가 계약을 맺고, 길드가 약속한 인력·실적을 제공하는 사업이다. 정식 계약원은 예정된 업무를 안정적으로 수행하는 기반이 된다. 부족한 자리는 자유 모험가를 개별 섭외할 수 있지만, 수락하지 않은 사람을 확보 인원으로 세지 않는다.

계약 전에 기간, 매주 필요한 인원·능력, 지급 구조, 완료 인정, 중도 취소·실패 책임, 방어 일정 충돌을 보여 준다. ‘계약금’이라는 말 하나에 관리비·선수금·모험가 보수를 섞지 않고, 8.4절의 정산을 따른다.

6.5 자체 던전 탐사

외부 의뢰인이 보상을 주는 일이 아니라 길드가 비용을 투자하고 전리품 수익을 나누는 사업이다. 길드 투자금, 투자금 회수 순서, 참가자 보수, 잔여 전리품 지분을 출발 전에 합의한다. 참가자 의뢰 수수료를 공제한 뒤 동일 전리품에 투자 지분까지 무조건 중복 공제하지 않는다.

이 기능은 정식 계약·전리품 소유권·실제 거래가 안정된 후 추가한다. 던전 입장료·탐사권·채굴권은 권리 소유자, 유지 책임, 수요·고갈·안전 관리가 정의되기 전에는 단순 자동 수익 버튼으로 넣지 않는다.

7. 중계료 정책과 모험가의 선택

7.1 정책은 요율과 서비스의 교환이다

첨부 메모의 ‘유저가 중개 요율을 정하고 애착에 영향을 준다’는 방향을 채택하되, 수수료를 높이면 의뢰가 자동으로 계속 들어오는 구조는 피한다. [S14]

구간 추천 범위 의도
F 기존 10% 유지 현재 초반 경제와 튜토리얼 보존
E 이후 최초 실험 10 / 15 / 20% 정책 3단계 낮은 요율·균형·지원형 운영 비교
이후 확장 25~30%는 고급 서비스·계약형에 한해 별도 검증 메모의 10~30% 상한을 즉시 전 등급에 적용하지 않음

이 표는 신규 제안이다. 기존에 승인된 ‘기본 10% + 정보실 효과’와 별개의 변경이며, 수수료 인상을 보조금 대체 수단으로 삼지 않기로 한 기존 결정도 재검토가 필요하다. [S07]

수수료 정책 변경은 새로 게시하는 의뢰부터 적용한다. 이미 게시·수락한 의뢰의 약속을 소급해서 바꾸지 않는다. 정책을 바꾼 뒤 귀환 직전 요율을 올리는 방법으로 추가 수입을 얻을 수 없어야 한다. 첫 버전은 월 1회 변경을 권장한다.

7.2 높은 요율이 항상 최적이 되지 않게 한다

모험가의 선택에는 보상 총액이 아니라 자기 예상 순수입, 성공 전망, 소요 기간, 필요한 물약·식사 비용, 직업·성향 선호, 동료 및 지원의 가치를 사용한다.

예를 들어 동일한 100G 의뢰라도 수수료 20%, 충분한 정보·치료 지원인 길드와 수수료 10%, 지원이 없는 길드는 서로 다른 선택이 된다. 신중한 모험가는 안전·치료를 더 높게 평가하고, 돈을 중시하는 모험가는 실수령액을 더 높게 평가하도록 기존 성향 축을 활용한다.

애착 변화는 매주 모든 모험가에게 일률적으로 깎는 방식보다, 실제 이용한 의뢰의 조건과 약속 이행에 반응하게 한다. 높은 요율에 이미 동의하고 충분한 지원을 받은 사람에게 같은 불이익을 반복해서 주지 않는다. 정확한 가중치와 애착 변화량은 검증값으로 둔다.

7.3 정보실의 역할

요율 정책을 넣으면 기존 정보실 효과 1개당 +2%p를 그대로 더하지 않는다. 정보실은 위험 예측 정확도·의뢰 품질·계약 기회·고급 요율 제공 조건을 개선하는 방향으로 옮긴다.

위험을 숨긴 뒤 위험 정보까지 별도로 팔아야 살 수 있는 구조는 피한다. 기본적인 위험 고지와 필수 안전 정보는 의뢰 서비스에 포함하고, 지도·희귀 탐사 정보처럼 추가 가치가 있는 내용만 선택 서비스로 취급한다.

7.4 고위험 의뢰의 수수료

‘위험하니까 길드 수수료가 높다’만으로 끝내지 않는다. 모험가에게 지급되는 위험 보수도 충분해야 한다. 긴급 의뢰는 외부 의뢰인이 추가 관리비·긴급 보수를 부담하는 방식이 더 명확하다. 이 비용은 의뢰서에 별도로 적고, 정식 계약의 길드 몫·일반 수수료와 중복 부과하지 않는다.

8. 정산 규칙과 계산 예시

8.1 일반 외부 의뢰 — 개인 배분 기준액

의뢰 보상 총액을 R, 파티원 수를 n, 모험가 i의 수수료 차감 전 배분 기준액을 B_i라고 한다.

B_i = R을 파티원에게 균등 분배한 금액
자유 모험가 i의 길드 몫 = B_i × 일반 중계료율
정식 모험가 i의 길드 몫 = B_i × 계약상 길드 배분율
모험가 i의 실수령액 = B_i − 해당 길드 몫
길드 의뢰 수입 = 모든 참가자의 길드 몫 합계

정식 계약 배분율은 일반 중계료를 포함한 최종 비율로 정의한다. 일반 10%를 먼저 떼고 정식 30%를 또 떼지 않는다. 계약원 1명이 파티 전체 보상에 30%의 권리를 발생시키는 것도 아니다.

정수 G를 사용하므로 균등 배분 잔액은 고정된 참가자 ID 순서 등 재현 가능한 규칙으로 배분한다. 길드 몫은 개인 기준액에 정해진 반올림 규칙을 적용하고, 개인 실수령액은 차액으로 계산한다. 길드 몫 + 모든 개인 몫 = 원래 보상 총액이 항상 같아야 한다.

8.2 혼성 파티 예시

총 보상 1,000G, 자유 2명·정식 2명, 일반 중계료 10%, 정식 계약 길드 몫 30%라고 가정한다. 모두 계산 설명용이다.

참가자 개인 배분 기준액 길드 몫 개인 실수령액
자유 A 250G 25G 225G
자유 B 250G 25G 225G
정식 C 250G 75G 175G
정식 D 250G 75G 175G
합계 1,000G 200G 800G

정식 C·D의 정기 보수와 지원비는 별도 길드 지출이다. 이 의뢰에서 200G가 들어왔다고 200G 전체를 순이익으로 표시하지 않는다.

모험가 보상 분배는 출발 때 확정한 계약·요율 스냅샷을 사용한다. 수행 중 계약 종료나 정책 변경이 있어도 보상을 귀환 시점의 새로운 조건으로 갈아 끼우지 않는다.

8.3 정식 편입의 손익분기

정식 계약의 경제성을 비교할 때 보상 총액 전체가 아니라 그 사람의 월간 개인 배분 기준액 합계 S를 사용한다.

자유 상태의 길드 기여 = f × S
정식 상태의 길드 기여 = r × S − 정기 보수 − 실제 지원비
전환으로 늘어난 직접 기여 = (r − f) × S − 정기 보수 − 실제 지원비

일반 10%, 정식 30%, 월 보수 40G, 실제 지원비 20G를 가정하면 다음과 같다. 영입금·섭외비 절감·추가 의뢰·보조금·전리품 효과는 제외한 단순 비교다.

월간 개인 배분 기준액 S 자유 상태 길드 기여 정식 상태 길드 기여 전환 차이
0G 0G −60G −60G
100G 10G −30G −40G
300G 30G 30G 0G
600G 60G 120G +60G

이 가정에서는 직접 수익만으로 비교한 손익분기점이 S = 60 ÷ 0.2 = 300G다. 실제 지원비가 0인 달에는 20G를 지출로 잡지 않는다. 위 0G 사례는 부상·대기 중 생활·치료 지원 20G가 실제 발생한 경우다.

현재 F급 보상 100G 의뢰를 4명이 나누면 개인 기준액은 25G다. 네 번 성공해도 그 사람의 S는 100G이지 400G가 아니다. 앞선 단순 고용 예시처럼 파티 전체 보상에 한 사람의 배분율을 적용하면 정식 영입의 수익성을 과대평가한다.

보다 완전한 비교에는 다음을 추가한다.

추가 가치 = 기존 지명 섭외비 절감
          + 계약원 확보로 새로 수행한 외부 사업의 추가 공헌
          + 가용성·지원으로 줄인 실제 손실
추가 비용 = 영입금 + 계약 때문에 늘어난 운영비 + 추가 장비·치료 비용

예컨대 기존 F급 섭외비가 20G라면 계약 범위 내 지명 두 번은 최대 40G의 길드 지출 절감이 될 수 있다. 이는 보조금처럼 새 돈이 지급되는 것이 아니다. 반대로 그 사람이 이미 거의 섭외되지 않던 모험가라면 절감 효과도 작다. 실제 이용 건수로만 계산한다. [S11, S13]

8.3-1 모험가 쪽에서도 계약할 이유가 있어야 한다

같은 예시를 모험가 입장에서 보면, 월 개인 배분 기준액이 300G일 때 자유 상태 현금 수입은 270G이고, 정식 상태는 의뢰 210G + 기본 보수 40G = 250G다. 여기에 실제로 필요한 지원 20G를 받으면 경제적 편익이 비슷해질 수 있지만, 지원은 개인 지갑에 들어오는 현금이 아니다.

반면 S가 600G인 숙련자는 자유 상태 540G와 정식 상태 현금 460G를 비교한다. 지원 20G가 본인에게 그만큼 가치가 있어도 총 편익은 480G여서 자유 활동보다 적다. 이런 인재는 더 좋은 보수·지원·업무 조건을 요구하거나 계약을 거절하는 것이 자연스럽다.

따라서 길드에 이익인 계약이 모험가에게도 항상 매력적이라고 가정하지 않는다. 영입·갱신은 최근 개인 순수입, 실제로 필요한 지원, 안정적인 보수의 가치와 계약상 제약을 함께 비교한다. 유망주를 좋은 조건에 육성한 뒤에는 성장에 맞는 재계약 요구가 생긴다. 이를 막기 위해 성장 전의 싼 계약을 영구 유지시키지 않는다.

8.4 상단 장기 계약 — 관리비와 수행 보수를 분리

예시: 상단이 한 달 계약금 300G를 맡긴다. 이 중 60G는 ‘합의한 인력 확보·관리’ 대가이고, 240G는 호위 4회 × 회당 60G의 수행 보수다. 이것은 실제 밸런스 제안이 아니라 정산 형식 설명이다.

선수금 300G를 즉시 길드 이익으로 넣지 않고 예치금으로 보관한다. 길드가 확보 의무는 지켰으나 호위는 3회만 성공했으며, 1회 실패 시 관리비에서 15G를 배상한다고 가정한다.

처리 금액
완료 3회 수행자 지급 180G
미완료 1회분 환급 60G
관리비에서 차감하는 배상 15G
길드 관리 대가 순수입 45G
합계 300G

길드 순수입 45G에서도 정기 보수·실제 지원·기타 직접비는 별도 차감한다. 수행 보수 180G에는 이 계약의 관리비가 이미 분리돼 있으므로 일반 중계료나 정식 30%를 다시 떼지 않는다. 계약별 정산 방식 중 하나만 적용한다.

성과 보너스는 계약 체결 때 ‘수행자 풀 / 길드 성과 보수’로 분리한다. 원래 인력 확보 의무를 지키지 못했다면 관리비 60G도 전액 인정되지 않게 조건을 명시한다. 장기 계약은 수익뿐 아니라 예약한 전력을 다른 곳에 쓸 수 없는 기회비용을 갖는다.

8.5 길드 발주 정산

소재 확보 보상 200G를 걸었다면 게시 때 200G를 예약하고, 납품 성공 시 길드 현금 −200G·수행자 지갑 합계 +200G로 처리한다. 길드 창고에는 지정 물품이 들어온다. 길드 수수료 +20G, 보조금 +160G를 추가하지 않는다.

정식 계약원을 활용하는 경우에는 급여에 포함된 지정 업무 + 필요한 실비인지 별도 보수 200G가 있는 업무인지 발주 때 선택한 표준 계약으로 표시한다. 같은 임무에 자동으로 두 가지 보수를 겹쳐 지급하지 않는다. 다만 명시한 정기 기본 보수는 정상적으로 유지한다.

8.6 지명 섭외비 정리

기존 자유 모험가의 섭외비(거절해도 지출)는 우선 유지한다. 현재 확인 코드에는 수취인의 지갑 입금이 없으므로 다음 중 의미를 정해야 한다. [S13]

초기 추천은 ‘섭외 운영비’로 명시하는 것이다. 연락·준비·행정 비용이며, 현재 동작과 가장 가깝다. 정식 계약 범위 내 요청은 이 비용이 정기 운영에 포함되어 별도 지출하지 않는다.

이를 ‘모험가에게 지급하는 응답·대기료’로 바꾼다면 개인 지갑 입금을 추가하고, 거절할수록 개인 돈이 늘어나는 효과를 별도 검증해야 한다. 이 변경을 단순 문구 수정으로 취급하지 않는다.

9. 전리품·매입·위탁·제작

9.1 소유권부터 정한다

자유 모험가가 가져온 물건을 길드가 무료로 자기 창고에 넣은 뒤 전부 판매하면, ‘자유 모험가를 지원하는 중개 조직’과 ‘소재 매입 비용’이 충돌한다. 새 소재 거래는 물리적 보관 장소와 경제적 소유자를 분리해야 한다.

정식 계약원이 되었다고 모든 개인 전리품이 길드 소유가 되지는 않는다. 정식 계약의 금전 배분과 소재 지분은 다른 권리다. 첫 버전은 일반 전리품을 개인 소유로 유지하고, 길드 발주·투자 탐사에서만 별도 권리를 정하는 편이 명확하다.

9.2 두 가지 거래

즉시 매입: 길드가 모험가에게 매입 대금을 지급하고 물건의 소유권을 얻는다. 이후 더 높은 가격에 팔면 차익을 얻지만 팔리지 않거나 가격이 내려가면 손실을 부담한다.

위탁 판매: 길드는 물건을 보관하고 판매를 대행한다. 판매 대금에서 수수료만 얻으며, 나머지를 소유자에게 준다. 판매되기 전에 위탁품을 요리·제작·선물·납품에 쓸 수 없다.

예시 모험가에게 지급 길드 현금 흐름 길드 거래 이익
70G에 매입 → 100G에 판매 매입 때 70G 매입 −70G, 판매 +100G 30G(부대비용 전)
100G에 위탁 판매, 수수료 10% 판매 때 90G 위탁 예치금에서 수수료 10G만 귀속 10G(부대비용 전)

한 물건이 동시에 매입 재고와 위탁품이 되어서는 안 된다. 매입 판매액 100G와 차익 30G를 둘 다 수입 합계에 더하지 않는다. 파티 공동 전리품은 보관 묶음에 지분을 기록하고, 판매 때 대금을 배분하면 소재 1개를 억지로 여러 조각으로 나누지 않아도 된다.

9.3 처음부터 시세 시뮬레이터를 크게 만들지 않는다

최초 버전은 기존 등급별 판매가(F 6G, E 9G 등)를 기준 가격으로 사용하고, 매입가·위탁 수수료·판매 가능한 수량만 검증한다. 복잡한 가격 변동은 후순위다. [S07]

현금이 부족하면 매입 대신 위탁을 권할 수 있어야 한다. 매입 예산 상한, 보관 한도, 최소 예비금을 둔다. 길드에 팔지 않아도 모험가가 외부 상인에게 판매하는 기본 경로를 두어, 길드의 자금 부족 때문에 모험가 경제까지 멈추지 않게 한다.

실제 판매 방식이 적용되는 시점에 자동 차익 resaleRate = 0.08을 해당 거래에서 끈다. 먼저 자동 수입을 제거하고 대체 수입은 미구현인 상태로 배포하지 않는다.

9.4 소재를 ‘팔까, 쓸까’

길드 소유 소재는 즉시 판매, 요리 발견, 길드 시설 개방, 대장간 납품, 정식 모험가 장비 지원, 이야기 리퀘스트 제출에 사용할 수 있다. 같은 재료가 여러 용도를 가지는 것이 핵심이다.

대장간·물약 상점의 완제품 매출은 기존대로 해당 상점의 수입이다. 길드는 소재 납품 대금 또는 별도로 맺은 위탁·서비스 계약의 수수료만 번다. ‘길드가 해금시켜 준 가게이므로 모든 매출이 길드 돈’이라는 규칙으로 바꾸지 않는다. [S04, S07]

9.5 제작·가공의 범위

초기에는 기존 대장간과 공급 계약·주문 제작을 연결한다. 길드가 자체 제작소까지 동시에 운영하게 하지 않는다. B급 해체장 등의 기존 시설에 가공 수수료·고급 재료 생산을 붙이는 것은 후속 확장으로 둔다. 신규 목욕탕·경매장·던전 입장 사업도 기존 15종 시설에 필요한 역할이 없는지 먼저 검토한다.

10. 시설 수익과 모험가 구매력

10.1 주점·식당의 실제 거래

현재 식사는 개인 지갑에서 가격을 차감하고 길드에 마진을 넣으며, 술은 확인한 처리에서 개인 지갑 차감 없이 마진이 발생한다. 업그레이드는 음식·술 마진에 5G를 더한다. [S10, S11]

개선 후에는 판매 가격 − 직접 원가 = 거래 기여가 맞도록 정리한다. 예를 들어 식사 25G, 외부 조달 원가 10G라면 모험가 −25G, 길드 매출 +25G·원가 −10G·기여 +15G다. 기존의 가격 25%·마진 60%와 같은 결과를 내는 설명용 예시다.

술도 구매 가능 잔액을 확인하고 실제 지갑에서 결제한다. 가격은 아직 별도로 정해야 하며, 기존 ‘마진 2G’를 판매가 2G로 오해하지 않는다. 예시로 가격 5G·원가 3G이면 마진 2G다.

업그레이드 후 가격이 그대로인데 이익만 가격을 초과해 늘어나는 일이 없어야 한다. 품질 개선에 따른 판매가·수요 변화 또는 원가 절감으로 설명하고, 원가 절감은 최소 원가 아래로 내려가지 않게 한다. 해당 변경은 기존 +5G 효과와 수입 곡선이 달라질 수 있으므로 회귀 실험 대상이다.

10.2 정식 모험가 지원과 내부 거래

길드가 정식 모험가에게 자기 식당 식사를 제공한 경우, 길드 돈을 자기 식당 매출로 돌려 새 순이익을 만들지 않는다. 외부 식재료 원가와 실제 개인 부담분만 순현금에 영향을 준다.

외부 물약 상점에서 20G짜리 물약을 50% 지원한다면 길드 −10G, 개인 −10G, 상점 +20G다. 길드가 무료로 물약을 만들어 주거나, 개인 지갑에서 전액을 뺀 뒤 지원비를 또 상점에 지급하지 않는다.

지원 예산은 사용 상한이고 실제 비용이 아니다. 미사용 예산은 비용 처리하지 않는다. 계약원은 ‘지원비 환급’을 반복 청구해 현금을 만들 수 없으며, 구매 영수증·품목·수량과 연결된 지원만 처리한다.

10.3 요리 발견과 판매 재료는 구분

기존 요리의 중심은 소재 조합으로 레시피를 발견하는 것이다. 이를 갑자기 매 끼니 재료를 수동 수급하는 식당 경영으로 바꾸지 않는다. [S04]

첫 버전은 발견 시 기존 소재 소모를 유지하고, 판매 시 소요 원가는 자동 조달 비용으로 표현한다. 실제 식재료 재고를 매 끼니 차감하는 구조는 선택적 확장이다. 위탁품은 어느 쪽에서도 자동 재료로 사용할 수 없다.

10.4 훈련·치료·숙박

훈련장·의무실·숙박 등은 실제로 제공하는 편익과 비용이 정의될 때 선택 서비스로 확장한다. 무료 자연 회복·기본 휴식 경로는 남겨 둔다. 돈이 없는 신입이 회복도 못 하고 의뢰도 못 하는 상태로 고착되지 않아야 한다.

치료비를 냈다고 현재 전투의 부상 규칙을 무시하고 즉시 완전 회복시키는 안은 채택하지 않는다. 기존 치료 시설의 회복 단축 범위에서 서비스를 설계한다. 길드가 아직 운영하지 않는 시설의 수익·비용은 먼저 장부에 추가하지 않는다.

이번 개선에서는 반기 실적형을 기존 확정안으로 존중하되, 신규 계약 경제가 들어갔을 때의 적정 비율로 검증됐다고 보지 않는다. 실적형이어도 수입에서 차지하는 비중이 크게 남을 수 있다.

시험 결과 초기 자금이 부족하면 1회 창립 지원금, 첫 반기 분할 지급, 필수 시설 비용 조정 중 하나를 별도 변경안으로 판단한다. 이 문서가 시작 금고를 임의로 다시 3,000G로 올리거나 추가 보조금을 승인한 것은 아니다.

11.4 사용 가능 자금과 예약 예산

길드 소유 현금, 그중 지급 예약액, 외부 예치금을 분리한다.

사용 가능 금액 = 길드 소유 현금 − 길드 소유 자금의 지급 예약액

외부 의뢰 보수·위탁 판매자의 돈·선수금 중 미이행분은 길드 소유 현금에 포함하지 않는다. 계약 체결 화면은 신규 계약금, 앞으로 8주 보수, 지원 예산을 지출 전망으로 보여 주고, 예약 가능한 현금이 충분할 때 계약하게 한다. 8주는 검증용 안전 기간이다.

길드 발주 200G를 예약했다면 게시 때 현금을 실제로 빼고 예약액을 다시 빼는 이중 차감을 하지 않는다. 게시 시 예약만, 지급 시 현금과 예약액을 함께 감소시키는 한 방식으로 통일한다. 예약 예산을 풀어 쓰는 조작이 있더라도 이미 수주한 의뢰 보수나 확정된 급여까지 해제할 수는 없다.

12. 화면과 장부

12.1 기존 업무 일지에 통합

매입 재고는 매입 때 현금 지출, 판매 때 해당 원가를 뺀 실현 손익으로 구분한다. 같은 원가를 두 번 비용 처리하지 않는다. 위탁금은 거래 취급액으로만 보이고 길드 수입에는 수수료만 넣는다. 원가 기록이 없는 기존 저장의 재고는 원가를 임의로 만들어 정밀 이익을 표시하지 말고, ‘기존 재고·원가 미상’으로 구분한다.

숫자를 많이 보여 주기보다 행동 가능한 문장을 우선한다.

  • “정식 모험가가 모두 외부 호위 중입니다. 방어 대기 인원을 남겨 주세요.”
  • “요율 변경은 새 의뢰부터 적용됩니다. 진행 중 보상은 바뀌지 않습니다.”

경고를 무시했다고 숨겨진 확률로 갑자기 전원이 이탈하게 만들지 않는다. 체납·업무 초과·권리 침해가 어떤 불만을 만들었는지 보고에서 설명한다.

13.2 주간·월간 처리의 일관성

주가 넘어갈 때 처리 순서에 관한 제안은 다음과 같다.

  1. 귀환·결과 확정, 기존 거래 중복 여부 확인.
  2. 확정된 의뢰 보수·전리품·지원비를 정산하고 사용한 예약 해제.
  3. 계약 종료·연장·부상·사망과 기존 업무 예약 정리.
  4. 월말이면 해당 기간 보수·사업 계약·보조금 적격 실적 결산.
  5. 침공·이미 수락한 계약 임무·지명 임무의 출발 가능 상태 확인.
  6. 남은 가용 인원이 게시판에서 자율적으로 의뢰를 선택.
  7. 새로운 기록·보고·화면 연출에 필요한 결과 저장.

실제 기존 stepWeek의 호출 순서를 무작정 이 목록으로 교체하지 않는다. 특히 ‘이번 주 귀환자 지명 가능’과 침공 차례 간 회복 같은 기존 예외를 보존하며, 예약 판정과 정산의 선후관계를 명시하는 것이 목적이다.

13.4 저장 호환

기존 저장을 불러오면 모든 기존 인물은 원칙적으로 자유 모험가로 유지한다. 과거 월급·미납금·계약금을 새로 만들지 않는다. 기존 home 상주 동작은 보존하고, 이것만 보고 정식 계약원이나 창립 멤버라고 추정하지 않는다. 창립 여부가 확실한 기록이 없는 저장은 기존 상주 혜택으로 유지한 뒤 표시를 보수적으로 처리한다.

진행 중 의뢰는 기존 정산 규칙으로 끝낸다. 신규 규칙은 전환 이후 게시·출발한 의뢰부터 적용하는 방식을 권장한다. 기존 s.mats는 기존 길드 재고로 한 번만 이관하고, 새 소유권 체계로 이관한 뒤 다시 불러와도 같은 재고를 추가하지 않는다.

기존 원가 미상 재고, 미수령 보수, 외부 체류 인물, 사망·이탈 이력을 명확하게 구분한다. 현재 확인 코드에는 이탈 때 alive = false를 쓰는 처리도 있으므로, 계약 해지·외부 이적을 추가하며 이를 실제 사망과 혼동하지 않도록 별도 상태나 원인 필드가 필요하다. [S10]

14. 개발 범위와 적용 순서

14.1 최소 검증 범위

첫 번째 playable 목표는 “E급에서 자유 모험가를 최대 2명 정식 계약하고, 같은 게시판·리퀘스트를 다른 비용 구조로 운영해 볼 수 있는 상태”다.

이 목표에 필요한 것은 소속 구분, 표준 계약 1종, 급여·실비 지원, 기존 지명 연결, 혼성 파티 보상 정산, 계약 종료, 장부다. 던전 권리·경매장·추가 직원·여관·시세 경제가 먼저 완성될 필요는 없다.

반기 보조금 개편은 기존 확정 작업이지만 이 단계들에 숨겨 묶지 않는다. 독립 설정으로 검증하고, P1·P2와 결합한 결과를 따로 기록한다.

14.3 첫 버전에서 제외

전원 의무 고용, F급 고정 급여 강제, 기존 접수원 급여 신설, 전 시설 유지비 부활, 광고·홍보 운영, 보험·공제 적립, 완전한 시장 가격 시뮬레이션, 던전·광산 경영, 정식 전용 전투 조작, 계약원 전용 마왕 토벌 자격은 넣지 않는다.

후반 콘텐츠를 제외한다는 뜻이 아니라, 경제·관계의 기본 연결을 확인하기 전에 개발 범위를 늘리지 않는다는 뜻이다.

15.3 시뮬레이션 비교

동일한 기준 커밋과 초기 설정을 기록하고, 기존 관문 1 방식의 첫 48주 비교를 유지한다. 정식 계약은 E급 이후 시작하므로 동일한 E급 진입 상태에서 추가 96주를 비교하는 별도 실험도 필요하다. 장기 검증에는 144주 이상을 사용하되 후반 미구현 기능의 효과를 임의로 넣지 않는다.

정책 확인하려는 점
A. 자유 중심, 정식 0명 추가 기능을 쓰지 않아도 기존 길드가 운영되는가
B. 핵심 역할 1~2명 계약 가용성·지명 비용·성장 지원의 이점이 있는가
C. 가능한 정원까지 계약 급여·지원·유휴 비용 때문에 무조건 최적은 아닌가
D. 높은 수수료, 낮은 지원 개인 구매력·수주·관계에 실제 대가가 있는가
E. 낮은 수수료, 높은 지원 육성에는 유리하더라도 재정 제한이 존재하는가
F. 소재 매입 편중 / 위탁 편중 현금·재고 위험과 안정 수수료가 다르게 작동하는가

기준은 100개 시드 비교를 권장한다. 예전 결과를 새 기능의 결과로 재사용하지 않는다. 난수 소비 순서가 바뀌면 같은 시드라도 의뢰·전투가 달라질 수 있으므로, 가능하면 의뢰·전투·계약 난수 흐름을 분리하거나 충분한 표본과 분포를 함께 비교한다.

17. 기대하는 플레이 흐름

초기: 창립 모험가와 자유 모험가가 게시판을 이용한다. 길드는 중계·음식·소재 거래로 성장 기반을 만들고 리퀘스트·침공을 해결한다.

E급: 자주 찾아오는 성직자를 정식으로 영입할지 고민한다. 영입하면 매월 보수가 들지만 중요한 요청의 수행 가능성을 계획할 수 있다. 아직 다른 역할은 자유 모험가를 활용한다.

사업 확장: 상단이 호위 계약을 제안한다. 계약원 둘을 모두 배치하면 안정적인 관리비가 생기지만 방어 대기 인원이 사라진다. 한 명은 남기고 자유 모험가를 섭외하거나, 더 작은 계약을 선택한다.

투자 선택: 모험가가 희귀 소재를 가져온다. 지금 매입하면 현금이 줄어 다음 급여가 빠듯하다. 위탁 수수료만 받거나, 계약원 장비 제작을 위해 매입하거나, 납품 리퀘스트를 위해 보관한다.

장기 목표: 돈을 가장 많이 쌓는 길드가 아니라, 다양한 자유 모험가와 신뢰 관계를 유지하고 필요한 사람에게 책임 있게 투자한 길드에서 마왕 토벌 파티가 성장한다.

이 개선안의 중심은 수익원 개수가 아니라 “누구와 어떤 약속을 맺고, 무엇을 지원하며, 그 책임을 감당할 것인가”를 플레이어의 결정으로 만드는 것이다.
